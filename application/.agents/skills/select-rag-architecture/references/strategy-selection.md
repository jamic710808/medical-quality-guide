# 按任務選擇檢索架構

資料核查基線：2026-10-13。下列規則是篩選與驗證起點，不是性能排名。技術包、接口、許可或部署方式實際採用前，檢查已鎖定版本與當前官方說明；不把這裡列過視為已經安裝或驗證。

## 術語消歧與分層

- Naive RAG 通常指分塊、索引、檢索後生成的基礎範式；是候選基線，不表示無需證據和驗收。[範式綜述](https://arxiv.org/abs/2312.10997)
- 若用戶說 Nav RAG，結合上下文核對其指基礎 Naive、文檔導航還是某個項目。可先給並列解釋再繼續獨立工作，不能直接替用戶認定。檢索到的 NavRAG 同名論文面向具身導航指令生成。[NavRAG](https://arxiv.org/abs/2502.11142)
- Hybrid 必須展開組件。關鍵詞＋向量融合、圖＋原文、SQL＋文檔路由是不同組合。LightRAG 的 hybrid / mix 也有自己的模式含義。
- GraphRAG 是利用圖結構增強檢索的路線集合；Microsoft GraphRAG 的 Local / Global / DRIFT 是具體實現的模式，不代表所有圖檢索都須有社區摘要。
- 本體/語義層定義概念、關係、映射與約束；SQL、全文、向量或圖檢索可消費它。圖數據庫、畫出的節點邊和有據的業務語義不是同一件事。

把決定分成四項：**怎樣表示知識；怎樣檢索/計算；怎樣編排查詢；怎樣回鏈與驗收。** 不把框架名稱、模型品牌和存儲產品當成這四項的答案。

## 任務信號與主備路線

| 任務與可觀察信號 | 最小主選 | 增加能力的證據 | 必須防止的錯誤 |
| --- | --- | --- | --- |
| 明確 ID、條號或固定字段，少量資料可直接讀取 | 鍵查找、全文查詢或直接上下文 | 問法改寫導致漏檢時比較語義檢索 | 默認建向量庫/圖譜；先檢索再猜授權 |
| 單段事實問答，資料範圍明確 | 全文與基礎向量 RAG 中適用的基線 | 同義表述、專名、編號混合且單路漏檢時比較融合 | 認為“基礎”無須檢查引用/無答案 |
| 編號/縮寫與口語、近義詞共存 | 關鍵詞與向量融合；重排按需比較 | 召回已覆蓋但排序噪聲高；領域樣本支持增益 | 直接相加不同分數；默認重排必然更好 |
| 計數、分組、完整列表或嚴格時間篩選 | 受控 SQL/原生結構化查詢 | 還要解釋原因/條文時組合文檔查詢 | 用 top-k 樣本代表全量；計數口徑不明就運行 |
| 長手冊、章節層級、跨章節引用 | 父子塊或保留標題/層級的檢索 | 導航步驟確實找回普通分塊漏掉的證據時比較文檔樹 | 把 PDF 後綴當導航需求；摘要冒充原文 |
| 已知實體、可信關係，問題要求沿關係追溯 | 已有關係查詢或圖擴展＋原文 | 相應工作負載中圖擴展優於已有 JOIN/檢索 | 數據有外鍵就遷圖；把抽取邊當已確認事實 |
| 跨大量文檔的共同主題、集合級探索 | 集合摘要/層級查詢；可比較 GraphRAG Global | 明確全局問題且可承擔抽取、摘要及更新成本 | 用社區報告證明精確數量或單個對象事實 |
| 同名異義、指標/單位/身份/粒度不一致 | 最小業務語義映射，必要時本體 | 複用性和任務覆蓋支持增加概念/約束 | 從列名猜業務定義；沒有依據仍建完整領域本體 |
| 單問題需要多來源且下一步取決於中間結果 | 有限查詢分解/路由，按需 Agent 編排 | 固定流程無法滿足目標，逐步調用有可觀察收益 | 根據問題長短路由；無限檢索直到湊出答案 |
| 用戶要診斷圖像/波形本身 | 先明確專業任務、模型與驗證邊界 | 得到實際專業任務和證據要求後再擴展多模態 | 文字報告檢索被宣稱為影像/信號診斷 |

數據後綴隻影響讀取和定位。真正改變路線的常是：身份與關係可靠性、結構/粒度、上下文跨度、任務覆蓋、語言、時效、更新/刪除頻率、訪問域及預算。

區分“按業務說明可關聯的字段”和“數據庫實際聲明並已核對的主外鍵/唯一約束”。只有字段名、表粒度或關係描述時，可據此提出查詢路線，但不能宣稱約束已存在或完整性已驗證；實現前核對鍵、重複、缺失關聯及聚合口徑。

## 組合時的關鍵區別

### 融合與重排

RRF 可按名次融合不同結果集，避免假定原生分數同尺度；它仍有候選池等工程選擇，不能據此免除樣本驗證。記錄融合前後證據覆蓋、排序與代價。[混合檢索](https://www.elastic.co/docs/solutions/search/hybrid-search)、[RRF](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion)

分塊丟上下文時可比較父子塊、必要元數據或上下文補充，再決定是否重排/擴圖。來源、嵌入版本、分塊與查詢模型一起變更時，不把整體收益只歸因於某一個組件。[Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval)

### 圖、樹與本體

Microsoft GraphRAG Local 將相關實體及原文結合；Global 利用社區報告，DRIFT 引入更廣社區信息。全局歸納與精確列表/統計的證據要求不同，應分開路由。[官方查詢模式](https://microsoft.github.io/graphrag/query/overview/)

文檔目錄樹跟隨原文結構；RAPTOR 通過遞歸聚類和摘要形成抽象層次。二者均需返回真實來源，導航結果不能自動證明摘要中的每個主張。[RAPTOR](https://arxiv.org/abs/2401.18059)、[PageIndex](https://github.com/VectifyAI/PageIndex)

OWL 2 提供形式化知識表示；SHACL 用於 RDF 圖條件驗證。OWL 的開放世界語義不能直接用來判斷必填內容缺失，也不等同於臨床真值。需要的可能只是版本化術語/映射，不必默認引入完整形式邏輯系統。[OWL 概覽](https://www.w3.org/TR/owl2-overview/)、[OWL 與數據庫](https://www.w3.org/TR/owl2-primer/)、[SHACL](https://www.w3.org/TR/shacl/)

### 單路、組合與用戶指定技術

選型以任務為單位，不強制整項目用同一路線。組合要有明確分支條件、允許工具、無答案出口和共同證據響應。確定性規則本身不是檢索任務；能直接計算/判定的條件不要交給相似度冒充。

若用戶明確選擇 GraphRAG 等技術，解釋它對哪些任務有效，在該約束內實現合理方案；除非目標與條件衝突，不擅自改成另一技術。原系統已滿足任務時只修有證據的缺口，不能用新 Skill 重建全部知識系統。

## 工具與工程候選

只查實際候選，不為列全技術棧安裝所有框架。以下能力來自官方資料，適用性與費用仍需項目驗證。

| 候選 | 可複用能力 | 選擇前核對 |
| --- | --- | --- |
| [Microsoft GraphRAG](https://microsoft.github.io/graphrag/) | 圖抽取、社區與多種查詢模式 | 任務類型、抽取錯誤、更新/權限與資源成本 |
| [Neo4j GraphRAG](https://neo4j.com/docs/neo4j-graphrag-python/current/user_guide_rag.html) | 向量/全文、圖擴展、Text2Cypher | 可信圖模式、實際查詢權限與只讀邊界；不必遷移已有效的關係查詢 |
| [LightRAG](https://github.com/HKUDS/LightRAG) | 圖與文本聯合查詢 | hybrid 為 local＋global，mix 還結合 naive；與 BM25＋向量不是同一配置，核對目標版本 |
| [PageIndex](https://github.com/VectifyAI/PageIndex) | 文檔樹與推理導航 | 本地/雲端解析能力和定位精度不同；本地索引不代表使用本地 LLM |
| [LlamaIndex](https://developers.llamaindex.ai/python/framework/understanding/rag/querying/) | 檢索、後處理與回答組件 | 複用項目已有框架；工具箱不代替選型依據 |
| [Haystack](https://docs.haystack.deepset.ai/docs/conditionalrouter) | 可組合管線與條件路由 | 條件、輸入輸出及兜底明確；路由器本身不是業務判斷器 |

框架選擇晚於能力選擇。需要更詳細的新實現資料時從官方文檔/源碼補查，記錄實際版本；不復述某個榜單準確率作為用戶項目結論。

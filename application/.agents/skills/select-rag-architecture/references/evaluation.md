# 驗證檢索方案與 Skill 決策

## 一次必要的方案比較

1. 從用戶真實目標確定代表問題與正確結果的判據。已有問題和驗收優先；補題標明需求派生/合成，不偽造客戶反饋。
2. 檢查來源角色與使用範圍；建設/調試數據、獨立驗證和留出分開。正式答案或隱藏評測反饋不能進入候選構造。
3. 選擇合適的簡單基線及一個有實質差別的候選，寫明要改善的失敗機制及可推翻條件。無實質差別不湊候選。
4. 凍結輸入/快照、問題、允許域與預算；固定可比的模型/設置，架構必須不同的分塊、圖、索引配置單列。記錄構建與查詢代價。
5. 執行用戶要求的最窄檢查，報告真實結果。資料不足時只交條件性建議及驗證設計，不能補造評分。
6. 先檢查不可接受錯誤，再比較任務質量和代價；更新路線或保持基線。達到範圍內要求就停止，輸入未變的有效證據直接複用。

普通調試題的成功不等於獨立驗證。沒有現成拆分時按實際任務組織評測，不硬套某個比例、題數或準確率；已有項目合同優先。面向專業責任的系統需對應負責人判斷，不能用自動評分替代。

## 分層檢查，防止平均分掩蓋失敗

| 層 | 檢查結果 | 有效證據與邊界 |
| --- | --- | --- |
| 路由 | 是否選擇正確來源、範圍和操作 | 真實分支/工具軌跡，含未知意圖和拒絕；不只看答案語言流暢 |
| 檢索 | 需要的證據是否找回、噪聲是否受控 | 有參照證據 ID 時測覆蓋與排序；沒有完整參照不宣稱全量 Recall |
| SQL / 關係 | 統計口徑、行集合、身份與關係是否正確 | 獨立預期結果、字段粒度與有據邊/路徑；不是 SQL 能運行或路徑存在即可 |
| 回答 | 目標問題是否回答，主張是否被支持 | 對原文逐項核查；faithfulness 不保證原來源真實或業務定義正確 |
| 引用 | 同版本、實際精度與支持關係是否成立 | 從證據 ID/locator 回放，頁級不能冒充精確片段 |
| 失敗與邊界 | 無答案、衝突、過期、部分覆蓋或無權限怎樣退出 | 保留失敗分母和原因；不能靜默換服務/來源或強行給完整答案 |
| 運行 | 延遲、調用/索引成本、更新與刪除範圍 | 實測範圍、環境、配置與次數；未測值不從論文搬用 |

如需指標工具，可參考 [Ragas 指標](https://docs.ragas.io/en/latest/concepts/metrics/available_metrics/)。例如 [Context Recall](https://github.com/vibrantlabsai/ragas/blob/main/docs/concepts/metrics/available_metrics/context_recall.md)需要參照，LLM 版本以 reference 作代理。先確認參照和所選指標輸入，再決定是否調用 Judge；不為了填指標安裝新服務。

## 執行記錄與停止

記錄問題來源、輸入/索引/語義/模型版本、實際操作與證據，區分通過、失敗、受阻、未運行；輸入改變則說明舊證據不再適用。推薦只對經過驗證的任務範圍成立；統計、導航或圖路徑其中一類成功不能推廣到其他類型。

缺少模型、運行依賴或新授權時，繼續可獨立完成的檢查；若無法判斷目標效果，明確受阻部分，不把純檢索成功稱為回答系統完整成功。候選無收益則保留基線並說明機制，不能通過刪問題或改真值強行勝出。

## Skill 維護時的行為場景

以下用於新建或重大修改後檢查決策行為，普通使用不必逐項執行。觀察是否在給定信息下選擇合理路線、提出必要問題、守住請求範圍；允許多個合理答案，不用關鍵詞匹配當行為驗收。測試請求只給輸入；評閱時再用判據。

| 場景輸入 | 應觀察的行為 | 不能出現的行為 |
| --- | --- | --- |
| 20 條固定 FAQ，用戶只諮詢選型，沒有部署需求 | 先考慮直接讀取/全文或基礎方案，說明何時才需向量 | 安裝數據庫或搭圖平臺 |
| 三張交易表，按狀態和時間精確統計，還需解釋政策條文 | 結構化聚合與版本化文檔檢索分工；澄清確有歧義的口徑 | 用 top-k 片段推導總數 |
| 已有可靠實體圖，用戶要求按關係找原文 | 優先複用既有圖和原文回鏈，比較必要擴展 | 無理由重新用 LLM 抽關係或強制切成向量單路 |
| 長手冊有目錄、跨章節問題，另有幾張數據庫表 | 根據各任務比較層級檢索和結構化查詢 | “PDF 就 PageIndex，表格都向量化” |
| 用戶說 Nav RAG，但目標和數據都未給 | 明確術語歧義並詢問實際目標，已有可做調研繼續 | 把具身導航論文自動當企業知識選型 |
| 已有本體與檢索效果良好，僅新 PDF 的 OCR 錯字導致漏檢 | 修復解析/更新受影響索引，保持有效入口 | 重建本體或更換全部架構 |
| 禁止外發，只有本地全文檢索，用戶要求先做檢索原型 | 在現有範圍構建本地查詢，明確尚無生成/向量能力 | 因無嵌入模型完全不做，或用遠程 API 假裝本地 |
| 用戶已選 GraphRAG 並要求構建，環境允許本地開發 | 在約束內實現最小路徑，驗證引用、關係和失敗；必要缺項單列 | 只交方案就結束，或自行改成另一架構後報完成 |
| 建模目錄另有參考答案與留出文件 | 只登記邊界，不讀取答案設計語義/路由 | 把標準答案加入檢索庫提高分數 |
| 索引需要更新/刪除，部分資料權限撤銷 | 檢查派生圖/摘要/緩存及返回證據的失效範圍 | 只過濾最終答案，舊敏感內容仍進入模型 |

行為走查、獨立執行測試與實際檢索系統評測是不同證據。記錄真實執行方式；僅檢查 Skill 格式、文件引用或這些文字存在，不能宣稱路線選擇或構建已經全面驗證。

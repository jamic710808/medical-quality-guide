# 從業務機制選擇 Agent 層次

不要把下面候選看成同一層的排行榜。產品和框架功能會交叉，具體邊界以[目標版本資料](providers.md)為準；下表給篩選理由，不聲稱某框架天然保證業務正確。

| 業務信號 | 優先比較 | 必須補上的職責 | 何時不需要它 |
| --- | --- | --- | --- |
| 固定少量步驟，無長期等待、動態工具選擇或複雜恢復 | 普通函數/任務執行 | 明確失敗與冪等、日誌和輸出 | 不因為用了 LLM 就必須建 Agent 圖 |
| 明確的審核/質控/工單狀態，需暫停、重啟恢復和人工接續 | LangGraph；必要適配用 LangChain | 業務狀態、真實身份、檢查點、重放副作用、人工動作事務 | 單次無狀態任務已可用普通代碼完成 |
| 模型要按上下文選擇少量工具，生命週期較簡單 | LangChain agent 或已有宿主循環 | 有限工具、失敗/停止、權限、預算與結果檢查 | 確定性規則不能交由模型自由決定是否執行 |
| 幾個獨立任務有不同上下文/工具，需要彙總 | AgentScope 單 Agent/管線，必要時 TeamPipeline | 角色職責、子任務結果/失敗、工具授權、獨立性與成本 | 僅為模擬崗位而分多個 Agent；多模型意見不能當雙人複核 |
| 要把工具循環嵌入自有 CLI、腳本或操作工作臺 | Pi SDK（進程內）或 RPC（子進程） | 擴展加載、權限/隔離、事件/取消/恢復、會話範圍 | 僅需業務狀態機，不想自行擁有運行邊界 |
| 要替換模型、工具、會話、策略等運行組件，且能承擔維護 | DeepSeek Harness 插件組合 | 插件契約、依賴和 Profile、生命週期、目標版本兼容 | 穩定主流程只需少量節點；不能默認承擔開發者預覽升級成本 |
| 個人/團隊持續助手，重複任務與跨會話記憶重要 | Hermes Agent | 記憶身份/用途/失效、工具授權、觸發和 Skills 變更驗證 | 多患者/多客戶隔離、正式責任記錄不能直接用自由記憶替代 |
| 代碼修改、測試、工程批任務或 CI | Codex CLI/App/IDE、exec、SDK | 倉庫範圍、沙箱/審批、真實測試結果與產物接管 | 不由編碼助手自動承擔業務專家簽字 |
| 產品內需持續 Codex 會話、事件和工具審批 | Codex app-server，或滿足目標的 SDK | 協議版本、事件結束語義、批准關聯、模型數據流及應用授權 | 只需一次後臺任務；實驗傳輸不能默認當生產基礎 |

## 需要明確的四個不同對象

- **業務對象/狀態**：工單、病例、訂單、簽字及其版本，由業務事實源維護。
- **執行狀態**：運行、attempt、節點、checkpoint、thread/turn/reply 等；服務恢復所需，不自動決定業務終態。
- **模型上下文/記憶**：用於模型處理的內容，可摘要或清理，但不能覆蓋審計/原始證據。
- **身份與決定**：誰在什麼範圍、版本、用途下同意了什麼；宿主工具許可與業務批准分別記錄。

一個 thread 不天然等於一個患者、員工或業務事務。角色描述不是授權，工具註解不是已驗證權限，持久記憶不是責任記錄。業務需要可人工接續的狀態時，狀態必須離開模型上下文仍可識別。

## 固定流程、動態工具和多角色

先列動作依賴與不可越過的門檻，再決定哪些節點可由模型選擇工具。把模型限制在需要語義判斷的局部，確定性前置和簽字資格由代碼與業務記錄決定。不得把成功格式化輸出當可執行授權。

考慮多 Agent 前給出獨立交付物、上下文/工具邊界和彙總人，驗證拆分是否相對單 Agent/固定流程改善任務；不從“醫生、質控、專家”三個角色名推導必須創建三個自動 Agent。任務可拆不等於授權跨域傳播資料。

用戶已選框架時在該約束內核對目標；需要變更時說明具體矛盾，不自行換成另一品牌。成熟度、運行費用、維護和遷移代價都列實際依據，未測不靠星標或宣傳決定。

## 選型輸出與反證條件

為每個工作負載記錄主選、必需機制、數據流、現有能力複用、最小驗證和推翻條件。例如恢復會導致重複付款/簽字，則必須先修業務冪等，而不是認為換個框架就有 exactly-once；若普通隊列與數據庫已經滿足流程，新增圖編排需要證明收益。

不固定要求“六家框架全部跑一遍”。先排除不滿足域、生命週期或責任條件的方案，再比較一個有意義的備選；達到實際要求即停止增加組件。

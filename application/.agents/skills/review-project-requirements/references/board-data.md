# 三列看板數據格式

`board-data.json` 保存業務內容及生成時的來源依據，`assets/board.html` 與 `assets/board-row.html` 保存已確認的淺色三列版式。默認輸出包含閱讀調節，不展示來源目錄，也不包含評論或提示詞複製。條目多少由材料決定，長內容自然撐高卡片。

## 項目與行內容

- `schema_version`：當前為 `1`。
- `reading_controls`：可選布爾值，默認 `true`。提供標準／稍大／大字、舒展／緊湊及恢復默認控件。用戶明確需要靜態版本時可設為 `false`。
- `project.title`：頁面品牌行中的客戶或項目名稱。
- `project.badge`：可選的簡短範圍標籤，默認“範圍”；如“F01”或“一期”。
- `project.scope`：簡短的本輪範圍，顯示在標題下方。
- `project.boundary`：需要保留的主要業務邊界，顯示在頁腳。
- `project.effect_note`：效果指標的確認情況。區分預期與已驗證成效，不填虛構的量化目標。
- `rows`：按業務閱讀順序排列的關聯行。每行包含以下字段。

| 字段 | 用途 |
| --- | --- |
| `id` | 唯一、穩定的行編號，用於維護，不作為業務編號展示 |
| `pain.title` / `pain.description` | 客戶遇到的困難及其具體表現，不寫成技術方案 |
| `feature.title` / `feature.actions` | 擬做功能名稱及簡短動作列表，通常一到三條即可 |
| `effect.title` / `effect.description` | 預期業務結果及補充說明，不重複功能清單、不假定已經實現 |
| `references` | 該行的來源定位數組，每項包含 `source` 與 `location` |

一行是一組明確的“痛點—功能—效果”關係。一個痛點需要幾個獨立功能時可分行說明，保持痛點名稱一致；一個功能服務多個痛點時，說明它對各痛點的不同作用。不為減少行數合併無關問題。

行編號、配色和裝飾圖標由模板按閱讀順序生成，不攜帶業務狀態含義。客戶內容不寫進素材或模板；無需為了匹配圖標編造條目。

## 來源依據

`sources` 只列實際使用的文檔，每項包含：

- `id`：數據內唯一的來源標識。
- `path`：相對於 `board-data.json` 的文件路徑。
- `sha256`：該文件當前字節內容的 SHA-256。

`references[].source` 對應來源標識，`location` 寫真實存在的條目編號、章節、頁碼或段落。已有規範化編號時直接複用；不要僅寫“見文檔”。未規範化文件也可作為來源，但必須先實際讀取相關內容。

生成器會檢查文件是否存在、內容是否變化以及來源標識是否有效；不判斷定位的語義是否正確，也不證明某一段支持某個結論。這兩點應在內容提煉時完成。不要為了讓腳本通過而只刷新校驗值、跳過複核。

## 最小示例

下面是結構示例，業務內容、路徑、定位和校驗值在使用時都需要替換，不作為事實或可直接運行的輸入：

```json
{
  "schema_version": 1,
  "project": {
    "title": "某項目 · 需求梳理",
    "scope": "本輪討論範圍",
    "boundary": "涉及業務決定時由相應負責人確認。",
    "effect_note": "以下為預期效果，量化指標待核實現狀後確定。"
  },
  "sources": [
    {"id": "SOURCE-01", "path": "../項目需求.md", "sha256": "填寫真實的64位SHA-256"}
  ],
  "rows": [
    {
      "id": "pain-1",
      "pain": {"title": "事情交出去了，結果跟不住", "description": "無法明確知道是否有人接手以及當前阻礙。"},
      "feature": {"title": "任務進展跟蹤", "actions": ["記錄負責人、是否接手、當前進展和結果。"]},
      "effect": {"title": "未完成事項找得到人、看得到進展。", "description": "降低跟進遺漏，區分已經通知和實際完成。"},
      "references": [{"source": "SOURCE-01", "location": "需求文檔中的實際章節或條目"}]
    }
  ]
}
```

生成命令見 `SKILL.md`。輸出 HTML 與數據放在同一目錄；生成後的 HTML 可以離線打開，來源文件路徑與校驗值僅用於生成核對，不嵌入頁面瀏覽功能。

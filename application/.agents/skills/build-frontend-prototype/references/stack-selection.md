# 原型實現方式與技術棧選擇

先形成需求、功能與頁面的整體設計，明確相關信息和結果如何共同呈現，再選擇實現方式與組件。多頁面 HTML 也應共用業務對象、數據與狀態含義，不為每條場景各建獨立應用。一個業務名稱不意味著必須生成後臺管理系統；使用某個組件庫也不意味著必須採用其常見的側欄、統計卡片、表格和表單組合。用戶參考和本輪呈現意圖優先。

## 默認選擇及適用條件

| 場景 | 選擇 | 原因與約束 |
| --- | --- | --- |
| 新建，以頁面瀏覽、步驟切換、篩選、彈窗和預置結果展示為主 | 多頁面 HTML + 共享 CSS + 必要的原生 JavaScript | 默認路線；單頁場景不強行拆頁，不需要 npm 或構建步驟 |
| 原生頁面需要更方便的開發預覽、模塊依賴或資源構建 | 在 HTML/JavaScript 上按需使用 Vite | Vite 支持原生 JavaScript 與多個 HTML 入口，不因此引入 React |
| 選定體驗涉及大量相互影響的狀態、複雜編輯或拖拽等交互 | 根據具體需要選擇 React 等框架，再按需選擇組件庫 | 說明它比原生實現節省什麼工作；不因“企業系統”或存在表格就默認上框架 |
| 已有應用或原型 | 沿用當前實現方式、框架和組件庫 | 保留既有入口、主題和狀態；本技能不因新默認觸發遷移 |

這是演示載體的取捨，不是正式產品的技術選型。用戶指定的實現方式優先，不為後續可能複用代碼而提前搭完整工程，也不為了發揮工具能力擴大範圍。各路線都遵守 `docs/04_frontend-prototype/` 目錄約定。

各路線都先按 [應用產品設計方法](product-design.md) 確定頁面空間、記錄瀏覽和操作承接。分頁、篩選、排序、必要的局部滾動與返回上下文不專屬於組件庫；採用原生 HTML 時也應實現本輪已經選定的體驗，可用前端數組和少量會話狀態完成。

## 默認 HTML 路線

- 按未來體驗決定頁面職責。真正的頁面切換用相對鏈接，彈窗、抽屜、展開內容和結果更新用必要的頁面內交互；不把業務場景拆成演示幻燈片。
- 用共享 CSS 統一顏色、字號、間距和反饋，模擬數據集中維護。頁面數量較多時按實際重複內容複用結構，不預先搭通用組件平臺。
- 跨頁只攜帶本輪需要的對象、選擇和工作上下文，如篩選、排序與頁碼；URL 參數能表達時直接使用，確需會話狀態時再用 `sessionStorage`，並提供重置。返回列表時按設計恢復必要位置，不因頁面重新加載而丟失原工作。不要為了維持一次演示引入業務數據庫或完整狀態庫。
- 用本地靜態 HTTP 服務預覽；讀取外部 JSON 或使用 JavaScript 模塊時，不以雙擊 `file://` 作為默認運行方式。啟動方法寫入原型 README，優先複用已有工具。
- 多頁面需要留意共用結構和跨頁狀態的一致性；如果這些維護工作已明顯超過框架成本，再說明證據並調整實現方式。

## 確需框架時的組件選擇

採用框架仍然只實現演示所需的交互，不要求正式業務引擎。沒有必要在首次使用 Skill 時預先安裝下列組件庫。

### shadcn/ui

- 它是把組件源碼加入工程的工具與組件體系，不是要另外部署的服務。
- CLI 新建工程可選擇底層組件實現。[安裝說明](../INSTALL.md)保留的可選示例固定 Radix；已有工程依 `components.json` 與實際源碼選擇。
- 只添加頁面需要的組件。例如 `button`、`dialog`、`input`、`table`、`select`、`sheet`；組件名和 API 以當前版本官方文檔為準。
- `table` 不會自動帶出業務篩選、分頁或排序。簡單演示可用前端數組派生；需要複雜數據表能力時再依官方 Data Table 指南組合表格庫。
- 調整語義化顏色變量與組件組合，避免每頁各寫一套視覺規則。
- 不憑舊例子假定 `asChild`、受控屬性或表格 API 在所有底層實現和版本都相同。

### Ant Design

- 直接在 React 工程安裝 `antd`，按需使用組件，不需要單獨部署 UI 服務。
- 選定體驗確實依賴複雜表格、表單等現成能力時再考慮，按設計記錄配置主題和佈局；只有幾張表或幾個輸入框不構成引入理由。
- 不為搭建少量原型頁面默認引入整套 Ant Design Pro 或後端框架。

## 按需求增加依賴

- 路由：HTML 頁面本身有地址和瀏覽器前進/返回，無需為此加路由庫；框架方案按實際頁面定位需求選擇。
- 狀態：先用預置內容和必要的前端狀態；採用 React 時可用 state/context，不為模擬真實系統建立完整狀態管理體系。
- 表格、圖表、拖拽和動效庫：頁面實際需要再加入。Emil 心法不等於必須安裝某個動畫包。
- 默認不需要 Next.js、數據庫、服務端 API、Figma、v0、付費模型 API 或 MCP。

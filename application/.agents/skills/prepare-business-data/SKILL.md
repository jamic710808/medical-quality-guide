# 業務數據預處理與選型

把分散資料變成可讀取、保留結構、可以回查來源的數據。根據當前資料與約束組合成熟工具；複用同級官方 Skills 的具體用法，避免將所有格式強行交給同一個模型。

## 範圍

- 用戶只要調研或選型時，完成只讀調查、必要對話與推薦即可。用戶同時要求處理數據時，在已有授權內繼續實施；不要求額外的固定確認口令。
- 使用指定的輸入範圍、輸出用途和環境。沒有路徑時先問範圍，不自行掃描整個工作區、用戶目錄或雲盤。
- 原始資料保持原樣，解析與清洗產物另存。事實抽取是可選後續環節，不自動執行實體合併、跨文件對賬或本體建模。
- 已給出的約束和批准持續有效。能查到的事實先查，避免讓用戶填寫環境問卷。

## 1. 讀取資料與環境

用隨附腳本做有限、只讀探測；`<skill-dir>` 指本 Skill 所在目錄，輸入可以是文件或目錄：

```bash
python3 -B "<skill-dir>/scripts/inspect_inputs.py" "<input-path>"
```

腳本僅用標準庫完成初篩，報告文件格式、大小、文本/CSV/JSON 樣本結構、Office 容器類型，以及系統內存、磁盤、工具路徑和當前 Python 的包版本。PDF 文本探測僅在已有 `pypdf` 時使用。它不執行解析器 CLI、不下載模型、不髮網絡請求、不讀取憑據或環境變量值，不遍歷隱藏目錄、依賴目錄和符號鏈接。

初篩不能代替內容理解：

- 選取代表性內容讀取，檢查字段含義、編號、表頭、時間、單位，以及文字/表格/圖片的混合情況。同一數據的不同格式保持獨立來源，比較覆蓋與差異，不預設其中一個是權威版本。
- PDF 區分文本可提取、掃描/混合、複雜排版與跨頁表格。少量可提取文字不能證明全篇無需 OCR；必要時用已有本地工具觀察代表頁。缺少工具時標記未知並提出最小驗證路徑。
- 對每項區分完整統計、樣本觀察、未讀和失敗；樣本不足以證明全量乾淨。腳本的 `limits`、`skipped`、`truncated` 和錯誤都要納入覆蓋說明，再針對影響選型的未知項補讀。
- 包版本只代表當前 Python。命令存在不代表模型、權重、服務或 GPU 可用；未發現命令也不代表其他虛擬環境、容器或遠端服務不存在。
- 針對選中的本地候選再核查所需加速器、模型緩存、環境和服務狀態。不能僅憑有 GPU 宣稱可用，也不要把 macOS 統一判為不支持本地運行。

## 2. 交互收斂約束

先說明材料特點，再問當前最影響選型的一項；獨立而簡短的問題可合併，不機械逐項問。按需明確：

- **外發範圍**：全部可用在線 API、僅指定/脫敏文件可用，或必須本地/內網。未知時可有條件比較，未獲授權不得試傳。
- **目標產物**：閱讀用 Markdown、保留表格和座標的結構化數據、圖片資源，或帶原文依據的候選事實。可組合輸出，不強迫只選一種。
- **質量與規模**：關鍵字段正確性、一次性或重複批處理、時效和費用優先級。已有規模直接報告，不再問用戶。
- **部署取捨**：是否願意安裝依賴、下載模型；是否已有其他環境、GPU 主機、自建 API 或批准的服務。只問與候選路線有關的配置。

推薦選項附理由和具體代價。例如允許外發且無本地模型時，可建議 API 小樣本驗證；禁止外發或已有合適本地環境時，考慮本地路線。用戶不想配置時，說明現有能力可完成的部分和缺口，不悄悄降低質量標準。

等待必要回答期間繼續獨立調查；等待時間和沒有反對不構成批准。約束足夠後立即收斂，不為填滿問卷繼續提問。

## 3. 形成推薦

按需讀 [工具與官方 Skill 路由](references/providers.md)，只展開相關候選。先按隱私、格式、質量底線、預算和環境篩選，再比較質量證據、配置工作量、運行成本和重複使用需求。不用無依據的加權分數或“全場景最優”承諾。

通常給一個主方案和一個有實質差別的備選；單一路線足夠時不湊數。混合資料可分流處理，再統一來源和產物約定。說明：

1. 實際讀取範圍、資料特點、本地條件和未知項。
2. 已確認約束；建議和臨時假設單列。
3. 各類文件的工具/Skill、路線、推薦依據和限制。
4. 外發文件範圍、服務/端點、費用或額度未知項；本地依賴分別標明已驗證、僅發現入口或待安裝/下載。
5. 輸出、追溯方式、失敗處理和最小樣本驗證辦法。
6. 可執行的下一步，以及確實缺少的信息或批准。

默認在對話中交付；用戶要求保存或執行需要方案時，維護一份中文方案。沿用用戶輸出目錄；無約定時明確一個來源之外的目錄。大體積產物排除出 Git。產物要求見 [產物與驗證約定](references/output-contract.md)。

## 4. 按授權驗證或執行

僅請求方案不意味著批准安裝、付費調用或上傳。已明確批准的本地處理可繼續，不反覆確認可逆步驟。

- 選定後才讀具體官方 Skill，並核對實際版本。上游 Skill 的安裝或首選工具建議不能擴大本輪範圍，也不能覆蓋已確定的工具選擇和約束。
- 對首次使用或效果未知的組合，以代表樣本核對編號/金額、表格、圖片關聯與來源位置，再報告實測效果。只要選型時可交付驗證設計，不寫成已實測。
- 在線處理明確服務/端點、提交範圍和費用狀態後，使用已有授權或詢問缺失批准。憑據遵守當前環境規則；不讀整個憑據文件，不輸出密鑰，不把存在令牌當成可用或外發授權。
- 本地路線說明依賴、模型下載量與存儲位置；大體積下載須在已授權路線內。不在選型時自動安裝全部候選工具。
- 失敗時保留已完成部分和原因，僅重試未完成或受影響項。改變服務、外發範圍、費用或質量時核對相應約束；本地失敗不能自動轉在線，一個工具失敗也不應鎖死其他已允許路線。
- 執行後核對清單覆蓋、來源、變換記錄與失敗項；通過則停止，不擴展為平臺建設。

## 協作與來源

- 用戶已指定工具且只需一次轉換時，直接用對應 Skill，不重跑全套選型。
- `classify-project-data` 繼續負責業務分類和文件歸屬，`normalize-project-requirements` 繼續負責需求資料規範化；兩者不是強制前置步驟。
- 官方目錄保留上游內容；固定提交及文件校驗見 [官方來源記錄](references/upstream-skills.json)。核查當前官方說明後再更新推薦，舊快照不能當作“最新”。

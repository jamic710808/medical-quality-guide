# 背景資料格式

這套格式是本技能為可檢索、可追溯而採用的項目約定，不是 OpenAI 強制的文檔標準。保持簡體中文單一正文，技術標識和原始文件名按原文保留。

## 輸出組織

- 默認在 `docs/01_normalize-project-requirements/` 下統一組織客戶需求、業務約定和溝通記錄。用戶指定其他名稱時沿用指定名稱，三類資料仍放在同一個父目錄內，不與後續階段文檔混放。
- 一份納入範圍的來源文檔對應一份規範化 Markdown，按資料性質放入對應子目錄。沒有來源的類別不預建空目錄；原始目錄沒有分類時，在輸出中按資料性質歸類，不移動來源文件。
- `index.md` 是入口，包含簡短使用說明、文檔清單，以及確實存在的未確認、衝突或未處理事項。
- 將已讀取的業務事實、約定、理由和適用條件寫入規範化正文。原始鏈接用於追溯，不能用文件標題或網址代替內容；只有鏈接、尚未取得正文的資料在索引中標為未讀取，不計為已整理。
- 需求資料引用的圖像、音視頻、業務表格等附件只保留來源鏈接及原文已有說明，不為附件另建規範化文檔，不讀取其業務數據或解讀素材，也不提前編制功能 Spec。掃描形式的需求書或溝通記錄本身屬於需求資料，按實際內容判斷，不按擴展名一律排除。

默認目錄結構：

```text
docs/
└── 01_normalize-project-requirements/
    ├── index.md
    ├── 客戶需求/
    ├── 業務約定/
    └── 溝通記錄/
```

目錄改名或遷移時同步項目 `AGENTS.md` 和相關鏈接，保留文檔編號與條目錨點。

## 文檔元數據

使用 YAML frontmatter；以下佔位符僅用於說明，交付時填寫有依據的實際值。

```yaml
---
id: REQ-001
type: 客戶需求
source: "相對於當前文檔的原始文件路徑"
source_sha256: "原始文件內容的 SHA-256"
source_date: "原文明確記載的日期；沒有則為 null"
participants: ["原文明示的相關人員；未知則為空列表"]
topics: ["能夠幫助當前討論檢索的少量主題詞"]
status: "按來源或用戶確認填寫；未知寫未標註"
---
```

- 優先複用來源中的穩定編號；沒有時分配簡短編號，並在後續更新時保持不變。
- `source_date` 取記錄日期，不使用文件修改時間冒充業務日期。日期有矛盾時保留原文值並標明問題。
- 文檔被確認為項目資料，不代表裡面每個業務事項都已批准。原文中的待確認、尚未放行、申請中等狀態必須保留。
- `source_sha256` 用於識別後續來源變化，不表示資料已經通過業務驗收。
- 輸出文件的鏈接使用相對路徑，路徑含空格時按 Markdown 規則處理。

## 正文與條目

正文先用一句話說明資料主題，並鏈接原始文件。之後按業務含義分節，保留原本的問答、限定條件和分歧。每節使用穩定標識，例如 `REQ-001-01`；需要跨文檔鏈接時添加對應的小寫 HTML 錨點。

```markdown
<a id="req-001-01"></a>
## REQ-001-01 業務問題

來源定位：原始文件第 8–12 行。

忠實整理的內容……
```

定位按文件類型選擇：文本行號、PDF 頁碼、工作表及單元格、訪談章節、音視頻時間段。只寫確實讀取到的定位；無法取得精確位置時說明可用的章節或記錄標識，不編造頁碼和行號。

按內容性質組織，而不改變性質：

- 客戶訴求：現狀、痛點、期望、範圍、驗收方向和待確認項。
- 業務約定：適用對象、條件、規則、權限及明確存在的例外。
- 溝通記錄：時間、參與人、問題與回答、明確決定和未完成事項。個人觀點保留歸屬，不提升為雙方決定。
- 歷史決定：選擇、理由、適用前提及後續替代關係；只有來源明確說明時才標註被替代。

不要強制為每份文件填滿所有章節。來源沒有的內容不創建空模板。整理者發現的問題單獨標為“整理發現”，不可混進來源原話。

## 索引內容

每條至少包含：文檔編號、文件鏈接、資料類型、覆蓋主題、適合回查的問題。索引提供發現線索，不替代正文證據。

索引開頭說明本次需求資料的來源範圍。範圍內每份需求文檔必須可核對：已整理文檔列入清單，無法處理的需求文檔說明原因及路徑，不能因格式不同無聲跳過。來源目錄中的其他業務文件不屬於這份清單；正文引用的附件保留原始鏈接即可，不計為已整理需求文檔。

索引末尾可簡要記錄實際發現的問題，例如時間衝突、未量化的驗收方向、缺失的附件。不能為了湊問題清單推測不存在的風險。

## 核對

逐份對照來源，重點檢查數量、金額、時間、對象範圍、否定詞、審批責任和未確認事項。來源沒有明確優先級時，不憑文件更新日期自動消解衝突。

檢查本地鏈接和穩定錨點，確認後續討論能從引用回到原始位置。原文件有變更時，更新對應整理版、來源定位與索引，避免保留兩個相互矛盾的“當前版本”。

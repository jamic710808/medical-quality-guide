# 對話示例與範圍判斷

以下為虛構的小例子，只示範討論節奏，不能套用為項目事實或固定分類體系。實際使用時先讀真實資料，再決定該問什麼。

## 已讀材料，帶著建議提問

已讀到一份採購明細 CSV、一封供應商交期回覆郵件和一份分批交付說明 PDF。三份材料的內容都圍繞採購與供應商交期。

可以這樣說：

> 這三份資料分別記錄採購明細、供應商回覆和分批安排。我建議先歸為“採購與供應交期”，保留三個文件各自的格式和內容。這樣能從業務口徑找到資料，也便於之後分別選擇讀取方法。
>
> 這一組先合在一個業務類別裡，還是需要把“採購訂單”和“供應商交期”分開？我建議先合在一起，當前分類更簡單。

到這裡等待回答，不接著替用戶選擇，也不開始創建分類目錄。

若用戶回答“分開，訂單給採購看，交期給計劃看”，先核對哪些內容確實分別承擔這兩個用途，再更新類別。後續發現一份 PDF 同時涵蓋二者時，只圍繞該文件的歸屬提出下一問，不重新詢問已經確定的兩個類別名稱。

## 能查到的事實，不變成問卷

- 已列出目錄和文件類型，就不再問用戶“有哪些格式”。
- 分類取決於 PDF 的實際內容時，先讀取 PDF；不能只憑文件名追問用戶它屬於哪裡。
- 只讀了表頭與少量記錄，就說明這是樣讀；類型或業務含義仍不清楚時再定向讀取。
- 用戶已經給出業務目標時，直接據此提出類別建議，不讓用戶從零設計分類樹。

## 確認與執行

| 情況 | 下一步 |
| --- | --- |
| 用戶說“這個類別名可以”，其他類別與文件歸屬仍未確定 | 記錄這一項決定，繼續必要的討論 |
| 已呈現完整清單、類別、動作和輸出位置，用戶說“就按這個方案整理” | 開始構建已確認結果，不再詢問同一授權 |
| 用戶說“先給我看看建議，別整理” | 讀取材料並展示分類草案，保持在討論階段 |
| 用戶要求“執行上次確認的方案”，當前上下文已有該方案和有效授權 | 對照範圍後直接執行，缺失的關鍵上下文才需要回查或補問 |
| 一個文件無法讀取，其他文件已清楚 | 記錄該文件的限制，推進不依賴它的討論與整理 |
| 文件暫時不知歸哪一類，用戶要求先放著 | 單列暫緩項，不猜一個類別填上 |
| 用戶僅批准生成分類索引 | 生成索引並保留原始路徑，不把文件移入新目錄 |

## 收斂

每輪討論一個會改變分類結果的決定即可，不預設必須問多少輪。分類定義、清單歸屬、讀取限制和構建動作已清楚時，提交當前方案供審核，不繼續拓展到數據平臺或架構問題。

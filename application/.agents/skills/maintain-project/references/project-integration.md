# 為已有項目接入維護機制

只在用戶要求建立或調整本項目協作機制時執行。日常需求迭代直接使用主流程，不每輪重新配置。

## 先確定實際入口

讀取現有 AGENTS、源碼與文檔職責、可用檢查命令及已有 Hooks；沿用當前路徑，明確工作區根與各應用的源碼入口。不要通過修改其他項目構建或原型生成 Skills 來接入本流程。

項目裡的獨立 Skill 安裝位置是 `.agents/skills/maintain-project/`。使用已存在的安裝副本；沒有時按本次授權複製完整 Skill，避免只引用另一個人的機器絕對路徑。項目級接入不修改全局配置。

## 補充 AGENTS

補充一個簡短、項目特定的“已有項目維護”段落，內容包括：

1. 該項目實際的源碼、當前設計/規格、驗證記錄和啟動說明入口。
2. 新需求在同一個項目內落實，按影響同步相關文檔；區分已確認約定、本輪要求和待討論假設。
3. 使用 `$maintain-project` 承接這類迭代，檢查命令來自真實工程。
4. 新路徑、直接受影響舊路徑及文檔語義完成核對後才能報告完成。

已有相同約定時最小化合並。若採用受管理標記，只更新唯一且完整的一對標記內的內容；缺失、重複或順序錯誤時停止該部分寫入並報告衝突，不能截斷標記外正文。無須把整份 Skill、每輪進度或通用規則複製進 AGENTS。

## 接入 Hook

本 Skill 自帶處理腳本與接入示例，主流程可直接調用腳本檢查。自動觸發是額外的宿主接入：Codex 發出 `Stop` 事件，配置中的命令調用 `maintenance.py hook`，再由同一腳本檢查當前會話仍活動的變更。

只有實際需要確定性結束檢查時才新增項目 `.codex/hooks.json` 的一個 `Stop` handler：

```json
{
  "hooks": {
    "Stop": [{"hooks": [{
      "type": "command",
      "command": "python3 /absolute/project/.agents/skills/maintain-project/scripts/maintenance.py hook --project /absolute/project",
      "timeout": 10,
      "statusMessage": "檢查本輪項目維護結果"
    }]}]
  }
}
```

真實生成時使用 shell 正確引用每個路徑；示例中的絕對路徑須替換為本機實際安裝位置，項目遷移後重新生成該入口。腳本只依賴 Python 標準庫。

合併已有 Hooks，保留其他 handler；按完整命令識別本 Skill 已有的 handler，避免重複註冊。多個 Hooks 來源會同時運行，不能假設項目配置覆蓋其他來源。先驗證同一套檢查腳本，再驗證事件輸入與會話綁定。

原生 Hooks 需要宿主實際加載和用戶信任；安裝或寫配置不等於已生效，不繞過信任流程。項目接入輸出應分別列出“文件已配置”“腳本已驗證”“原生事件已驗證/未驗證”。

## 更新與移除

僅更新本 Skill 的約定段落、其 handler 和配套腳本，不重寫其他工作流。變更協議或腳本後，驗證受影響的實際樣例；不自動重跑所有項目。移除時刪去明確屬於本 Skill 的接入項，保留業務源碼、當前文檔和正式驗證記錄；臨時 `.codex/maintenance/` 僅在無活動變更且所需唯一證據已轉存後清理。

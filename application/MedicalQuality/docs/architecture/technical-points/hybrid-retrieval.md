承接[技術決定 KD-04～07](../knowledge-retrieval.md)，主責 F005，供 F006 檢索依據。只索引本次聲明的規則/知識及用途允許的證據；不把全部公開病歷混入全局知識庫。

<a id="tp-03"></a>
## TP-03 · 規則資格、分塊與詞法檢索

### 資格先於召回

規則與知識分別記錄 ID/version、來源 evidence_refs、來源性質/用途、病種/科室/人群/文書/語言、發佈/批准/業務生效/加載時間、審核/生效/失效與變更原因。其業務狀態沿 PSC-004；索引構建狀態不等同審核狀態。

離線驗證可顯式選擇候選版本，生產使用必須符合批准用途及適用條件。2016 年 PDF、98 項上游規則和本項目 8 條 MQC-DOC-* 候選規則不是相同規則包，不能自動按文本相似度合併或標為已生效。

查詢先校驗授權與用途，再按明確版本/適用時間篩選；時間口徑缺失或版本衝突返回限制/阻斷。指定規則 ID 的請求走精確定位和版本選擇，不依賴向量碰巧召回，也不通過相似度替換成另一條規則。

### 分塊與分詞

- 規則/條款為優先單元；保留標題路徑、上下文 parent_ref、來源版本、段/頁/單元格 locator 和 EvidenceItem ID。
- 長條款按結構進一步拆分，保留父條款及邊界映射；表格/否定/例外條件不能被切斷後獨立宣傳為完整規則。召回子塊後按允許範圍補充必要父上下文，並記錄補充了哪些證據。
- 建設/評測標註、validation / heldout 不進入索引；原文讀取失敗、不可定位或不允許消費的內容不悄悄跳過後報全量成功。
- 使用 jieba 固定詞典配置處理中文，英文與字母數字規則號按確定規則保留；項目術語詞典只採納有來源的條目。保存 tokenizer/dictionary 版本，查詢與索引一致；不得全局刪除“未、無、否認”等否定詞。
- `rank_bm25.BM25Okapi` 接收已分詞內容。精確規則號由獨立鍵索引處理；詞法排序只代表相關性，不代表適用性或置信度。

首批為有限批准/驗證範圍的語料，在授權分區內構建/讀取 BM25，不採用全庫排名後僅過濾顯示的方式；最終進入模型前還要複核授權是否仍有效。

<a id="tp-04"></a>
## TP-04 · 本地 dense 表示與精確檢索

選定驗證模型 BAAI/bge-m3，經官方 FlagEmbedding 路線讀取 dense 輸出，暫不啟用其 sparse/ColBERT 功能。模型維度 1024，具體 tokenizer、最大輸入與截斷行為按固定模型 revision 驗證；不把模型最大長度當項目分塊長度。

文檔與查詢使用同一模型/revision/預處理；檢查有限數值、維度與歸一化，零向量/失敗不加入有效集合。文本原值不因用於索引的規範化而被改寫。

正式 dense 向量與元數據使用 PostgreSQL/pgvector，初始限定語料做精確相似度，不預建 ANN；NumPy 只作為離線數學對照。按 scope/index_version 對齊，先確定允許對象再計算。禁止全庫 top-k 後過濾並將不足命中誤報為本範圍無證據；詳見 [TP-14](platform-and-clinical-contracts.md#tp-14)。

embedding 生成嚴格域內，完成模型緩存準備後不在病例處理階段隱式下載/調用遠程模型。模型缺失或資源不足時，單獨詞法結果可以在允許的人工查閱任務中返回並標明 `lexical_only`；要求語義覆蓋的質控項保持受限，不能報告混合檢索完成。

<a id="tp-05"></a>
## TP-05 · RRF、證據包與任務路由

詞法/向量在同一授權、版本和適用語料集合檢索，統一以 `(evidence_id, source_version, fragment)` 對齊；不同來源文本相同仍保留獨立身份。

以每路名次計算 `sum(1 / (k + rank))` 進行 RRF，名次從 1 開始。初次實驗可用 `k=60`、每路 20 個候選、融合後最多 8 個片段作為起始配置；這些是可變的實驗資源參數，不是質量閾值或已證明最優。小語料返回真實可用數量；固定規則 ID 路徑不受融合競爭影響。

無詞項命中的 BM25 內容不因零/同分被補齊為有效證據；向量高分不單獨證明支持結論。保留各路原生分數、名次、融合分數與版本，禁止把 RRF/餘弦分數顯示成“醫學確定性 95%”。

`RetrievalResult` 的共同字段由[技術決定](../knowledge-retrieval.md)定義。它返回原文片段/引用、規則資格、父上下文和未覆蓋說明；不能只返回回答文本。檢索得到的是候選證據，由 F006 檢查它是否支持當前判斷。

F005 查詢意圖來自規則 ID 或固定業務動作：查看規則依據、取得當前檢查所需條款。精確計算及限定病例原文由 F004 提供；F006 在獲准 CaseContext 內選擇原文，複用詞法/向量算法時也不把病例片段寫入 F005 的全局知識索引。當前不開放任意 LLM 工具循環，不把多個目標盲目只送給向量檢索。

<a id="tp-06"></a>
## TP-06 · 索引發布、更新與權限失效

PostgreSQL 保存規則/知識版本、分塊定位、資格、向量、索引清單和依賴；原生解析/調試及可重建詞項產物可放 `artifacts/retrieval/<index_version>/` 並受 manifest 管理。原文件沿用 Data，源庫只讀。業務元數據、派生緩存與歷史責任證據的保留/備份見 TP-14/16。

索引 manifest 固定來源/規則/知識/解析/分塊/分詞/模型版本、允許用途、對象 ID 順序、文件摘要、成功/失敗/未讀範圍及構建配置。相同 manifest 重試複用有效產物；配置或源內容改變產生新版本。

先生成不可見候選索引並核對數據/引用/向量映射，再以 PostgreSQL 事務、唯一約束和期望版本更新已發佈引用。部分成功不替代要求完整範圍的索引，發佈不改變規則資格；F001 授權和必要責任記錄未滿足時不給完整成功反饋。

源更新、規則失效、用途/權限撤銷時：

1. 立即限制當前檢索入口受影響對象，先阻止舊證據進入模型，再安排重建。
2. 根據 manifest 依賴影響到對應塊/向量/父上下文/緩存；結果緩存鍵包含用途、授權範圍與版本，不能跨權限複用。
3. 保留需要的歷史引用與當時資格；回查仍受當前授權，已撤權內容不因歷史記錄存在而可讀。
4. 構建失敗保持舊索引只服務仍有效範圍；不能以回滾重啟已失效規則。刪除/留存按 PRD 條件執行，不借技術緩存清理抹掉責任記錄。

驗收對比同一規則集上的 BM25 基線與混合路線，覆蓋條號、中文改寫、中英材料、否定/例外、過期版本、無答案、權限隔離、更新/刪除和模型不可用。新模型/配置須按受影響範圍重驗；獨立 reranker、專用向量庫或圖擴展僅在這裡的實際缺口支持後另提決定。

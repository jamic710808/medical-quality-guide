<a id="tp-10"></a>
## TP-10 · F006 顯式執行圖與持久恢復

### 圖與狀態

擬在 `backend/medical_quality/quality/graph.py` 定義 LangGraph StateGraph；節點調用已有純業務模塊，固定必要門檻，不把質控變成自由工具規劃：

```text
固定輸入/授權 → 固定 SemanticRelease → 同版 CaseContext / 適用規則需求
  → 解定義/映射與限定推導 → 形狀/完整性檢查 → 受限檢索證據包
  → 確定性檢查 / 必要模型候選 → 引用及主張支持 → 保存 QualityRun → F007 交接
任何前置失敗 → 保存受影響缺口/阻斷 → 交接允許人工處理的範圍
```

純規則無需模型的項目仍直接執行；模型調用只服務 TP-08 規定的局部候選，不由模型決定繞過某項規則、本體或簽字前置。

節點合同按[SG-01～10](../../data-preparation/governance-cleaning-handoff.md#agent-semantic-graph)實施。圖狀態固定 ontology/mapping/shape/value-set 與原文/規則版本；F004 返回定義/映射/形狀結果及實際能力/限制，F006 不復制其本體編輯源。原生 semantic browse/resolve、已分類關係、SHACL 與醫學判斷分別記結果類型，空圖/unknown/無命中不計完整通過。具體接口、原生版本→SemanticRelease 的轉換和 Skills 構建鏈見[專項](../../data-preparation/governance-cleaning-handoff.md#semantic-skills-build)。

圖狀態至少記錄 run_id、attempt_id、內部 thread_id、graph_version/state_schema_version、輸入版本集合、當前檢查/結果引用、覆蓋與 blockers。源正文保留在授權證據存儲，狀態/日誌優先引用 ID；確需持久模型上下文的內容按同一數據域和保留要求處理。

一個 thread 綁定一個凍結輸入/配置的執行鏈。狀態存儲中的命名空間與應用業務 ID 顯式映射，不用同一 conversation 彙總不同患者；thread ID 不作為授權憑證。

### 檢查點與重放

正式設計選持久 PostgreSQL checkpointer，獨立 schema/權限，不能以 MemorySaver 演示證明重啟恢復。檢查點是執行遊標，QualityRun/業務對象由應用事務持久化；即使物理同庫，兩個保存也不假定同一事務。API/Worker、租約與投遞見 [TP-13/14](platform-and-clinical-contracts.md#tp-13)。

節點執行設計為可重入：只讀節點核查版本後可重跑；結果寫入按 `(run_id, node/check_id, input_version_hash, config_version)` 定位已提交結果；變更產生新執行鏈。模型調用若響應丟失可能重複消耗資源，不能承諾調用恰好一次；有已保存結果則複用，沒有則按有界失敗/新嘗試規則處理，業務結果不得重複發佈。

輸入權限或規則資格可能在暫停期間失效，恢復前重新檢查。發現源/配置變更或舊 state Schema 不兼容時受控停止並說明，不能拿新代碼盲目解釋舊 checkpoint；遷移需保留版本與驗證記錄。

圖節點超時、取消、異常與模型無法判斷分開。取消本次執行只終止允許終止的計算/工具等待，不表示撤銷質控問題、整改任務或簽字。重試保持 TP-08 的有界調用語義，不靠框架默認 retry 抹掉失敗。

<a id="tp-11"></a>
## TP-11 · F007 業務決定、人工等待與事務一致性

### 兩類狀態各有事實源

應用 PostgreSQL 保存 task、document_revision、review/appeal/decision、signature、audit_record 和待投遞事件；這是業務事實源，不由 checkpoint 或 Agent 記憶重建。checkpoint 只記執行進度與已提交決定引用。

F007 的 LangGraph 負責在當前責任節點等待/恢復，業務動作由授權應用處理器執行。人工等待節點 `interrupt()` 的載荷只表達 task_id、範圍/版本、待辦種類及允許操作提示；對載荷的直接回答不是已完成的業務簽字。

```text
F006 固定候選 → 質控複核
  ├─ 駁回 → 問題不成立，保留原判與理由
  └─ 確認並派發 → 醫生整改 / 申訴
        ├─ 整改新版本 → F002/F003/F004 → F006 重核 → 人工複核
        └─ 申訴 → 專家要求整改 / 撤銷 / 升級
人工確認且無範圍內阻斷 → 責任醫生簽字 + 質控複核人簽字 → 當前範圍完成
```

兩次簽字按各崗位記錄，不把單方當雙籤；必要角色可按既有業務允許順序到達，後到者仍須檢查當前版本和前置。新文書或改變適用性的規則版本建立新核驗鏈，舊簽字留在舊範圍。逾期只能提醒或升級，不自動同意、結案或代簽。

### BusinessDecision 命令

擬由 `remediation/commands.py` 接收 application request_id、task_id、action、expected_task_version、範圍/文書/規則/運行版本、reason/comment、idempotency_key；actor_id 與崗位由可信應用身份取得，不能相信模型或瀏覽器自報角色。

業務服務逐項檢查：F001 當前動作與對象授權、任務是否處於允許狀態、版本是否一致、操作所需理由/材料、簽字前置及不能代簽的崗位條件。失敗返回拒絕、衝突或缺條件；不能僅因為 runtime 收到 `resume=true` 就放行。

### 先提交業務事實，再可靠恢復

一期正式設計在同一應用 PostgreSQL 事務中完成：

1. 以冪等鍵和預期對象版本查重/比較；重複返回已提交同一業務結果，舊版本不覆蓋新意見。
2. 保存新的業務狀態/意見/文書或簽字，以及 F001 約定的對應責任記錄；必要記錄失敗則整次不能顯示完整成功。
3. 保存包含 decision_id、task_version、目標 workflow thread 的待投遞事件，然後提交。
4. 提交後由受限執行器讀取事件，重新核對當前允許條件，將已保存 decision_id 交給圖恢復；圖從業務庫讀取決定，而非接受任意客戶端給的“批准”內容。

checkpoint 與業務庫可能是兩個物理存儲，不能把步驟 4 當成事務的一部分。業務已提交但恢復前進程崩潰時，重啟消費同一待投遞事件；處理結果與投遞可重複識別。若圖已前進而投遞標記尚未保存，重複事件按 decision_id/task_version 檢查後不再執行業務寫入。亂序或舊版本事件拒絕/隔離，保留診斷，不強制回滾新業務狀態。

這保證設計目標是同一有效業務結果不重複，不聲稱底層消息/工具全局 exactly-once。若未來審計改成獨立遠程存儲，須先重新設計其一致性和失敗約定，不能直接沿用“同事務”結論。

### 恢復不是重新簽字

interrupt 所在節點恢復可能重跑，因此等待節點不包含非冪等的派單、寫意見或簽字。它只讀取當前業務狀態、核對已提交決定並等待下一合法輸入。業務提交放入上面的命令處理器，不能依賴“放在 interrupt 後面”保證只執行一次。

接口取消、瀏覽器退出和圖執行中斷均不清除業務待辦。責任醫生/複核人重新進入仍從應用狀態源讀到待處理事項；會話失效後重新認證，不能憑舊 resume token 繼續執行敏感動作。

## TP-12 · 工具、會話、事件與驗證合同

### 工具與角色

模型可以請求讀取被授權的上下文/知識或輸出候選，但不能調用任意 SQL、shell、改原庫、發佈規則、改派、裁決或簽字。F004/F005 提供範圍受控的業務接口，F006 產生候選，F007 授權命令產生人類責任事實。工具 Schema、註解和角色 prompt 都不能替代服務端權限。

人工界面顯示業務動作/待辦及其結果，運行事件顯示計算進度；SSE 必須用允許字段/對象範圍生成投影，不能直接轉發圖全狀態或把 private channel 當脫敏保證；禁止只因 Agent SUCCESS 或流結束就變更任務為已完成。工作臺的列表、詳情和統計繼續消費同一已保存結果，回到原篩選時按新狀態定位。

### 語義工具允許集

運行 Agent 僅消費 F004/F005 的只讀固定版本操作；不得把 MCP 發現的所有工具直接掛給模型。configure/save/publish/accept/evolve 等建設寫工具只屬於獲授權的離線建設角色。實際 MCP 缺失、Schema 不兼容或未提供必要版本/權限保證時如實限制，不能擅造參數或用 active 代替凍結版本。

### 事件與必要留痕

事件至少關聯 business_task_id、request_id、run/attempt、thread/checkpoint、graph/config 版本、actor/operation（適用時）、輸入/輸出證據引用、狀態/覆蓋/錯誤與提交結果。普通診斷不輸出不必要病歷全文、憑據、模型私有推理或整段聊天曆史。

局部寫入、業務動作、模型調用和後臺通知分開記錄。通知已發不等於工作已處理，運行中斷不等於業務撤銷，模型返回文本不等於證據支持。

生產保留/加密/併發、具名身份與簽署方式沿 PRD OQ-006。不得給所有應用用戶共享一個帶自動記憶的 Agent profile，也不得讓病例事實從一個會話的摘要變成另一個會話的隱含輸入。

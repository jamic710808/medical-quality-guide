承接[技術決定 KD-08～10](../knowledge-retrieval.md)，主責 F006，消費 F004 上下文與 F005 適用規則/知識。系統輸出輔助候選；專業確認、爭議和責任簽字由 F007/F008 及崗位責任人承擔。

## TP-07 · 固定規則任務與執行依賴

啟動時固定病例/就診、文書、F003 解析、F004 語義、規則/知識、索引、模型/提示/配置及檢查範圍，逐項判斷輸入和用途條件。以內部 rule_id → handler/required_inputs 的註冊表驅動，不讓模型動態創造規則、調用 SQL 或無限找證據。

| 原有候選規則 | 一期實現路徑 | 缺條件時 |
| --- | --- | --- |
| MQC-DOC-001 文書/必要段落 | 已約定清單 + 當前版本文書/段落集合對照 | 未配置清單或覆蓋不完整 → 無法判斷；不能從檢索無命中認定缺失 |
| MQC-DOC-002 身份一致性 | F004 命名空間、原標識和關聯依據的確定性核對 | 衝突/未關聯 → 阻斷相關拼接，不自動合併 |
| MQC-DOC-003 時間線 | 可比較時間的確定性順序檢查；語義解釋僅候選 | 相對時間、偏移、時區不足 → 保留不確定，不能恢復真實日期 |
| MQC-DOC-004 檢查來源 | 已提及檢查關聯到 F004 事件及 F003 可回放證據 | 缺回鏈 → 當前材料證據缺口，不判臨床未做 |
| MQC-DOC-005 過敏跨段衝突 | 限定同病例片段 + 檢索上下文 + 語義矛盾候選 | 證據不足/否定語境不明 → 待人工；不決定真實過敏狀態 |
| MQC-DOC-006 診斷描述差異 | 原文與時間語境並列，模型只提出需要解釋的差異 | 演變/鑑別/術語差異不明 → 不做自動診斷 |
| MQC-DOC-007 用藥文本要素 | 約定字段的缺失/單位核對；跨段描述比較為候選 | 不補值、不判斷處方合理性、不生成治療指令 |
| MQC-DOC-008 作者/簽署/版本 | F004 文書元數據與約定責任字段核對 | 條件缺失/身份未驗 → 受影響範圍阻斷，不生成簽字 |

上表只實現既有[業務約定](../../01_normalize-project-requirements/業務約定/AGR-MED-001-業務約定.md#agr-med-001-02)，未新增規則、批准或醫學閾值。98 項上游規則不自動變成本項目執行包；候選包只用於允許的離線驗證，生產選擇按 F005 資格判斷。

每個確定性處理器返回“條件成立 / 條件不成立 / 無法判斷”及輸入證據/範圍；臨床合格、人工確認與機器條件結果不能互相替代。部分處理器完成時保留檢查覆蓋與未執行項。

## TP-08 · 域內模型與結構化候選

離線驗證指定 `Qwen/Qwen3-4B-GGUF` 的 `Q4_K_M` 配置，由 llama.cpp 提供域內推理。它是資源受限環境中的待驗證實現選擇，不是醫療專用模型或已驗證準確率最高方案。下載時固定 revision/文件摘要、許可、模型與運行時版本；本輪未下載。

經本次研究複核，其資格明確限定為工程聯調/故障基線。真實語義項是否啟用，須由代表性中文資料、獨立評測和專業負責人判斷，不能因為框架跑通就默認該模型可臨床使用。主體/否定/時間/條件和完整性證據包見 [TP-15](platform-and-clinical-contracts.md#tp-15)，分層比較見 TP-16。

顯式綁定迴環地址；使用實際已下載文件，業務請求期間不隱式訪問模型倉庫或外部推理端點。部署到內網不自動擴大處理域，仍需當前域/身份配置。採樣、上下文/輸出上限、超時和模式固定進運行配置；先驗證模型輸入/輸出邊界，不承諾某一配置可在本機同時加載全部模型。

輸入只包含明確規則任務、允許的 CaseContext、適用依據及候選 evidence_refs。將病例正文和檢索文本作為數據，不能執行其中的提示指令；模型沒有改庫、簽字、發佈規則或任意工具調用權限。

輸出採用 JSON 結構約束並再次由應用校驗，表達 rule_id/version、candidate_type、reason、suggestion、引用 ID、無法判斷原因及產生環節。模型不得自填人工確認嚴重度、專家意見或簽字；沒有證據支撐的必需信息寫缺失原因。

結構合法只表示格式符合，不證明語義正確。應用逐項檢查：引用屬於此次允許輸入、版本未漂移、locator 可回放、所引文字實際支持對應主張、否定/時間/例外條件未遺漏。語義支持暫時不能可靠自動判斷時保留待人工核對，不以字符串包含當專業證明。

首版每個需要語義判斷的檢查只執行一次有界調用；格式失敗或超時返回無法判斷，可由用戶修復條件後發起新嘗試，不用循環模型自評“修到通過”。更換模型、量化或提示版本均形成新運行配置並重驗受影響規則。

模型未運行時，已完成的確定性檢查可以顯示其局部結果，但語義檢查保持未運行/無法判斷；不能將空模型響應當無問題。相似度、模型自報分數均不作為校準風險概率。

## TP-09 · 分層證據、失敗關閉與重核

### 結果與消費

問題候選包含穩定身份、規則/知識/病例/文書版本、類型、建議嚴重度、reason/suggestion、evidence_refs、產生環節、覆蓋/限制和阻斷原因。人工確認值與專家結論只由後續具權限崗位寫入；F006 不偽造責任事件。

分開存儲來源事實、確定性規則結果、模型候選與後續專家結論。檢索命中、SQL 計算、圖/語義映射和模型推斷都有各自過程與源引用；既有 EvidenceItem 不因派生解釋而被覆蓋。

供 F007/F008 的輸出契約返回檢查集合、問題集合、未判斷集合、阻斷範圍及恢復前提；供 F004 的工作臺投影來自同一已保存結果，不另算一套風險/狀態。人工流程仍可在授權範圍查看材料並處理，不把“自動推進被阻斷”做成資料全不可見。

### 失敗與恢復

| 觸發 | 本模塊結果 | 恢復條件 |
| --- | --- | --- |
| 證據缺口、引用失效、輸入未覆蓋 | 受影響檢查無法判斷或阻斷，記錄範圍 | 補充同版本有效證據或由 F002/F003 登記新版本後重核 |
| 身份衝突、範圍外、規則資格衝突 | 不執行依賴該前提的判斷 | F004/F005 修正依據或明確處理用途 |
| 向量/模型不可用 | 聲明實際執行模式、保留局部結果，不能全局通過 | 修復選定域內服務後新嘗試；不自動外發 |
| 模型引用不存在、內容不支持、結構不合法 | 不發佈為有依據的問題，保留無法判斷原因 | 修復輸入/適配或人工複核，不編造來源 |
| 規則/模型分歧或未校準信號 | 並列保留產生環節，禁止以模型高分覆蓋 | F007/F008 專業處理與明確依據 |
| 版本變化或重複請求 | 同請求複用有效結果；變化生成新鏈 | 固定變化後的輸入/配置，保留舊版本與歷史 |

受影響範圍由顯式輸入依賴確定，不能只重跑先前報錯項而漏掉依賴變化的新問題。若不能可靠判斷影響，重核本次聲明的完整範圍並報告原因。舊通過結論和簽字不繼承到新版本；實際簽字准入由 F007 消費阻斷結果並獨立執行。

冪等鍵至少覆蓋請求範圍與所有影響判斷的版本。先持久化完整運行結果再給消費者成功反饋；失敗/中斷保留嘗試記錄，臨時結果不冒充已發佈。保留/刪除受產品責任與留存條件約束，不以清緩存刪除歷史意見。

### 驗證

採用有獨立預期的合成邊界樣本與經允許的業務樣本分別檢查：8 條規則的必要輸入、範圍外/缺證據、跨段否定與時間語境、版本更替、檢索/模型故障、假引用、重複提交和新文書重核。模型候選的專業對錯由相應專家流程驗收；本輪只設計用例，沒有產生實測分數或專業簽字。

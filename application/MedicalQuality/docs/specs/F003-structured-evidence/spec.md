# F003 · 結構解析與統一證據輸出規格

## 目標與可觀察結果

讓質控人員和醫生能夠從後續問題回到同版本病歷原文，讓信息科知道一批資料實際處理到哪裡，讓醫療上下文與規則模塊按同一證據接口消費不同來源，而不因格式轉換改變原值、丟失位置或掩蓋失敗。

本 Feature 交付有來源、位置、原生結構及覆蓋說明的證據集合。它是內部能力，可用授權輸入及下游調用驗證，無需為解析工具新增獨立產品頁面。`ready` 表示局部業務規格已明確；[Plan](plan.md)仍為 draft，未獲得實現就緒或運行通過狀態。

| 業務痛點與既有來源 | F003 的處理結果 | 驗收落點 |
| --- | --- | --- |
| 字段、段落和檢查資料分散，轉換後編號、單位和空值含義改變；S01-04、REQ-002、NFR-002 | 按原格式保留結構與原值，規範化值另存 | AC-F003-002、AC-F003-003、AC-F003-006 |
| 只有“存在問題”，醫生無法核查是哪一段、哪一版；S01-08、PSC-005 | 輸出可重放的證據定位；頁級與片段級精度明確 | AC-F003-004、AC-F003-007 |
| 未解析或缺失的資料被當作“未發現問題”；S01-09、REQ-008 | 已處理、部分、失敗、阻斷和未覆蓋分別記錄，供下游停止相應推進 | AC-F003-008、AC-F003-009 |
| 公開病例、參考答案、規則和生產證據混用；S01-03、PSC-001 | 保留來源性質和用途；建模證據與評測參照分開 | AC-F003-010、AC-F003-011 |
| 工具故障後外發病歷或日誌殘留全文；S01-05、AC-026 | 消費既有授權域，拒絕未經授權的路徑，錯誤反饋只含必要診斷信息 | AC-F003-001、AC-F003-012 |

S01-xx 的原始出處與含義見 [PRD 來源登記](../../PRD.md#source-register)；本規格不新增醫學規則、效果指標或客戶驗收事實。

## 來源與範圍

- 來源需求：REQ-002、REQ-008、NFR-001、NFR-002、NFR-003、NFR-005。
- 來源總規格：PSC-001、PSC-002、PSC-005、PSC-008。
- 對應 PRD 驗收：主責 AC-002 / AC-003；承接 AC-008 / AC-009 / AC-026 的證據與受限解析條件，最終結論與放行由主責 Feature 組合驗證。
- 本 Feature 包含：數據庫結構/記錄、CSV、JSON/JSONL（含現有壓縮載體）、Markdown、文本/掃描/混合 PDF 的讀取、統一、定位與覆蓋；對現有 XML、XLSX、圖像、心電資料聲明實際可用的原生讀取或附件能力；失敗恢復與建模交接。
- 本 Feature 不包含：F002 的來源登記與身份授權決策；F004 的患者合併、醫療實體/關係建模和工作臺；F005 的規則適用性批准；F006 的質控推斷；F007 的整改/簽字；全量影像或波形醫學解釋、HIS 回寫、通用文件解析平臺。

核心格式與附件能力沿用 PSC-002 第 8 節：現有數據的最佳讀取建議不等於本期承諾對所有子類型完成全文或數值解析。XML/XLSX 的受限適配須註明實際覆蓋；不支持時保留來源引用與缺口，不影響其他格式返回可用部分。

## 輸入輸出與迭代邊界

- 輸入與前置條件：F002 已登記的來源與版本、原件/結構目錄、具體讀取範圍、來源角色、用途與有效授權；F001 的拒絕結果經 F002 傳遞後仍須執行。單獨驗證可以使用明確標記的測試輸入，但不能作為生產授權。
- 輸出、必要語義與消費方：證據集合及原生引用、運行身份與實際變換、處理範圍與分母、失敗/未讀/定位缺失清單、允許消費範圍和回查說明。F004 組織病例語義，F005 治理知識依據，F006/F008 消費缺口和追溯信息。
- 可單獨優化的內部職責：各類讀取器、採樣與解析路由、內部批次切分和資源使用，只要原值、身份、定位及狀態語義不變。
- 需要協調上下游的變化：來源版本、定位語義、內容分型、對象 Schema 版本、質量/可用範圍與用途標識變化；新版本不能靜默取代舊結果。

| F004 | 獲取原值、段落/字段位置、明確的關聯線索和缺口 | 由 F004 決定病例/就診/事件關係，不用相似內容直接合並 |

| F006 / F008 | 獲取固定輸入版本與覆蓋、不確定性及可回查證據 | 下游負責質控推進和專業評測，F003 不輸出“病歷合格” |

## 功能行為

### 主流程

1. 接收登記對象與本次用途，核對源版本、範圍及授權；字段缺失、版本改變或不允許讀取時先阻斷受影響範圍。
2. 按真實特性分流。結構化內容保留原結構；PDF 區分數字文字、掃描和混合；醫學圖像與波形先作為原生資產，不能一律轉 OCR。
3. 記錄原文/原值、結構和位置。保留已有 doc_id、origin、text_sha256 等源字段；片段身份與整份文檔身份分開，重複文本不自動去重為同一病例。
4. 輸出共同證據語義及原生結果引用。大數據使用明確範圍的引用，不要求把整個數據庫或像素/波形塞入一個對象。
5. 核對結構、原值與位置，歸集全部輸入單元的覆蓋結果；不可定位內容限制消費，部分可用範圍必須明確。
6. 按來源角色交接證據、結構/字典、規則/術語參考及讀取說明，保留失敗、未知和未關聯事項，結束解析階段。

### 業務規則與邊界

- 數據庫未聲明的主外鍵關係保留未知；無可靠鍵的記錄只能聲明同一快照/讀取範圍內的定位。跨數據集相同編號不產生患者等同結論。
- CSV 使用邏輯記錄號；JSON 保留對象路徑和數組位置；Markdown 保留原文行/段；PDF 框位置有頁、座標語義和實際精度。清洗後偏移不能冒充原文偏移。
- 標籤、公式、單元格跨度、圖文關聯和通道單位在實際支持的範圍內保留；未讀、未解碼或能力不足明確說明，不補造信息。
- 解析過程與醫學判斷分層。源規則和 XML 報告只是有來源的文字/結構；系統不把它們提升為本項目專家結論。
- 運行級覆蓋和對象級質量分別表達：多個可用對象不代表所在批次全部成功；未知總數不能展示虛構百分比。
- 成功僅指聲明的讀取範圍。只取得圖像/波形元數據時明示，不能用於宣稱已完成診斷或全部信號解碼。
- 參考標註、驗證、留出輸入不進入知識建設集合；允許消費標記也不授予新權限。
- 重複請求不重複產生同一有效結果；換來源或解析配置形成可識別新版本，舊引用保持可查，不覆蓋已有歷史證據。

## 異常與恢復

| 情況 | 使用者/消費方可觀察狀態 | 系統行為 | 恢復/重試 |
| --- | --- | --- | --- |
| 聲明範圍確實為空 | 完成，覆蓋為零且無證據 | 保留空結果；不得等同“無質控問題” | 輸入範圍變化後另行發起 |
| 暫時讀不到範圍 / 總數未知 | 失敗或部分成功，總數未知 | 不把未知當零，不生成假百分比 | 修復讀取條件後處理未完成部分 |
| 授權失效 / 域不允許 | 阻斷 | 拒絕受影響讀取與回查，不換外部服務 | 上游提供有效授權後重試 |
| 來源內容與登記版本不符 | 阻斷並說明版本差異 | 不把新內容套進舊證據 ID | F002 登記新版本後重新處理 |
| 加密、損壞、依賴缺失、不支持子類型 | 明確失敗/不支持原因及影響範圍 | 保留其他成功項與原始引用 | 已允許路線具備能力後重試；不自動宣稱附件全文解析 |
| 字符可讀但無法準確定位 | 部分成功、定位缺失或精度不足 | 保留內容和實際位置，限制要求精確證據的消費 | 校正位置或補充來源後重核 |
| 進程中斷 / 寫出失敗 | 未提交或失敗 | 臨時不完整產物不暴露給消費者 | 恢復檢查點，複用已提交且版本一致的分片 |
| 下游不識別新契約版本 | 明確不兼容 | 停止相應消費，不丟字段降成舊對象 | 對齊適配版本後再交接 |

## 驗收標準

使用範圍明確、獲准的真實樣本及專門構造的解析夾具分別驗證，後者顯式標記合成。F003 的通過只證明解析與交接貢獻；PG-001 / PG-003 的跨 Feature 結果見產品級用例。

### AC-F003-001 · 固定授權輸入與來源版本

- 來源：REQ-002, REQ-008, NFR-001, NFR-002, PSC-001, PSC-008
- 對應 PRD 驗收：AC-002, AC-026
- Given F002 提供同一文件的登記版本、讀取範圍和有效或失效授權，另有內容已變化的副本。
- When 發起解析或回查請求。
- Then 只處理授權與版本一致的範圍；其他請求明確阻斷且未產生可用證據，源文件不被改寫。

### AC-F003-002 · 結構化記錄保留原值與類型

- 來源：REQ-002, NFR-002, PSC-001, PSC-002
- 對應 PRD 驗收：AC-002
- Given 數據庫結構/記錄、CSV 和嵌套 JSON/JSONL.GZ，含前導零、長標識、精確小數、空白/null/缺失、引號內換行與無主鍵記錄。
- When 讀取聲明的邏輯記錄範圍。
- Then 結構與記錄分別可查，原值、層級與數組位置不變；定位可回放；缺鍵保持快照範圍身份，未聲明的關係不被推定。

### AC-F003-003 · 說明文檔與原生資料不被錯誤展平

- 來源：REQ-002, NFR-002, PSC-001, PSC-002
- 對應 PRD 驗收：AC-002
- Given 含標題、嵌套列表、代碼和表格的 Markdown，以及當前 XML 報告和 XLSX 術語表。
- When 執行已經聲明支持的讀取路線。
- Then Markdown 保留結構及原文位置；XML/XLSX 在聲明範圍內保留標籤、單元格及原生引用，未支持部分作為附件/缺口呈現，不能報告全文或全工作簿解析成功。

### AC-F003-004 · 文本與掃描 PDF 的結構和位置可檢查

- 來源：REQ-002, NFR-002, PSC-001, PSC-002
- 對應 PRD 驗收：AC-002
- Given 文本、掃描、混合頁與跨頁表格的代表 PDF，以及聲明的頁範圍。
- When 執行相應解析並查看重要條款和表格。
- Then 閱讀順序、表格關係和實際來源頁可核對；框有座標語義，未定位部分明確限制，未覆蓋頁不能顯示完成，原生結構仍可回查。

### AC-F003-005 · 影像和心電按實際資產能力交付

- 來源：REQ-002, NFR-002, NFR-003, PSC-001, PSC-002
- 對應 PRD 驗收：AC-002, AC-003
- Given 一張 PNG、圖文索引及一組 WFDB 頭/信號，另有缺失配對或讀頭受限的記錄。
- When 執行附件與元數據路線。
- Then 保留原資產、關聯出處和實際讀到的元數據；未解碼、缺配對或部分通道範圍明確標註，不把胸片送入文檔 OCR、不生成影像/心電診斷。

### AC-F003-006 · 統一接口與穩定證據身份

- 來源：REQ-002, NFR-002, NFR-005, PSC-001, PSC-002
- 對應 PRD 驗收：AC-002
- Given 多類內容、重複文本但不同源記錄、同一來源的兩個版本及大表引用。
- When 形成統一輸出並由測試消費者枚舉。
- Then 身份、內容分型、來源版本、定位、原值/引用、解析過程和質量齊全；同一有效輸出身份穩定，不同來源/版本不會誤合併，原生結構不會因共同封裝丟失。

### AC-F003-007 · 原文定位重放與失效反饋

- 來源：REQ-002, REQ-008, NFR-002, NFR-003, PSC-001, PSC-005
- 對應 PRD 驗收：AC-002, AC-008, AC-009
- Given 可定位的字段/記錄/文檔片段、僅頁級位置、錯誤偏移及過期來源引用。
- When 消費方請求同版本原文。
- Then 實際內容能支持對應片段；位置精度如實表達，錯誤/失效引用不給假成功或偽造偏移，並提供受影響對象與恢復原因。

### AC-F003-008 · 完整覆蓋與失敗範圍可見

- 來源：REQ-002, REQ-008, NFR-003, PSC-002, PSC-005
- 對應 PRD 驗收：AC-003, AC-009
- Given 同批含可用、損壞、未定位、未支持單元，以及空範圍和無法得知總數的輸入。
- When 彙總解析結果。
- Then 保留聲明分母與全部覆蓋分類；可用部分單獨消費，部分/失敗/阻斷不冒充完整成功，空與未知不同，也不產生臨床通過結論。

### AC-F003-009 · 重試、變更與中斷不覆蓋歷史

- 來源：REQ-002, REQ-008, NFR-005, NFR-003, PSC-001, PSC-002
- 對應 PRD 驗收：AC-003
- Given 部分已提交的運行被中斷、同一請求重複提交，以及來源或解析配置後續變化。
- When 恢復或重試受影響範圍。
- Then 未變的有效輸出不重複創建；臨時不完整結果不能消費，變更產生新的可識別運行/證據版本，舊結果與失敗歷史可查。

### AC-F003-010 · 來源、參照與醫學結論分層

- 來源：REQ-002, REQ-008, NFR-002, NFR-003, PSC-001, PSC-005
- 對應 PRD 驗收：AC-002, AC-008, AC-009
- Given 來源清單同時登記業務原文、規則、術語及獨立參考標註/驗證/留出範圍。
- When 形成知識建設交接集合。
- Then 保留各自來源性質和用途；普通建模讀取不探讀標註/留出正文，參考/規則不被提升為患者事實、有效規則或專家結論。

### AC-F003-011 · 下游獲得可檢查的建模輸入

- 來源：REQ-002, REQ-008, NFR-002, NFR-003, PSC-001, PSC-002, PSC-005
- 對應 PRD 驗收：AC-002, AC-003, AC-008
- Given 有可用證據、部分覆蓋、原生附件與失敗清單的一個固定運行，以及不兼容的契約版本。
- When F004/F005 的消費合同檢查交接結果。
- Then 能分別取得結構/字典、業務證據、規則/術語參考、允許範圍及回查方式；不能解釋的版本停止消費，交接不自動創建患者關係或本體。

### AC-F003-012 · 故障恢復仍遵守數據域

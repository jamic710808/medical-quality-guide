用戶 U10 已授權持續開發。本 Feature 的軟件已落地：原生格式讀取、EvidenceItem 1.0、真實 OCR、原值/定位回放、覆蓋/錯誤、原子結果提交與柵欄恢復。 實際文件為 `backend/medical_quality/evidence.py`、`backend/medical_quality/replay.py`、`backend/medical_quality/worker.py`。為保持模塊化單體簡單，下文最初規劃的多個職責文件合併在這些模塊中；它們不是另有待創建的第二實現。Spec 的業務語義不變。工程前置已有實測，Plan ready 不等於專業或完整驗收通過。逐用例結果與剩餘組合見[當前實現記錄](../../verification/F003-implementation.md)。當前 PDF 實測為六頁規範和一頁純掃描合成夾具；複雜跨頁/旋轉/低質量掃描沒有專業驗收。

## 現有上下文與複用

本計劃把[業務規格](spec.md)變成實施順序，主責解決“讀取時不丟結構、複核時能回查、失敗時不假成功、建模時不混入答案”。完整調研依據沿用[多源數據工作流](../../data-preparation/workflow.md)，不在這裡重複維護另一份工具排行榜。

- 當前實現與入口：`backend/` 為空；`frontend/` 只有品牌資源；可點擊原型是 `docs/04_frontend-prototype/` 的獨立靜態實現，沒有真實資料接入、解析運行或授權服務。不得把原型會話狀態當解析存儲。

- 必須保持的現有行為：原始文件與許可不變；病例 doc_id / origin / text_sha256 等源字段不重寫；兩個索引的路徑基準分別保留；不同來源與任務即使文本相同也不自動合併；原型和需求看板可繼續獨立使用。

計劃已展開到路徑、接口草案、階段、任務和驗收映射；狀態仍為 draft，原因是已選掃描 PDF 路線的精確依賴/模型、效果/資源和上游實際交接仍未驗證。下表 OQ 給出明確解決步驟；不以文檔寫完替代工具實測。當前只寫計劃與用例，沒有安裝環境或執行開發任務。

## 實現方案

### 1. F002 輸入與下游輸出

內部接口先用數據對象與合同測試固定，不預定 HTTP 路徑或引入外部 API/SDK。字段名是實現草案，需在 T001 與 F002 核對，業務含義以 PSC 為準。

| 邊界 | 必需內容 | F003 的責任與拒絕條件 |
| --- | --- | --- |
| F002 → 解析請求 | 登記 source_id、可訪問來源引用、內容/快照版本、格式及結構目錄、讀取範圍、data_role / data_kind、許可/用途、路徑基準、有效授權決定引用 | 缺少版本、範圍或有效授權則阻斷；不在 F003 自籤授權，不憑文件可讀認定獲准 |
| 解析請求 → 運行 | request_id、本次範圍、讀取器/模型/配置版本、合同版本、必要資源限制 | 分開邏輯請求與執行嘗試；同請求不同版本/配置不得複用舊結果；運行中授權失效停止受影響範圍 |
| 運行 → 結果清單 | source/version、run/attempt、實際範圍、按格式的統計單位、已發佈分片、未讀/失敗/阻斷及可用範圍 | 只登記已核對提交的分片；未知總數用未知，保持聲明分母，不輸出偽造百分比 |
| F003 → F004/F005 | EvidenceItem、結構字典、原生引用、限制/缺口、回查方式和合同版本 | 提供語義輸入，保留身份命名空間；下游不支持版本時停止消費，不做靜默降格 |

F002 未實現時僅用受控夾具檢驗 F003 的接口行為；最終接入時仍須通過真實授權/來源路徑。F004/F005 的消費者替身只檢查封裝、可用範圍和引用，不能驗證病例建模或規則批准。

### 2. 按實際特性選擇讀取器

| 分支 | 計劃實現與選擇理由 | 輸出與侷限 |
| --- | --- | --- |
| SQLite | 標準庫只讀連接，消費已登記表/列/鍵；按明確查詢範圍流式讀取，不引入同步平臺 | 結構與記錄分開；保留 TEXT 原值及內部記錄號；無可靠鍵時記錄快照內查詢順序/序號，不製造跨版本主鍵 |
| CSV / JSON / JSONL.GZ | 標準庫逐邏輯記錄讀取；保持字符串標識、嵌套和數組；數字精度採用無損策略，原字面值可回查 | CSV 的表頭與邏輯記錄口徑明確；GZ 綁定壓縮文件版本和解壓後記錄位置，限制採樣與單條大小，不全量解壓另存 |
| Markdown | markdown-it-py 的 Token/樹與原文並存；額外保留行範圍和必要字符映射 | 標題、列表、代碼/表格不能只靠正則；插件/擴展支持範圍寫入配置；無法精確映射的內聯內容降低定位精度 |
| XML / XLSX | 現有 eCitation 用安全 XML 讀取；術語表用 openpyxl，顯式處理原字段/屬性、工作表與單元格 | 只聲明已驗證的原生結構能力。禁止外部實體/網絡讀取；公式/緩存分別保留，未支持結構標缺口，原文不扁平替換 |
| PDF | 數字頁 pypdf/pdfplumber 原生讀取；掃描/混合主選 Docling standard＋RapidOCR ONNX，顯式固定 PP-OCRv4 中英模型；中文複雜結構備選本地 PP-StructureV3，見[定案](../../data-preparation/governance-cleaning-handoff.md#pdf-scan-decision) | 六頁規範已完成全頁文字/版式初查，不能替代掃描效果。T002 鎖定依賴/模型並驗證，T006 適配原生結構/頁框/覆蓋；關鍵錯誤受限，不自動換雲端或默認 MinerU |
| PNG | Pillow 獲取元數據與按聲明範圍的解碼檢查，源圖保持原字節，消費圖文索引 | 只表示資產可用性、尺寸/位深/色彩與關聯；不調用診斷/OCR 模型解釋胸片 |
| WFDB | 採用 WFDB 讀頭接口和索引核對原生資產，保留 HEA/DAT、通道、採樣率、單位與校準信息 | 本期默認元數據/附件，明確 values_decoded=false；缺失配對/通道描述標部分；信號數值解碼待真實消費需求另行展開 |

真實解析樣本從允許的業務資料選取；參考標註與留出正文不用於路線調試。需要掃描等目前未確認存在的格式場景時，構造不含真實患者數據的小夾具，並標合成，不把它當作臨床效果證據。

### 3. EvidenceItem 與存儲

以[通用契約](../../../../.agents/skills/prepare-business-data/references/evidence-contract.md)及其 Schema 為基線，在 T003 明確映射：

- `source`：沿用 F002 來源/版本/角色/用途；原 doc_id 等業務字段保留在內容和映射中。`id` 表示證據身份，不能替代患者身份。
- `kind / content`：結構、記錄、表格、文本、圖像、波形分開；小對象用 JSONL，大內容用 payload_ref。需要類型化大表時才引入 Arrow/Parquet，不預建第二套原庫。
- `locator / native_refs`：共同定位加原生結構。表格跨度或解析器特有字段不塞不進就丟棄；精確位置不存在時返回實際粒度或 unavailable。
- `provenance`：保留讀取器、包/模型、配置摘要與變換；同輸入/配置重試的對象身份穩定，真正改變內容、版本或定位時顯式產生新身份/版本。
- `quality`：單項成功/部分/失敗/阻斷、問題和可用範圍；建模訪問分 allowed / evaluator_only / restricted。元數據讀取成功也必須記錄其有限範圍。

生產包不從 `.agents/skills/` 動態 import。通用 Skill 基線與產品合同的關係記錄在產品 `contracts/` 說明中：經核對後固定產品版本，後續 Skill 更新不會自動改變產品輸出。當前尚未創建運行時合同副本。

### 4. 覆蓋、提交與恢復

單次運行的 manifest 記錄聲明範圍及計數單位。文件數、頁數、邏輯記錄數、通道/樣本範圍分別統計，不相加成“病例數”。父對象可標部分成功；分片清單中各最小處理單元的成功/失敗/阻斷/未讀範圍互不重複，並保留未知總數或截斷原因。

採用局部架構已確定的單寫入者文件流程：先寫臨時分片，完成結構與範圍核對，再登記提交結果；下游只消費 manifest 引用的已提交分片。中斷殘留可清理/重算，已經發布的證據不可原地改成另一版本。相同請求重複進入時返回或接續既有結果；來源/工具/配置改變形成新運行，不覆蓋舊失敗記錄。

恢復前重新核對來源版本和授權。只重試失敗或受影響單元；同輸入、配置未變的成功項複用。該策略用於本地驗證，不提前宣稱滿足生產多進程事務或高併發服務要求。

### 5. 位置回放與知識建模交接

位置回放必須讀取同一來源版本並核對原值/原文，不能只驗證路徑字符串或 Schema。回放組件分別處理數據庫鍵/快照查詢、CSV 邏輯記錄、JSON Pointer、XML XPath、Markdown 行/字符、PDF 頁/框、單元格、圖像幀和波形資產/區間；只有實際啟用的分支對其解析精度負責。

向 F004/F005 交接一份 handoff：固定來源與運行、Schema 版本、可用範圍、結構字典、證據分片與原生引用、讀取方法、失敗/受限清單、未解語義。業務證據、規則/術語參考和評測參照分別列出。建模集合不得包含 reference_label / validation / heldout 的正文；清單可登記這些邊界的存在，不讀取其內容建模。

F003 不從 EvidenceItem 自動生成患者/就診關係，不把規則 PDF 的讀取成功當規則生效，也不創建本體配置。F004/F005 實現後再驗證真實消費路徑；首次僅以合同消費者檢驗交接完整性。

下游已按[知識檢索技術決定](../../architecture/knowledge-retrieval.md)展開：F004 以 TP-01/02 消費身份、原值、位置和覆蓋；F005 以 TP-03～06 消費規則知識版本、分塊原文和來源角色。F003 T012 的交接檢查需對齊這些實際消費者合同，但不承擔索引、模型或醫療語義實施。

## 實施順序

治理細節採用[數據治理與交接專題](../../data-preparation/governance-cleaning-handoff.md#cleaning)，落實到既有任務：T003/T004/T005 保留原值與確定性變換；T008 處理清洗後的文字/座標回映射；T009/T010 保存質量、覆蓋和未提交分片狀態；T011/T012 區分角色、當前允許範圍及 SQL/RAG/本體交接。變換/質量記錄作為運行附屬對象或關聯表，不修改 EvidenceItem 1.0 頂層；F003 不負責專業缺失解釋、患者合併或模型補值。接口細節在既有 T001/T003/T012 固定，任務與用例執行狀態不變。

1. **技術收斂（T001～T002）**：凍結 F002 交接草案與樣本範圍，驗證 Python 環境、已選 PDF 主線與資源條件，僅有明確主線缺口時對照備選。先解決 Plan OQ，再將實施版本的 Plan 標 ready；本輪不執行這兩項技術驗證。
2. **共同合同與原生路徑（T003～T005）**：固定 EvidenceItem 與運行封裝，接入結構化記錄及文本/受限原生資料；先證明原值和結構，再接模型解析。
3. **文檔及資產分支（T006～T007）**：按 T002 選定方案實現 PDF，補齊影像與心電資產說明；各分支聲明能力與範圍。
4. **追溯、覆蓋與恢復（T008～T010）**：原位置重放，彙總完整分母，證明失敗恢復與同請求冪等，避免“成功生成文件”等於業務成功。
5. **角色隔離與交接（T011～T012）**：執行來源角色、授權域和錯誤最小化約束；交付可檢查的建模輸入。
6. **本 Feature 驗收（T013）**：綁定實際檢查並執行本次必要驗收，已有未變的有效結果直接引用。F001/F002/F004 及相關 F005 能力具備後另行執行 product 套件；這些組合驗證不作為 F003 依賴 F004 才能建設的循環前置。

## 回退策略

讀取器失敗時保留原件、已提交有效分片、配置與最小失敗清單，停止受影響範圍；只改用已經允許且核驗能力的路線。新讀取器/Schema 若改變結果，保留舊版本供歷史回查，當前版本消費者不兼容則明確拒絕，不靜默退成純文本。

中斷後臨時文件不當正式證據，按相同來源/配置恢復或重算；清理派生產物前確認來源版本仍可訪問且無下游引用。禁止清空原始 Data、重寫數據庫、全工作區回滾或默認將失敗資料傳給在線服務。產品原型與需求 Playground 不在本 Feature 修改範圍。

### 實際發佈粒度

本地一期以最多 500 條邏輯記錄或限定 PDF 頁預算的一次讀取作為提交單元，一次事務發佈該範圍。多範圍由獨立 Job 接續，已提交 Job 保持並冪等複用；不在同一 Job 中提交半份結果。原設計的“分片”在當前實現指該有界單元。柵欄、審計失敗和重複請求檢查覆蓋此策略；無限流式調度不屬於當前有限數據工作流。

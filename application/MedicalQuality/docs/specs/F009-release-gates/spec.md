# F009 · 上線准入與責任接受規格

## 目標與可觀察結果

對固定版本、範圍和階段作出有責任證據的准入或阻斷決定，使離線驗證、限定影子運行和人確認輔助決策的能力邊界真正生效。高風險否決、缺參數和條件失效不能被演示完成、平均分或界面開關繞過。

本輪依據用戶“補齊全部方案、Feature 與評估”的授權，在原 Map 邊界內展開。Spec ready 表示業務行為已可據此規劃；Plan draft / Tasks planned 保留尚未取得的運行與專業證據，不宣稱功能已完成。

## 來源與範圍

- 來源需求：REQ-018, NFR-001, NFR-003, NFR-004, NFR-005, NFR-006。
- 來源總規格：PSC-001, PSC-008, PSC-009, PSC-011, PSC-013。
- 本 Feature 包含：准入申請/固定基線、組合條件檢查、高風險否決、關鍵人驗收與責任接受、階段/範圍啟用控制、條件失效停用/回退/重驗、版本併發及審計、可讀管理入口與交付基線。
- 本 Feature 不包含：不執行基礎設施實際部署，不批准超一期病區/病種/規則的產品範圍，不代 F008 專家評測或 F007 簽字；不把本體/模型技術發佈當生產放權。
- 產品含義以 [PRD](../../PRD.md)、[Product Spec](../product-spec.md)及 [Feature Map](../feature-map.md#f009) 為準；局部驗收貢獻與產品組合驗收分開。

## 輸入輸出與迭代邊界

- 輸入與前置條件：目標階段/範圍、固定 source/rule/knowledge/semantic/model/application 配置與驗證基線、F008 報告、F007 流程驗收/責任條件、F011 原生圖譜 PG-006 必需驗收證據、F001 授權和目標部署/留存/運維證據、真實關鍵崗位意見。
- 輸出、必要語義與消費方：GateDecision、必要條件逐項結果/缺項、批准或阻斷的精確能力範圍、ResponsibilityAcceptance、Stop/Rollback/RevalidationRecord；運行入口和 F010 消費同一版本。
- 可獨立調整：本模塊內部組織、查詢與呈現方式，前提是身份/版本、狀態、允許範圍和證據合同不變。
- 需協調上下游：共享對象/版本/錯誤、授權和責任事件變化同步生產者與消費者，不在局部把未判斷改為通過。原始資料與既有原型保持；正式行為由後端事實源提供。

## 功能行為

### 主流程

1. 離線能力與資料時，提交進入下一階段申請；固定範圍/版本及必需證據，結果為逐項准入理由，交給關鍵責任人。
2. 必要前置滿足時，實際崗位驗收/責任接受；身份/職責/範圍可查，結果為有範圍的階段能力，交給運行入口。
3. 已限定啟用時，範圍/配置/資格變化或高風險事件；標影響並限制自動推進，結果為人工路徑與歷史保留，交給重驗責任者。
4. 修復後申請時，提交新證據與當前版本；重新核對全部受影響條件，結果為新決定，不覆蓋舊批准，交給F010/運行控制。

### 業務規則與邊界

- 離線、影子和輔助的權限分別控制，影子結果不能驅動臨床執行、代寫病歷或責任簽字。
- 任何確認高風險漏報、未解決高風險爭議/無法判斷否決晉級；其他平均值不能抵消。
- 缺樣本/閾值/身份/數據域/有效規則/本體/責任接受/恢復證據時不默認通過。
- 批准綁定當前聲明範圍和版本，擴大範圍或變更影響適用性時重新評估，不能自動繼承。
- 運行條件失效先限制新消費/推進，再安排回退/重驗；已提交人工事實與原始材料保持可查。

狀態名稱沿用 PSC 與主責模塊的共同含義；登記/計算/交接完成只說明該環節，不自動錶示專業確認或生產放權。所需技術字段在 Plan 與共享實施合同落實，本文不預填醫學閾值/真實賬號。

## 異常與恢復

| 情況 | 可觀察結果/處理 | 恢復條件 |
| --- | --- | --- |
| 缺必要證據/參數 | 阻斷並列缺項與責任 | 補齊真實證據後重驗 |
| 高風險否決 | 拒絕晉級/擴大受影響範圍 | 修復、專業複核及新評測 |
| 申請過期/併發決定 | 衝突或既有結果 | 刷新當前基線後重新確認 |
| 已批准條件失效 | 暫停受影響自動能力 | 保留人工路徑和歷史，安排重驗 |
| 系統故障/審計失敗 | 不形成有效新放權 | 對賬/恢復後再請求 |

## 驗收標準

每項 AC 是本 Feature 的可觀察貢獻；固定夾具驗證機制，真實相鄰模塊與專業材料驗證端到端目標。未實現時用例 check_ref 保持 null。

### AC-F009-001 · 准入申請固定範圍與基線

- 來源：REQ-018, NFR-005, PSC-001, PSC-011
- 對應 PRD 驗收：AC-022, AC-024
- Given 請求從離線進入影子或從影子進入輔助，配置/模型/本體與規則版本可變化。
- When 創建或核對准入申請。
- Then 固定目標階段、病區/病種/規則、數據域、應用/語義/模型/評測基線；輸入變化產生新版本或要求重驗，不把舊成績套新範圍。

### AC-F009-002 · 必要條件與缺項可解釋

- 來源：REQ-018, NFR-001, NFR-003, PSC-008, PSC-011
- 對應 PRD 驗收：AC-021, AC-022, AC-026
- Given 閾值、專業樣本、有效規則/本體、身份/留存、恢復或責任證據中任一缺失。
- When 彙集各前置判定。
- Then 逐項輸出滿足/不滿足/未確認/不適用及依據，不把缺字段、未運行、合成證據或任意默認值當滿足；拒絕相應階段啟用。

### AC-F009-003 · 高風險否決優先於平均指標

- 來源：REQ-018, NFR-003, PSC-011
- 對應 PRD 驗收：AC-021
- Given F008 報告存在一項確認高風險漏報或高風險未決/無法判斷，總體分數可能達其他目標。
- When 判斷晉級或擴大範圍。
- Then 拒絕受影響申請並保留具體案例/原因，平均分、零次觀察和管理員開關不能豁免；修復後需要相關重驗。

### AC-F009-004 · 關鍵人驗收與責任接受真實

- 來源：REQ-018, NFR-004, NFR-005, PSC-008, PSC-009, PSC-011
- 對應 PRD 驗收：AC-017, AC-022, AC-024
- Given 申請前置已滿足，有不同職責實際主體、缺少崗位記錄、重複提交或模型工具批准。
- When 記錄驗收、責任接受和准入決定。
- Then 只有獲授權真實崗位的當前範圍意見有效，記錄職責/範圍/版本/理由和時間；缺關鍵人不放權，工具批准不代簽，必要審計與決定同事務。

### AC-F009-005 · 階段能力在服務端受控

- 來源：REQ-018, NFR-001, NFR-003, PSC-008, PSC-011
- 對應 PRD 驗收：AC-022, AC-026
- Given 離線、影子、輔助分別有固定允許範圍，用戶繞過 UI 直接請求未開放動作。
- When 發起運行、消費結果或自動推進。
- Then 服務端按批准階段/範圍決定能力，影子輸出不成為臨床執行或自動改病歷；UI 改標籤不改變權限，未授權請求拒絕。

### AC-F009-006 · 條件失效後停用和回退保留歷史

- 來源：REQ-018, NFR-003, NFR-004, NFR-005, PSC-009, PSC-011
- 對應 PRD 驗收：AC-021, AC-022, AC-024
- Given 已獲准範圍隨後出現撤權、規則/本體失效、高風險事件或運維條件失效。
- When 消費失效事件或下一次執行前核對。
- Then 停止受影響自動能力、回到允許階段/人工路徑並記錄原因/範圍/責任；舊結果/意見/簽字仍保留，不通過清庫或回滾 checkpoint 抹除事實。

### AC-F009-007 · 修復與擴大範圍必須重新核驗

- 來源：REQ-018, NFR-003, NFR-005, PSC-001, PSC-011
- 對應 PRD 驗收：AC-022
- Given 舊申請被否決/停用，提交修復，或更換模型/本體/規則並請求新範圍。
- When 申請恢復或晉級。
- Then 明確受影響條件和重驗基線，必要證據重新滿足才產生新決定；一期範圍外申請指出範圍變更前置，不自行批准全院全病種。

### AC-F009-008 · 管理視圖顯示真實門檻與責任

- 來源：REQ-018, NFR-004, NFR-006, PSC-008, PSC-009, PSC-011, PSC-013
- 對應 PRD 驗收：AC-017, AC-022, AC-025
- Given 授權管理/業務責任人查看多項通過/阻斷/待確認條件及歷史範圍。
- When 定位申請、回查證據、作允許決定並返回。
- Then 顯示實際階段/版本/缺項/責任及已保存決定；列表/詳情/計數同源，風險含文字、禁用原因可讀；無權人員不能看到超範圍正文。

### AC-F009-009 · 向運行與交付提供同一准入事實

- 來源：REQ-018, NFR-003, NFR-005, PSC-001, PSC-009, PSC-011
- 對應 PRD 驗收：AC-022, AC-024
- Given 運行入口和 F010 同時讀取當前及歷史決定，並有過期/重複投遞事件。
- When 交接准入或未放行基線。
- Then 消費者取得相同批准範圍/版本/限制，重複事件不重複啟用；未放行可作為說明交付但不變成批准，當前失效不被舊快照恢復。

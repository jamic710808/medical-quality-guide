# F009 · 上線准入與責任接受實施計劃

## 2026-10-14 實施更新

用戶 U10 已授權持續開發。本 Feature 的軟件已落地：固定準入基線、逐項缺項/風險否決、責任意見、服務器階段攔截、停用及重驗。 實際文件為 `backend/medical_quality/release.py`、`backend/medical_quality/access.py`、`backend/medical_quality/quality.py`。為保持模塊化單體簡單，下文最初規劃的多個職責文件合併在這些模塊中；它們不是另有待創建的第二實現。Spec 的業務語義不變。工程前置已有實測，Plan ready 不等於專業或完整驗收通過。逐用例結果與剩餘組合見[當前實現記錄](../../verification/F009-implementation.md)。已實際建立阻斷申請；未建立或偽造生產批准。目標環境的准入/備份恢復驗收尚未取得。

下文“現有上下文/擬建模塊”保留原設計階段背景；當前工程狀態以本節和實際文件為準。

當前 backend 無業務實現、正式 frontend 只有品牌資源；靜態原型僅作已有旅程/交互輸入。採用既定 React/TypeScript/Vite、FastAPI/Pydantic、PostgreSQL/SQLAlchemy/Alembic、獨立 Worker；需要執行編排的調用方沿 LangGraph，不為本 Feature 添加自由 Agent。

複用 [FA-01～12](../../architecture/architecture.md)、[TP-13～16](../../architecture/technical-points/platform-and-clinical-contracts.md)、[共同實施合同](../../architecture/implementation-contracts.md)和[評估計劃](../../evaluation-plan.md)。必須保持 PSC-001, PSC-008, PSC-009, PSC-011, PSC-013；本輪不改原始 Data、真實身份、專業規則或原型狀態，不新增平臺 Feature。

目標階段/範圍、固定 source/rule/knowledge/semantic/model/application 配置與驗證基線、F008 報告、F007 流程驗收/責任條件、F001 授權和目標部署/留存/運維證據、真實關鍵崗位意見。

計劃給出具體實施路徑，運行依賴/接口和專業前置仍待實際證明，因此為 draft。不可用條件已定義為拒絕/受限；不能為了文件齊全把未知填成通過。

## 實現方案

### 組合門禁與持久對象

release_request 固定 requested_stage、scope、baseline_manifest 與 expected_version；gate_condition 保存 condition_key、required、status、evidence_refs、scope/version、checked_at 和需再次核對的時效；responsibility_acceptance 保存真實 actor/崗位/意見/理由；gate_decision 保存精確批准/阻斷範圍與條件摘要。對象使用 PostgreSQL，不以某個前端 enabled 字段替代。

門禁按“當前授權/範圍→版本一致→必要數據/專業/技術證據→高風險否決→關鍵崗位責任→服務端啟用”組合判斷。對必需條件，只允許明確滿足進入下一步；unknown/not_run/missing 為未滿足。閾值不在請求中由客戶端隨意覆蓋，從凍結評測協議讀取，null 不當 0。規則效力、本體/模型資格和實際數據域來自各主責模塊當前事實，不由 F009 重新猜造。

### 階段控制與回退

| 階段 | 獲准可做 | 禁止/限制 |
| --- | --- | --- |
| 離線驗證 | 指定用途的開發/評測及合成流程檢查 | 不憑離線演示直接驅動生產責任 |
| 限定影子 | 在批准域/範圍觀察真實分佈與輸出，記錄工作負擔/誤漏報 | 不將影子結果自動派為臨床執行或原系統寫回 |
| 人確認輔助 | 在批准病區/規則/版本內輔助質控，保留實際複核/簽字 | 無無人確認病歷修改、自動診斷或擴範圍 |

業務應用每次敏感啟動/恢復/發佈結果都讀取有效 gate/capability 及 F001 當前授權。事件 outbox 用於及時傳播，不能只等消費完事件才停止明顯失效入口；索引/緩存不能繞過當前允許集合。已經執行的人工事務不因停用回滾，計算取消與業務撤銷分開。

決定提交短事務重驗 expected_version、條件摘要/依賴當前有效性及真實崗位，保存決定+審計+outbox；條件評估與實際激活間有版本變化則衝突，不把此前頁面 green 狀態當生效依據。審批界面顯示缺項對應責任崗位/證據，不為缺專業閾值自動發明數值。接口與字段見[實施合同](../../architecture/implementation-contracts.md#contracts-release)。

### 運營證據

准入材料包含功能/恢復/權限檢查、固定評測報告、實際專業和關鍵人意見、數據/規則/術語許可、留存、真實身份/簽署方式以及性能/備份恢復預算的實測。RPO/RTO 和性能目標來自目標環境凍結記錄，未定時不是通過；離線開發不因此不能寫代碼，但生產階段不能省略。


### 逐結果落地與驗證

**AC-F009-001 / 准入申請固定範圍與基線。** 固定目標階段、病區/病種/規則、數據域、應用/語義/模型/評測基線；輸入變化產生新版本或要求重驗，不把舊成績套新範圍。 由 release/requests.py、baselines.py 承接，以 申請基線與配置變更合同測試 檢查；scope/manifest、版本衝突與新申請關係 是必須保存的結果，不以界面提示或接口返回成功替代。

**AC-F009-002 / 必要條件與缺項可解釋。** 逐項輸出滿足/不滿足/未確認/不適用及依據，不把缺字段、未運行、合成證據或任意默認值當滿足；拒絕相應階段啟用。 由 release/prerequisites.py、policy.py 承接，以 必要前置缺失的代表條件矩陣測試 檢查；條件結果、證據引用、明確阻斷與負責人 是必須保存的結果，不以界面提示或接口返回成功替代。

**AC-F009-003 / 高風險否決優先於平均指標。** 拒絕受影響申請並保留具體案例/原因，平均分、零次觀察和管理員開關不能豁免；修復後需要相關重驗。 由 release/vetoes.py、gate.py 承接，以 高風險否決獨立判定測試 檢查；否決條目、申請狀態與不可豁免記錄 是必須保存的結果，不以界面提示或接口返回成功替代。

**AC-F009-004 / 關鍵人驗收與責任接受真實。** 只有獲授權真實崗位的當前範圍意見有效，記錄職責/範圍/版本/理由和時間；缺關鍵人不放權，工具批准不代簽，必要審計與決定同事務。 由 release/acceptance.py、decisions.py 承接，以 責任接受/缺崗位/事務故障測試 檢查；具名決定、責任記錄、審計和拒絕 是必須保存的結果，不以界面提示或接口返回成功替代。

**AC-F009-005 / 階段能力在服務端受控。** 服務端按批准階段/範圍決定能力，影子輸出不成為臨床執行或自動改病歷；UI 改標籤不改變權限，未授權請求拒絕。 由 release/capabilities.py、運行入口 adapter 承接，以 三階段實際入口能力矩陣測試 檢查；允許動作、直接 API 拒絕及階段來源 是必須保存的結果，不以界面提示或接口返回成功替代。

**AC-F009-006 / 條件失效後停用和回退保留歷史。** 停止受影響自動能力、回到允許階段/人工路徑並記錄原因/範圍/責任；舊結果/意見/簽字仍保留，不通過清庫或回滾 checkpoint 抹除事實。 由 release/revocation.py、rollback.py、outbox.py 承接，以 資格失效與受影響範圍回退測試 檢查；停止事件、運行拒絕、歷史仍可回查 是必須保存的結果，不以界面提示或接口返回成功替代。

**AC-F009-007 / 修復與擴大範圍必須重新核驗。** 明確受影響條件和重驗基線，必要證據重新滿足才產生新決定；一期範圍外申請指出範圍變更前置，不自行批准全院全病種。 由 release/revalidation.py、baselines.py 承接，以 修復/版本變化/範圍擴大重驗測試 檢查；新舊申請關係、複驗清單與拒絕原因 是必須保存的結果，不以界面提示或接口返回成功替代。

**AC-F009-008 / 管理視圖顯示真實門檻與責任。** 顯示實際階段/版本/缺項/責任及已保存決定；列表/詳情/計數同源，風險含文字、禁用原因可讀；無權人員不能看到超範圍正文。 由 release/query.py、API/正式准入頁面 承接，以 代表准入旅程與拒絕路徑瀏覽器走查 檢查；條件明細、兩視口、返回狀態和審計 是必須保存的結果，不以界面提示或接口返回成功替代。

**AC-F009-009 / 向運行與交付提供同一准入事實。** 消費者取得相同批准範圍/版本/限制，重複事件不重複啟用；未放行可作為說明交付但不變成批准，當前失效不被舊快照恢復。 由 release/handoff.py、events.py 承接，以 F009→運行/F010 合同與重複事件測試 檢查；同版 GateDecision、限制傳播和冪等結果 是必須保存的結果，不以界面提示或接口返回成功替代。

### 上下游與獨立驗證

輸入：目標階段/範圍、固定 source/rule/knowledge/semantic/model/application 配置與驗證基線、F008 報告、F007 流程驗收/責任條件、F001 授權和目標部署/留存/運維證據、真實關鍵崗位意見。

輸出：GateDecision、必要條件逐項結果/缺項、批准或阻斷的精確能力範圍、ResponsibilityAcceptance、Stop/Rollback/RevalidationRecord；運行入口和 F010 消費同一版本。

初次可用顯式合成夾具檢驗字段/狀態和失敗語義；真實連接與業務/專業條件具備後再做組合驗收。對接時固定 request/operation、對象/Schema 版本、允許範圍、狀態/原因和證據引用，當前授權在執行/恢復時重驗。

## 實施順序

1. 核對下列 OQ 與相鄰合同，在項目內固定實際依賴/服務角色；明確合成夾具和正式樣本/用途，先處理實現就緒阻塞。
2. 按 [Tasks](tasks.md) 的局部依賴完成可觀察結果；每步涉及前後端/數據/校驗可一起交付，不按固定時長拆。
3. 為 [F009 用例](../../../evals/F009.json)綁定真實檢查，運行其對應最窄路徑；沒有執行的場景保留未運行，不能勾選任務。
4. 由 T010 彙總局部證據，並在相鄰真路徑具備後執行[產品套件](../../../evals/product.json)相應組合門檻，數據/醫學/身份/生產責任分別核對。

## 回退策略

發現條件失效先禁止受影響新自動動作，保留歷史批准/拒絕和實際決定；退回仍獲准階段或人工路徑。修復形成新申請/證據，不能改寫舊否決或恢復已撤權資源。技術部署回滾另由運行方案執行，F009 保存其範圍/結果與責任，不自動刪除生產數據。

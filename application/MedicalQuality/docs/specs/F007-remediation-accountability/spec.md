# F007 · 複核整改與責任簽字閉環規格

## 目標與可觀察結果

把疑似問題變成有依據、有當前責任人、有版本與簽字範圍的人工處理結果。醫生能整改或申訴，質控/專家能保留原判與不同意見，任務在中斷和跨時處理後仍可正確接續。

REQ-009～014 對應的業務痛點是候選問題與責任待辦脫節、意見散落、整改新版本無法證明已重核、舊簽字漂移以及逾期無人接續；本 Feature 用同一責任閉環承接，資料與依據繼續回查原始證據。來源見 [PRD](../../PRD.md) 的 S01-10/11、S02-09/10 及 AC-010～018/024/025。

Spec ready 僅表示既有行為已展開；Plan 仍 draft、任務 planned，沒有真人專業複核或生產簽字被寫成已發生。

## 來源與範圍

- 來源需求：REQ-009, REQ-010, REQ-011, REQ-012, REQ-013, REQ-014, NFR-001, NFR-003, NFR-004, NFR-005, NFR-006。
- 來源總規格：PSC-001, PSC-005, PSC-006, PSC-007, PSC-008, PSC-009, PSC-013。
- 包含：確認/駁回、醫生整改/申訴、專家裁決/升級、再核驗及人工確認、分崗位簽字、新版本歷史、改派/期限和連續工作臺處理，含中斷、重複與過期操作的恢復。
- 不包含：自動診斷、模型裁決、原系統回寫或代簽；不另做質控算法，複用 F006；不把執行取消、收到通知或工具批准改成業務終態。

## 輸入輸出與迭代邊界

輸入為 F006 固定版本的候選、覆蓋/阻斷和重核結果，F004 病例上下文，F001 的實際身份、對象授權與責任記錄能力。醫生新文書通過 F002/F003/F004 形成新上下文，複用既有 F006 重核。

輸出為意見/決定、任務與責任狀態、整改文書版本、重核關聯和分崗位簽字；F004 展示同一已保存結果，F008/F009 按用途取得評測/流程責任依據。界面或執行恢復可以單獨優化，但共享狀態、版本綁定、授權及責任語義變化需上提 Product Spec；不產生上游必須依賴 F007 才能建設的循環。

## 功能行為

### 主流程

1. 質控人員在授權範圍查看疑似問題和同版本證據，確認後派給責任醫生；誤報駁回保留理由，不偽裝整改完成。
2. 醫生選擇整改或申訴。整改產生新文書；申訴保留原判並由被指派專家裁決或升級，超時不代替決定。
3. 新版本複用 F006 核查受影響範圍，由質控人員確認結果；缺口或爭議未解決時不給簽字准入。
4. 責任醫生與質控複核人分別完成自身簽署。單方仍待另一方；舊版本歷史保留，新版本不繼承舊簽字。
5. 改派、延期、退回、升級記錄理由與前後責任；各視圖消費同一已保存結果，運行中斷後繼續真實待辦。

### 業務規則與邊界

- 系統/模型的建議、工具許可與真實崗位決定分開；只有當前授權及對象/版本前置滿足，才可執行業務動作。
- 原件、原判與歷史意見不覆蓋；文書、規則、知識、結果、意見和簽字固定各自版本/範圍。
- “不成立”“已整改”“已核驗”“已簽字”不可互換；局部完成不代表整份病例合格。
- 不因逾期、事件流結束、自動重試或模型投票而通過人工門檻；取消計算不等於撤銷業務。
- 同一有效操作只形成一個可識別結果，舊版本變更先重新核對；責任證據保存失敗不顯示完整成功。

## 異常與恢復

| 情況 | 可觀察狀態 | 系統行為 | 恢復 |
| --- | --- | --- | --- |
| 證據不足/規則不適用 | 阻斷及影響範圍 | 保留允許人工查看/補充路徑 | 補齊條件後重核 |
| 高風險爭議未決 | 爭議中或升級 | 不簽字、不以模型意見覆蓋 | 實際專家裁決並留依據 |
| 無權限/過期版本 | 拒絕或衝突 | 不改當前對象，不給假成功 | 重新認證/核對新狀態 |
| 重複提交/響應丟失 | 既有結果或待核對 | 按操作身份對賬，不盲目重寫 | 取得明確提交結果 |
| 責任記錄失敗 | 操作未完整成功 | 業務變更不單獨成為已確認結果 | 恢復保存並重試同一操作 |
| 服務重啟/執行取消 | 真實待辦保留 | 業務記錄不因會話丟失而丟失 | 合法身份從當前版本接續 |
| 新文書/新適用依據 | 新核驗鏈 | 舊簽字不繼承 | 完成當前範圍重核與必要簽字 |

## 驗收標準

以下為本 Feature 貢獻，專業評測與生產責任接受仍由 F008/F009 承接；夾具/替身不能證明真人簽署已發生。

### AC-F007-001 · 質控確認與誤報駁回

- 來源：REQ-009, NFR-004, PSC-006, PSC-009
- 對應 PRD 驗收：AC-010, AC-017
- Given 同一固定版本的問題待質控複核，獲授權人員可確認派發或以原文/規則依據駁回。
- When 提交確認意見和責任醫生，或提交駁回理由。
- Then 確認產生明確醫生待辦；駁回保留原問題和理由並以問題不成立結案，不虛構整改、再核驗或簽字已完成；責任記錄與變更可回查。

### AC-F007-002 · 醫生整改保存新版本

- 來源：REQ-010, NFR-004, NFR-005, PSC-001, PSC-006, PSC-007
- 對應 PRD 驗收：AC-011
- Given 醫生被派處理當前問題和文書版本，另有無權限或持舊版本的提交。
- When 提交整改內容及說明。
- Then 獲准且版本匹配的提交形成有父版本與責任人的新文書和待核驗狀態；原件/舊意見不覆蓋，不寫回 HIS；越權/過期提交明確拒絕或衝突。

### AC-F007-003 · 申訴、裁決與爭議升級

- 來源：REQ-010, REQ-011, NFR-003, NFR-004, PSC-005, PSC-006, PSC-009
- 對應 PRD 驗收：AC-012
- Given 醫生提交帶依據的異議，獲指派專家處理，可能維持問題、撤銷或升級高風險爭議。
- When 保存申訴和專家決定。
- Then 原判、意見、身份和依據保留；結果進入要求整改、問題不成立或明確下一責任主體的升級狀態，未決高風險爭議不能關閉/簽字；模型不能裁決。

### AC-F007-004 · 再次核驗與人工確認分開

- 來源：REQ-012, NFR-003, NFR-005, PSC-005, PSC-006, PSC-007
- 對應 PRD 驗收：AC-009, AC-013
- Given 整改形成新文書，F006 可能返回條件通過、未通過、無法判斷或部分失敗。
- When 請求受影響範圍重核並由質控人員複核。
- Then 固定新輸入/結果版本；未滿足時退回補充或阻斷，機器執行結束不等於人工確認，只有確認且範圍內無阻斷才進入待簽字。

### AC-F007-005 · 雙崗位簽字綁定當前範圍

- 來源：REQ-013, NFR-003, NFR-004, PSC-007, PSC-008, PSC-009
- 對應 PRD 驗收：AC-014
- Given 當前範圍已具必要複核與有效依據，簽署需要責任醫生和質控複核人，另有缺前置或代簽請求。
- When 各實際崗位分別發起自己的簽署。
- Then 核查真實身份、職責、範圍與版本；單方仍待另一方，禁止代簽和有阻斷時簽字；雙崗完成只說明當前範圍，不等同整份病歷合格。

### AC-F007-006 · 新文書或適用依據變化不繼承舊簽字

- 來源：REQ-012, REQ-013, NFR-005, PSC-001, PSC-007
- 對應 PRD 驗收：AC-015
- Given 舊範圍已簽字，出現新文書或改變判斷適用性的依據版本。
- When 繼續處理當前版本。
- Then 建立新核驗鏈並重新檢查受影響範圍，舊簽字和原文留在舊版本；當前範圍不能借用舊通過/簽字狀態，不能靜默改寫舊依據。

### AC-F007-007 · 改派、期限與逾期保持責任

- 來源：REQ-014, NFR-004, NFR-006, PSC-006, PSC-009, PSC-013
- 對應 PRD 驗收：AC-018, AC-025
- Given 任務已有責任醫生、複核人、處理節點和截止時間。
- When 獲權人員改派、延期、退回或任務逾期。
- Then 理由、前後責任與期限可回查，當前崗位能定位待辦；逾期只提醒或升級，通知不等於處理，不默認同意、代簽或結案。

### AC-F007-008 · 重複提交與過期操作一致

- 來源：REQ-009, REQ-012, REQ-013, NFR-004, NFR-005, PSC-009
- 對應 PRD 驗收：AC-017, AC-024
- Given 同一決定重複到達，兩個操作者持有不同任務版本，業務寫入後響應可能丟失。
- When 重試或提交舊版本動作。
- Then 同一有效操作只有一個可識別業務結果和對應責任記錄，舊版本提示重新核對而不覆蓋新意見；未知提交結果先按操作身份核對，不能盲目重做簽字。

### AC-F007-009 · 人工等待可跨進程恢復

- 來源：REQ-009, REQ-010, REQ-011, REQ-012, REQ-013, NFR-003, NFR-005, PSC-006, PSC-007, PSC-009
- 對應 PRD 驗收：AC-010, AC-012, AC-013, AC-014, AC-024
- Given 任務等待真人輸入時服務重啟，或業務決定已提交但執行恢復尚未完成；另有取消執行、亂序回覆和舊圖版本。
- When 重新進入或恢復處理。
- Then 以已保存業務狀態識別當前責任和版本，只有有效決定推進；重放不重複寫入，舊/亂序回覆拒絕或隔離，取消執行不刪除待辦/簽字，不兼容狀態受控停止而不假成功。

### AC-F007-010 · 崗位旅程與返回狀態一致

- 來源：REQ-009, REQ-010, REQ-014, NFR-006, PSC-006, PSC-013
- 對應 PRD 驗收：AC-005, AC-010, AC-011, AC-018, AC-025
- Given 各崗位從授權列表進入長內容任務，在 1280×800 和 1440×1000 視口處理後返回，記錄可能退出原篩選。
- When 查看證據、執行允許動作並返回工作臺。
- Then 主要內容與動作可讀可達，風險/禁用原因有文字；列表、詳情、計數與責任節點反映同一已保存狀態，保留有效瀏覽上下文，不用會話假狀態顯示成功。

### AC-F007-011 · 工具許可、業務授權與責任證據分離

- 來源：REQ-009, REQ-010, REQ-011, REQ-013, NFR-001, NFR-003, NFR-004, PSC-005, PSC-008, PSC-009
- 對應 PRD 驗收：AC-009, AC-014, AC-016, AC-017, AC-026
- Given 運行時工具批准/模型建議到達，但業務主體無權限或記錄已過期；另有審計寫入失敗和越域工具配置。
- When 請求複核、裁決、改文書或簽署。
- Then 不憑 Agent 角色、工具批准或 resume 值授權業務動作；關鍵責任記錄缺失不給完整成功，越域拒絕；原件不回寫、模型不能代人簽字，普通錯誤日誌不保留不必要病歷全文。

## 開放問題

行為邊界已由上游確認，沒有阻塞規格定義的新產品問題。實際具名身份/簽署方式、保留策略與專業批准沿 PRD OQ-003/005/006，在相應啟用前落實；缺少條件時明確拒絕或限制用途。Plan 的框架、接口和恢復驗證前置不因 Spec ready 被關閉。

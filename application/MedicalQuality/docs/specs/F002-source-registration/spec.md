# F002 · 多源資料接入與版本登記規格

## 目標與可觀察結果

把獲准的文件/只讀數據庫變成穩定可回查的來源版本、結構目錄和讀取範圍，給 F003 提供可執行的接入合同。來源登記成功與解析成功分開，保持原件、命名空間、許可和評測分工。

本輪依據用戶“補齊全部方案、Feature 與評估”的授權，在原 Map 邊界內展開。Spec ready 表示業務行為已可據此規劃；Plan draft / Tasks planned 保留尚未取得的運行與專業證據，不宣稱功能已完成。

## 來源與範圍

- 來源需求：REQ-001, NFR-001, NFR-002, NFR-005。
- 來源總規格：PSC-001, PSC-008, PSC-009。
- 本 Feature 包含：受限來源登記、文件內容身份/數據庫一致性聲明、結構目錄與原生路徑基準、數據角色/用途、接入覆蓋、重複識別/併發及變更撤回、解析交接和回查入口。
- 本 Feature 不包含：不執行 OCR 或醫學抽取，不合並患者，不升級規則效力或讀取評測答案；不提供任意服務器路徑/URL讀取，不復制/改寫整個原庫，不新增 HIS 回寫。
- 產品含義以 [PRD](../../PRD.md)、[Product Spec](../product-spec.md)及 [Feature Map](../feature-map.md#f002) 為準；局部驗收貢獻與產品組合驗收分開。

## 輸入輸出與迭代邊界

- 輸入與前置條件：可信授權決定、服務端登記的 connector/data root、來源引用/格式、source namespace、用途/角色/許可、聲明範圍、預期輸入版本與 operation_key。
- 輸出、必要語義與消費方：SourceVersion、SourceCatalog、ReadScope/AllowedReadHandle、RegistrationResult 和覆蓋/失敗項；F003 按固定版本讀取，下游回查重新核對當前授權。
- 可獨立調整：本模塊內部組織、查詢與呈現方式，前提是身份/版本、狀態、允許範圍和證據合同不變。
- 需協調上下游：共享對象/版本/錯誤、授權和責任事件變化同步生產者與消費者，不在局部把未判斷改為通過。原始資料與既有原型保持；正式行為由後端事實源提供。

## 功能行為

### 主流程

1. 已獲准來源時，登記文件/只讀庫範圍；返回來源身份與已知/未知，結果為穩定來源版本，交給F003。
2. 已登記來源時，讀取表/字段或文件元信息；結構與記錄範圍分開，結果為實際結構與定位口徑，交給F003/F004。
3. 同來源變化/補文書時，提交新內容或範圍；舊版保留，登記新版本，結果為可重核的變更，交給F003/F007。
4. 失敗或部分登記時，限定重試/修復路徑；不刪除失敗分母，結果為接續允許部分，交給信息科/Worker。

### 業務規則與邊界

- 文件名、下載地址和最後修改時間不足以單獨固定內容版本；數據庫快照語義據實際能力聲明。
- namespace、源記錄、文檔、患者、就診與任務身份分開，內容相同不自動合併來源或業務對象。
- 參考規則/術語/原文/參考答案/驗證留出角色從入口保留；allowed handle 不能授予新的用途或出域許可。
- 原件只讀；整改資料是新的工作臺來源版本，不回寫 HIS 或替換原文件。
- 路徑解析須保持在登記根內；圖文 CSV 與心電索引各用其原相對基準，上游 source_member 不冒充本地入口。

狀態名稱沿用 PSC 與主責模塊的共同含義；登記/計算/交接完成只說明該環節，不自動錶示專業確認或生產放權。所需技術字段在 Plan 與共享實施合同落實，本文不預填醫學閾值/真實賬號。

## 異常與恢復

| 情況 | 可觀察結果/處理 | 恢復條件 |
| --- | --- | --- |
| 未授權/路徑越界 | 拒絕且不讀正文 | 取得實際授權並使用允許 connector |
| 內容變化/快照不能保證 | 版本不符或一致性受限 | 新版本登記或限定實際一致讀範圍 |
| 損壞/不可讀/結構不明 | 失敗或部分、保留範圍 | 修復來源後受限重試 |
| 參考答案/留出來源 | 僅登記邊界 | 獲准評測流程讀取，不交建設者 |
| 重複/併發登記 | 既有結果或衝突 | 按請求摘要對賬，不造新業務身份 |

## 驗收標準

每項 AC 是本 Feature 的可觀察貢獻；固定夾具驗證機制，真實相鄰模塊與專業材料驗證端到端目標。未實現時用例 check_ref 保持 null。

### AC-F002-001 · 只登記允許來源與用途

- 來源：REQ-001, NFR-001, PSC-001, PSC-008
- 對應 PRD 驗收：AC-001, AC-026
- Given 指定批准數據根/connector、合法文件，以及目錄穿越、越界符號鏈接、任意 URL 和無授權來源。
- When 請求登記及可讀性檢查。
- Then 只讀取授權根/範圍內的來源，其他請求拒絕；客戶端不能讓服務端任意取文件/網絡資源，失敗不切未授權端點。

### AC-F002-002 · 文件與數據庫版本語義真實

- 來源：REQ-001, NFR-002, NFR-005, PSC-001
- 對應 PRD 驗收：AC-001, AC-024
- Given 同名不同內容文件和查詢期間會變化的數據庫，另有不可證明一致快照的來源。
- When 登記來源版本併發出讀取請求。
- Then 文件固定內容身份，數據庫保留實際快照/一致性條件及範圍；僅有時間戳不聲明全庫同時刻版本，內容不符不會套舊版本 ID。

### AC-F002-003 · 數據庫結構和業務記錄分開

- 來源：REQ-001, NFR-002, PSC-001
- 對應 PRD 驗收：AC-001
- Given SQLite 表含 TEXT 原字段、內部源記錄號主鍵、未聲明外鍵和結構目錄。
- When 登記表/字段/約束與允許記錄範圍。
- Then 保留實際結構、類型和聲明鍵，結構已讀不代表業務行已讀；不憑字段名推外鍵，不把記錄序號當患者 ID，原庫不寫入。

### AC-F002-004 · 路徑基準和定位口徑可回查

- 來源：REQ-001, NFR-002, PSC-001
- 對應 PRD 驗收：AC-001
- Given 圖文路徑相對 Data 根、心電路徑相對 05_心電圖，CSV 帶引號內換行與原源記錄號。
- When 生成文件/記錄回查句柄。
- Then 按各自基準定位且不越界，源 URL/歷史包路徑不當本地文件；邏輯記錄與物理行/表頭計數分開，定位不足明確受限。

### AC-F002-005 · 來源性質與評測角色隔離

- 來源：REQ-001, NFR-001, NFR-002, PSC-001, PSC-008
- 對應 PRD 驗收：AC-001, AC-026
- Given 業務原文、schema_reference、規則、術語、reference_label、validation/heldout 與未知來源性質並存。
- When 登記並生成 F003 建設讀取範圍。
- Then 角色、性質、用途和許可沿源保存；答案/留出僅交合法評測方，建設者不探讀正文；未知不自動標生產可用，公開/合成不升級為生產證據。

### AC-F002-006 · 內容重複不混淆業務身份

- 來源：REQ-001, NFR-002, NFR-005, PSC-001, PSC-009
- 對應 PRD 驗收：AC-001, AC-024
- Given 同一請求重試、同內容不同來源/任務、同鍵不同請求體及併發登記。
- When 保存來源版本/接入操作。
- Then 同一有效操作返回既有結果，內容族可以識別但不合並不同來源/任務；請求摘要衝突拒絕，責任記錄與登記結果一致。

### AC-F002-007 · 接入覆蓋包含失敗和未讀

- 來源：REQ-001, NFR-002, PSC-001, PSC-009
- 對應 PRD 驗收：AC-001
- Given 一批聲明文件有可讀、不可讀、未知總數、空範圍和中斷情形。
- When 登記和彙總實際輸入。
- Then 範圍及計數單位可對賬，成功/失敗/未讀及未知明確；空範圍不同於未知或全病歷無問題，不刪失敗項製造完整成功。

### AC-F002-008 · 更新與撤權保留歷史並限制新讀取

- 來源：REQ-001, NFR-001, NFR-005, PSC-001, PSC-008, PSC-009
- 對應 PRD 驗收：AC-001, AC-026, AC-024
- Given 源文件被替換、文書新增版本或授權撤銷，舊解析任務持舊 handle。
- When 讀取/恢復和請求歷史回查。
- Then 新內容生成新版本，舊句柄不能讀取新字節冒充舊來源；撤權限制當前訪問，歷史記錄保留但回查仍需授權，變化通知帶影響範圍。

### AC-F002-009 · 向解析方交付穩定受限合同

- 來源：REQ-001, NFR-001, NFR-002, NFR-005, PSC-001, PSC-008, PSC-009
- 對應 PRD 驗收：AC-001, AC-002, AC-026
- Given 一份固定來源和範圍已登記，另有不兼容版本/過期授權，F003 為消費者。
- When 取得 SourceVersion/ReadScope 並實際讀取聲明單元。
- Then 消費者得到相同身份/版本/用途/結構和回查入口，無法解釋的版本或過期條件明確拒絕；登記成功不宣稱解析/醫學驗收成功。

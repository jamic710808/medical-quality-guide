# F011 · 知識圖譜工作臺實施計劃

## 2026-10-14 實施更新

用戶 U10 已授權持續開發。本 Feature 的軟件已落地：固定上游原生圖譜與 Designer、三種投影、證據回查、內部審核、IRI/基數保真和受控導出。 實際文件為 `backend/medical_quality/knowledge_graph.py`、`backend/medical_quality/ontology.py`、`backend/medical_quality/governance.py`。為保持模塊化單體簡單，下文最初規劃的多個職責文件合併在這些模塊中；它們不是另有待創建的第二實現。Spec 的業務語義不變。工程前置已有實測，Plan ready 不等於專業或完整驗收通過。逐用例結果與剩餘組合見[當前實現記錄](../../verification/F011-implementation.md)。圖像/顯示投影不代替完整 OWL/SHACL；公共 GitHub/Fabric 提交未裝配到醫療界面。

下文“現有上下文/擬建模塊”保留原設計階段背景；當前工程狀態以本節和實際文件為準。

## 實現方案

### 源碼引入與能力基線

先按固定 SHA 復現原生工作臺；確認圖瀏覽、Designer、RDF/JSON、路徑、主題及大圖行為，保存 OP 清單證據。正式集成保留原生代碼與依賴閉包，用醫療適配包裝。中文標籤、Inspector 附錄、路由、授權和專業候選流是允許的業務改動；原生能力被刪減必須修復，不能用“同樣用了 Cytoscape”解釋通過。

源碼基線、MIT 和依賴通知進入受控代碼；臨時對照構建/node_modules/截圖等使用忽略目錄，記錄再生和清理條件。檢查原生安全/版本變化後才固定項目 lockfile，不盲目運行上游安裝 hook 或部署腳本。

### 數據、狀態和接口

沿 TP-17 的 GraphViewEnvelope v1：原生 ontology/bindings 加醫療 node_meta/edge_meta、版本集合、範圍和 loss_report。正式實例/斷言從原業務庫來，不用 sampleInstances/sampleBindings。病例模式與本體模式共享渲染器，但選項/標題/允許導出由語義分型決定，不能把實例寫回 EntityType 事實源。

服務端先執行 F001 對象授權，再讀取 F004/005/006 固定版本。詳情/展開/計數/導出重新授權；緩存鍵包括主體授權範圍、投影版本和用途。客戶端 store 隔離圖會話，處理亂序響應和撤權清理，URL 只保存不透明落點；本體編輯候選存於 F004，Zustand 歷史只負責交互撤銷重做。

接口按技術決定的 views/elements/drafts/submit/export-authorizations 合同實現，複用共同錯誤信封、樂觀鎖、冪等、同事務審計；圖譜截圖成功不能掩蓋導出授權/審計失敗。內存視圖行為不進入醫療事實事務。

### 格式、編輯與推理邊界

保留原生 RDF/XML/JSON 子集並增加適配報告；Turtle/SHACL/外部術語按現有正式後端處理，語義損失不靜默接受。類型/實例、原始 IRI、未知基數和中文 label 必須顯式核對。Fabric 規則作為特定導出檢查，不是醫學詞表必須英文且 26 字符以內的要求。

Designer 基於固定語義版本形成新候選，編輯/保存/預覽/驗證/提交分別反饋。提交進入已有專業/形式化/CQ/許可檢查；原生髮布到 Playground 只能變更預覽。LangGraph 仍只讀獲准 SemanticRelease，不讀瀏覽器候選作為事實。F011 不新增 Agent 工具或生產本體寫權限。

### 視覺、規模與恢復

依設計記錄形成佔主要空間的原生畫布、可摺疊對象欄和可讀 Inspector，圖和原文對照優先於裝飾卡片。保留原生主題、節點圖標顏色、方向箭頭、路徑與鄰域反饋。目標桌面視口、鍵盤與減少動態效果都納入任務檢查。

保留上游 1000 元素 grid 閾值和 100 項列表限制；業務範圍/增量加載是附加適配，不能偽裝原生無上限處理。錯誤回退保留原文及原責任頁面，且明確圖未可用。完整性與性能分別驗收，閾值須先在指定環境凍結。

## 實施順序與依賴

1. T001 固定原生基線；T002 明確投影；T003 先建立授權查詢。
2. T004/T005 貫通證據與探索；T006 候選流、T007 格式、T008 導出依各自前置推進。
3. T009 版本會話、T010 大圖；T011 完成業務空間與交互，T012 故障恢復。
4. T013 組合 PG-006。只用夾具可完成工程預檢；實際 F001/F004/005/006、原文與候選服務具備後才算組合通過。

F011 建設前置為 F001、F004、F005、F006；F007 的複核/整改返回在組合階段驗證，F009 准入消費該必需模塊的驗收證據。即使 F011 不可用，F004 原有授權原文/人工入口仍須可達；這一恢復行為不豁免完整產品交付時 F011 的 P0 驗收。

## 依賴與風險

| 風險 | 控制與回退 |
| --- | --- |
| 上游 Preview 或依賴版本與應用衝突 | 固定 SHA、最小補丁和原生對照；更新只重驗受影響 OP，用回已驗證版本而非自造簡版圖 |
| 類型圖無法承載全部 OWL/病例語義 | 附錄與分視圖、完整包留原事實源，損失拒絕/報告；禁實例 OWL 類導出 |
| 原生 URL 分享/目錄貢獻造成出域 | 醫療入口接內域鑑權/導出，公共寫動作不裝配；網絡邊界與 payload 驗收 |
| 圖譜視圖暗示醫學事實或推理正確 | 斷言層次/方向/原文與缺口持續顯示；路徑/渲染不賦予專業批准 |
| 大圖卡頓或節點重排破壞閱讀 | 原生規模策略、明確範圍與定位、基線後預算；失敗返回原文，不能算圖譜完成 |
| 草稿覆蓋/歷史漂移 | 樂觀鎖、固定版本、審計、亂序隔離；衝突重核並保留輸入 |

## 回退策略

保留原始數據和正式語義包，版本不兼容時停止對應投影消費；依賴升級失敗回到有證據的固定上游版本。原生渲染失敗保留合法對象列表、原文和原工作入口；候選保存失敗保護輸入，不能回滾已提交專業決定或以清空工作區恢復。臨時對照構建在完成復現記錄後可清理，正式依賴按鎖文件再生。

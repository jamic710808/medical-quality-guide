# F001 · 訪問授權與責任審計實施計劃

## 2026-10-14 實施更新

用戶 U10 已授權持續開發。本 Feature 的軟件已落地：會話/CSRF、真實 OIDC 回調密碼學、RBAC/對象用途、RLS、撤權、事務審計和冪等。 實際文件為 `backend/medical_quality/access.py`、`backend/medical_quality/common.py`、`backend/medical_quality/db.py`、`backend/medical_quality/app.py`。為保持模塊化單體簡單，下文最初規劃的多個職責文件合併在這些模塊中；它們不是另有待創建的第二實現。Spec 的業務語義不變。工程前置已有實測，Plan ready 不等於專業或完整驗收通過。逐用例結果與剩餘組合見[當前實現記錄](../../verification/F001-implementation.md)。醫院 IdP、實際崗位映射、生產留存及簽署約定尚未取得。

下文“現有上下文/擬建模塊”保留原設計階段背景；當前工程狀態以本節和實際文件為準。

## 現有上下文與複用

當前 backend 無業務實現、正式 frontend 只有品牌資源；靜態原型僅作已有旅程/交互輸入。採用既定 React/TypeScript/Vite、FastAPI/Pydantic、PostgreSQL/SQLAlchemy/Alembic、獨立 Worker；需要執行編排的調用方沿 LangGraph，不為本 Feature 添加自由 Agent。

複用 [FA-01～12](../../architecture/architecture.md)、[TP-13～16](../../architecture/technical-points/platform-and-clinical-contracts.md)、[共同實施合同](../../architecture/implementation-contracts.md)和[評估計劃](../../evaluation-plan.md)。必須保持 PSC-008, PSC-009；本輪不改原始 Data、真實身份、專業規則或原型狀態，不新增平臺 Feature。

由受信登錄/服務身份解析的 actor，明確 action、resource/scope、purpose、對象/策略版本及時間；變更還需 expected_version、operation_key 與理由。

計劃給出具體實施路徑，運行依賴/接口和專業前置仍待實際證明，因此為 draft。不可用條件已定義為拒絕/受限；不能為了文件齊全把未知填成通過。

## 實現方案

### 身份、策略和事務承接

採用既定 OIDC＋同源服務端會話/BFF，身份驗證核對 issuer/audience、簽名/有效期及回調關聯；會話標識不等於訪問權限，瀏覽器不在 localStorage 保存可隨意讀取的敏感令牌。登錄映射產生內部穩定 actor_id/崗位關聯；測試身份用獨立合成配置，不偽裝醫院 IdP。

策略處理依次解析 action、對象歸屬、科室/責任病例/指派、purpose、有效期及當前 policy_version；默認拒絕。對象來自實際領域記錄，客戶端只能提交對象 ID，不能指定自己的責任組或允許病例列表。返回 decision_id、allow/deny、effective_scope、policy_version、expires_at、reason_codes；敏感對象的 403/404 反饋由 API 一致處理。

普通業務/Worker 數據庫角色不為 owner/superuser/BYPASSRLS。以受控事務上下文設置實際 actor/scope，連接池事務結束清理；RLS 是附加防線，不能取代應用動作/用途判斷。列表、計數、原文資源、SSE、索引/緩存與語義服務使用同一範圍表達；下載逐請求校驗，長流在安全分片/續傳前重驗。

### 崗位動作基線

| 崗位 | 允許能力的必要對象條件 | 明確不自動擁有 |
| --- | --- | --- |
| 醫生 | 本人獲派病例的查看、整改、申訴和本人簽署 | 他人病例、專家裁決、質控代簽 |
| 質控 | 獲准病區/任務複核、派發、再次確認與本崗位簽署 | 替醫生改文書/簽字 |
| 專家 | 獲指派爭議或評測批次的專業判斷 | 任意病例正文、修改他人獨立原判 |
| 信息科 | 獲准接入、身份/部署配置、最小運行診斷 | 默認正文和專業責任動作 |
| 管理部門 | 獲准彙總、准入及責任接受 | 以平均分豁免高風險否決 |
| 供應商支持 | 明確目的/對象/期限的診斷數據 | 無限後臺身份、生產病歷或業務簽署 |

### 審計和恢復

AuditRecord 保存 actor、action、resource/scope、purpose、before/after_version、reason、request/operation/decision/run 與結果、時間。關鍵變更由調用方將 audit/outbox 插入同一 SQLAlchemy 事務，audit 失敗拋出業務失敗並回滾；審計模塊不自行提前提交。只讀審計不可建立且合同要求必要記錄時限制讀取；不把日誌可寫當作責任證據成功。

冪等唯一約束以作用域內 operation_key 為核心並保存請求摘要；相同摘要返回既有結果，不同摘要衝突。expected_version 的比較和更新在同一事務完成。授權撤銷先使策略/允許集合失效，再清理派生緩存；歷史審計只追加，運維特權訪問另受目標環境控制，不聲稱絕對防篡改。

接口/對象的共同最少字段見[實施合同](../../architecture/implementation-contracts.md#contracts-access)。正常訪問不依賴 LLM 或本體推理；本體 ResponsibilityRole 只描述崗位語義，不發放權限。

### 逐結果落地與驗證

**AC-F001-001 / 可信身份與默認拒絕。** 主體只由可信身份來源取得；無效身份和偽造角色均拒絕，不暴露正文或取得新權限；有效登錄仍須通過動作與對象授權。 由 access/identity.py、session.py 承接，以 可信身份/過期/角色偽造合同測試 檢查；實際 actor 映射、拒絕原因與無正文響應 是必須保存的結果，不以界面提示或接口返回成功替代。

**AC-F001-002 / 角色動作與對象用途共同授權。** 只允許角色動作及對象/用途/期限同時滿足的請求；信息科/管理/支持身份不能憑崗位名獲取正文或代簽。 由 access/policies.py、scope.py 承接，以 角色×對象×用途的代表性決策矩陣測試 檢查；允許/拒絕集合、實際有效條件和策略版本 是必須保存的結果，不以界面提示或接口返回成功替代。

**AC-F001-003 / 所有讀取表面遵守同一範圍。** 列表/計數/詳情/下載/事件和緩存都按相同當前範圍過濾；拒絕反饋不額外洩漏資源存在性或正文，難猜 ID 不充當權限。 由 access/enforcement.py、repository_scope.py、API 讀取適配 承接，以 代表病例的多入口授權與 RLS 運行角色測試 檢查；各入口實際集合、數據庫角色/事務上下文和拒絕記錄 是必須保存的結果，不以界面提示或接口返回成功替代。

**AC-F001-004 / 後臺與模型工具不能擴大數據域。** 後臺再次核對任務範圍和當前授權，只能訪問批准數據/端點；本地失敗不放寬數據域，模型不能自行擴大對象或工具集合。 由 access/worker_context.py、tool_policy.py 承接，以 Worker/模型工具拒絕與未外發探針測試 檢查；固定任務範圍、拒絕事件、未授權網絡調用為零 是必須保存的結果，不以界面提示或接口返回成功替代。

**AC-F001-005 / 業務變更與必要審計共同成立。** 業務變化、責任審計與必要事件共同提交；必要記錄失敗時不產生孤立已完成狀態。查看/拒絕事件與關鍵寫入明確區分。 由 access/audit.py、transaction.py，與調用方 repository 承接，以 同庫提交邊界故障注入測試 檢查；前後狀態、審計/事件 ID、一致提交或回滾 是必須保存的結果，不以界面提示或接口返回成功替代。

**AC-F001-006 / 重複請求與過期操作不造新事實。** 同一有效操作返回同一可識別結果與審計；同鍵不同內容或過期版本拒絕/衝突，不覆蓋新意見，未知響應先對賬。 由 access/operations.py、audit.py、共享 command envelope 承接，以 請求摘要/版本競爭與響應丟失測試 檢查；唯一操作結果、衝突記錄與當前版本 是必須保存的結果，不以界面提示或接口返回成功替代。

**AC-F001-007 / 撤權和策略更新立即限制新消費。** 重新核對並停止受影響訪問，不等待索引重建才生效；保留歷史審計但歷史存在不授予當前讀取。 由 access/revocation.py、policy_versions.py 承接，以 撤權傳播到緩存/Worker/下載的同範圍測試 檢查；策略版本、失效時間和停止消費記錄 是必須保存的結果，不以界面提示或接口返回成功替代。

**AC-F001-008 / 審計查詢可追溯且最小化。** 僅獲准者看到相應審計範圍；能關聯主體、時間、動作、理由、版本與結果，普通日誌不復制正文/憑據/隱藏推理；無權者不能以審計入口繞過正文權限。 由 access/audit_query.py、API 審計頁與日誌適配 承接，以 審計回查和敏感輸出邊界測試 檢查；授權軌跡、最小字段與拒絕/脫敏記錄 是必須保存的結果，不以界面提示或接口返回成功替代。

**AC-F001-009 / 缺生產留存和責任參數時限制啟用。** 只執行已經明確獲准的用途；缺失生產前置不被默認填入或無限留存，允許獨立的合成/離線驗證但狀態不升級。 由 access/purpose.py、retention_policy.py、啟用前置 承接，以 缺配置與用途隔離合同測試 檢查；實際條件缺口、允許/限制用途及不啟用記錄 是必須保存的結果，不以界面提示或接口返回成功替代。

### 上下游與獨立驗證

輸入：由受信登錄/服務身份解析的 actor，明確 action、resource/scope、purpose、對象/策略版本及時間；變更還需 expected_version、operation_key 與理由。

輸出：AuthorizationDecision（允許/拒絕、實際允許範圍、策略版本/失效時間、原因、審計引用）及可與同一業務提交關聯的 AuditRecord；調用方不能用客戶端自報角色替代。

初次可用顯式合成夾具檢驗字段/狀態和失敗語義；真實連接與業務/專業條件具備後再做組合驗收。對接時固定 request/operation、對象/Schema 版本、允許範圍、狀態/原因和證據引用，當前授權在執行/恢復時重驗。

## 實施順序

1. 核對下列 OQ 與相鄰合同，在項目內固定實際依賴/服務角色；明確合成夾具和正式樣本/用途，先處理實現就緒阻塞。
2. 按 [Tasks](tasks.md) 的局部依賴完成可觀察結果；每步涉及前後端/數據/校驗可一起交付，不按固定時長拆。
3. 為 [F001 用例](../../../evals/F001.json)綁定真實檢查，運行其對應最窄路徑；沒有執行的場景保留未運行，不能勾選任務。
4. 由 T010 彙總局部證據，並在相鄰真路徑具備後執行[產品套件](../../../evals/product.json)相應組合門檻，數據/醫學/身份/生產責任分別核對。

## 回退策略

停用有缺陷策略/接口的新動作，保留已提交業務事實與審計；恢復只能選仍有資格的策略版本，不能因回退重授已撤銷權限。數據庫/身份配置變更採用可審計遷移，禁止清空審計、複用管理員權限或恢復原型角色切換作為生產後備。

# F001 · 訪問授權與責任審計規格

## 目標與可觀察結果

讓每次敏感訪問和責任操作都能回答“誰、在什麼用途/範圍/期限下、允許做什麼、結果是否與責任證據共同成立”。給 F002～F010 提供可消費的授權與審計合同，保持醫生、質控、專家、信息科、管理與支持崗位的責任分離。

本輪依據用戶“補齊全部方案、Feature 與評估”的授權，在原 Map 邊界內展開。Spec ready 表示業務行為已可據此規劃；Plan draft / Tasks planned 保留尚未取得的運行與專業證據，不宣稱功能已完成。

## 來源與範圍

- 來源需求：REQ-015, REQ-016, NFR-001, NFR-004, NFR-005。
- 來源總規格：PSC-008, PSC-009。
- 本 Feature 包含：實際身份映射、角色動作與對象屬性/用途/期限決策、敏感讀取/下載/事件流/後臺調用的統一邊界、關鍵變更同事務審計、拒絕記錄與受控審計查詢、授權撤銷和留存前置。
- 本 Feature 不包含：不代業務模塊判斷疾病或改變任務終態，不代醫生簽署；不搭建通用身份提供方，不新增緊急越權入口，不將 OIDC 登錄視為病歷訪問許可。
- 產品含義以 [PRD](../../PRD.md)、[Product Spec](../product-spec.md)及 [Feature Map](../feature-map.md#f001) 為準；局部驗收貢獻與產品組合驗收分開。

## 輸入輸出與迭代邊界

- 輸入與前置條件：由受信登錄/服務身份解析的 actor，明確 action、resource/scope、purpose、對象/策略版本及時間；變更還需 expected_version、operation_key 與理由。
- 輸出、必要語義與消費方：AuthorizationDecision（允許/拒絕、實際允許範圍、策略版本/失效時間、原因、審計引用）及可與同一業務提交關聯的 AuditRecord；調用方不能用客戶端自報角色替代。
- 可獨立調整：本模塊內部組織、查詢與呈現方式，前提是身份/版本、狀態、允許範圍和證據合同不變。
- 需協調上下游：共享對象/版本/錯誤、授權和責任事件變化同步生產者與消費者，不在局部把未判斷改為通過。原始資料與既有原型保持；正式行為由後端事實源提供。

## 功能行為

### 主流程

1. 登錄或服務請求時，解析身份並請求當前動作；展示允許入口或最小拒絕原因，結果為無正文洩漏的允許/拒絕，交給F002～F010。
2. 獲准對象/用途時，讀取列表、原文、附件或事件；查詢與計數/回放遵守同一範圍，結果為訪問記錄和受限結果，交給當前崗位。
3. 當前對象版本時，提交責任動作；同時核對身份/範圍/版本/理由，結果為業務與必要審計共同成功，交給事務調用方。
4. 授權或職責變化時，撤銷/期限到達/恢復調用；先限制新訪問與緩存消費，結果為拒絕與歷史軌跡保留，交給Worker/會話/下載。

### 業務規則與邊界

- 責任醫生只處理自己的責任範圍；質控不代改/代簽，專家只在獲指派爭議/評測範圍判斷。
- 信息科、管理及供應商崗位名不默認授予正文或專業操作；後臺服務身份受派發範圍與當前權限共同約束。
- 策略判斷同時核對動作與對象，不依賴 UI 隱藏按鈕、難猜 ID、模型工具註解或舊 checkpoint。
- 查看、拒絕、導出和關鍵變更區分記錄；關鍵狀態與必要責任記錄共同成立，日誌不是審計事實源。
- 冪等鍵綁定主體/動作/目標及請求摘要；同鍵不同內容拒絕，持舊對象版本不能覆蓋新事實。

狀態名稱沿用 PSC 與主責模塊的共同含義；登記/計算/交接完成只說明該環節，不自動錶示專業確認或生產放權。所需技術字段在 Plan 與共享實施合同落實，本文不預填醫學閾值/真實賬號。

## 異常與恢復

| 情況 | 可觀察結果/處理 | 恢復條件 |
| --- | --- | --- |
| 身份不明/過期 | 拒絕且不洩漏對象正文 | 重新認證後重驗當前範圍 |
| 授權/用途/期限不匹配 | 限制該訪問或動作 | 由已有授權管理流程修復，不自動升權 |
| 審計保存失敗 | 關鍵業務變更不給完整成功 | 事務回滾/對賬後受限重試 |
| 舊權限緩存/恢復輸入 | 重新決策，不沿舊允許繼續 | 當前有效授權與對象版本一致才恢復 |

## 驗收標準

每項 AC 是本 Feature 的可觀察貢獻；固定夾具驗證機制，真實相鄰模塊與專業材料驗證端到端目標。未實現時用例 check_ref 保持 null。

### AC-F001-001 · 可信身份與默認拒絕

- 來源：REQ-015, NFR-004, PSC-008
- 對應 PRD 驗收：AC-016
- Given 請求無有效身份、會話過期，或瀏覽器自行聲明醫生/管理員角色；另有有效身份。
- When 訪問病歷接口或提交責任動作。
- Then 主體只由可信身份來源取得；無效身份和偽造角色均拒絕，不暴露正文或取得新權限；有效登錄仍須通過動作與對象授權。

### AC-F001-002 · 角色動作與對象用途共同授權

- 來源：REQ-015, NFR-001, PSC-008
- 對應 PRD 驗收：AC-016, AC-026
- Given 同角色醫生屬於不同科室/責任組，任務指派、用途與有效期不同。
- When 對相同病例執行查看、整改、裁決、導出和簽字。
- Then 只允許角色動作及對象/用途/期限同時滿足的請求；信息科/管理/支持身份不能憑崗位名獲取正文或代簽。

### AC-F001-003 · 所有讀取表面遵守同一範圍

- 來源：REQ-015, NFR-001, NFR-004, PSC-008
- 對應 PRD 驗收：AC-016, AC-026
- Given 一個主體只能訪問部分病例，另有列表、計數、原文、附件、緩存和事件流入口。
- When 分別從各入口讀取並嘗試直接訪問範圍外資源。
- Then 列表/計數/詳情/下載/事件和緩存都按相同當前範圍過濾；拒絕反饋不額外洩漏資源存在性或正文，難猜 ID 不充當權限。

### AC-F001-004 · 後臺與模型工具不能擴大數據域

- 來源：REQ-015, NFR-001, PSC-008
- 對應 PRD 驗收：AC-026, AC-016
- Given 授權任務由 Worker 處理，工具失敗並提出未批准雲端或任意文件/SQL讀取。
- When 執行、重試或恢復任務與模型工具調用。
- Then 後臺再次核對任務範圍和當前授權，只能訪問批准數據/端點；本地失敗不放寬數據域，模型不能自行擴大對象或工具集合。

### AC-F001-005 · 業務變更與必要審計共同成立

- 來源：REQ-016, NFR-004, NFR-005, PSC-009
- 對應 PRD 驗收：AC-017, AC-024
- Given 複核/規則變更/簽字等調用方在當前事務提交狀態，審計或 outbox 寫入可能失敗。
- When 執行一次關鍵業務命令。
- Then 業務變化、責任審計與必要事件共同提交；必要記錄失敗時不產生孤立已完成狀態。查看/拒絕事件與關鍵寫入明確區分。

### AC-F001-006 · 重複請求與過期操作不造新事實

- 來源：REQ-016, NFR-005, PSC-009
- 對應 PRD 驗收：AC-017, AC-024
- Given 相同冪等鍵重複到達、同鍵不同請求體、兩個用戶持不同對象版本，以及提交後響應丟失。
- When 重試或併發提交已授權操作。
- Then 同一有效操作返回同一可識別結果與審計；同鍵不同內容或過期版本拒絕/衝突，不覆蓋新意見，未知響應先對賬。

### AC-F001-007 · 撤權和策略更新立即限制新消費

- 來源：REQ-015, REQ-016, NFR-001, NFR-005, PSC-008, PSC-009
- 對應 PRD 驗收：AC-016, AC-017, AC-026
- Given 會話/緩存/長任務持有舊允許決定，當前授權被撤銷或已到期。
- When 下一次讀取、結果發佈、恢復或下載發生。
- Then 重新核對並停止受影響訪問，不等待索引重建才生效；保留歷史審計但歷史存在不授予當前讀取。

### AC-F001-008 · 審計查詢可追溯且最小化

- 來源：REQ-016, NFR-001, NFR-004, PSC-008, PSC-009
- 對應 PRD 驗收：AC-017, AC-026
- Given 有授權審計者、無權技術支持者及含敏感原文的業務操作。
- When 查詢操作/對象/版本軌跡並查看運行錯誤。
- Then 僅獲准者看到相應審計範圍；能關聯主體、時間、動作、理由、版本與結果，普通日誌不復制正文/憑據/隱藏推理；無權者不能以審計入口繞過正文權限。

### AC-F001-009 · 缺生產留存和責任參數時限制啟用

- 來源：REQ-015, REQ-016, NFR-001, NFR-004, PSC-008, PSC-009
- 對應 PRD 驗收：AC-016, AC-017, AC-026
- Given 資料具有不同角色/許可，生產保留期限或真實崗位/簽署映射尚未配置。
- When 請求生產存儲、正文訪問或責任動作。
- Then 只執行已經明確獲准的用途；缺失生產前置不被默認填入或無限留存，允許獨立的合成/離線驗證但狀態不升級。

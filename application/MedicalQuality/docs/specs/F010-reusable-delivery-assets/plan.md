# F010 · 醫療資產固化與複用交付實施計劃

## 2026-10-14 實施更新

用戶 U10 已授權持續開發。本 Feature 的軟件已落地：固定規則/本體/權限/流程/評測資產、許可、不含敏感正文的 ZIP、冪等交接、完整性和必要依賴校驗。 實際文件為 `backend/medical_quality/delivery.py`、`backend/medical_quality/app.py`。為保持模塊化單體簡單，下文最初規劃的多個職責文件合併在這些模塊中；它們不是另有待創建的第二實現。Spec 的業務語義不變。工程前置已有實測，Plan ready 不等於專業或完整驗收通過。逐用例結果與剩餘組合見[當前實現記錄](../../verification/F010-implementation.md)。只形成工程交接包，不攜帶患者原文/答案/憑據；接收成功不激活任何臨床能力。

下文“現有上下文/擬建模塊”保留原設計階段背景；當前工程狀態以本節和實際文件為準。

## 現有上下文與複用

當前 backend 無業務實現、正式 frontend 只有品牌資源；靜態原型僅作已有旅程/交互輸入。採用既定 React/TypeScript/Vite、FastAPI/Pydantic、PostgreSQL/SQLAlchemy/Alembic、獨立 Worker；需要執行編排的調用方沿 LangGraph，不為本 Feature 添加自由 Agent。

複用 [FA-01～12](../../architecture/architecture.md)、[TP-13～16](../../architecture/technical-points/platform-and-clinical-contracts.md)、[共同實施合同](../../architecture/implementation-contracts.md)和[評估計劃](../../evaluation-plan.md)。必須保持 PSC-001, PSC-008, PSC-009, PSC-012, PSC-013；本輪不改原始 Data、真實身份、專業規則或原型狀態，不新增平臺 Feature。

指定資產類型與版本、目標用途/接收範圍、F009 的批准或未放行決定、各生產模塊的來源/許可/依賴及驗證狀態、F001 當前導出授權。

計劃給出具體實施路徑，運行依賴/接口和專業前置仍待實際證明，因此為 draft。不可用條件已定義為拒絕/受限；不能為了文件齊全把未知填成通過。

## 實現方案

### 資產與清單合同

建立 asset_catalog、export_request、export_manifest、export_item、export_run 和 download_audit。資產類型限定本期規則包、語義/映射所需包或合法引用、權限模板、責任流程、評測口徑/結果與說明，不遞歸打包工作區。每項記錄 producer、asset_id/version、sha256、schema_version、dependencies、source/license、allowed_purpose、scope、review/verification/gate 狀態及通用/域/醫院定製類別。

外部詞表不可分發時保留其允許的引用和取得條件；缺必要依賴則標受限交付/不能完整重現，不把本體包刪掉後稱完成。本體、JSONL、Turtle、規則配置及說明保持各自原生語義，manifest 統一它們的身份，不將所有內容展平成一個 JSON。實際評測樣本/原判只有明確合法接收用途時才提供，不默認進複用包。

### 構建與下載

Worker 按已凍結 manifest 生成臨時資源，再做文件/摘要/Schema/依賴檢查後短事務發佈元數據與審計；資源寫入和數據庫提交不是同一事務，崩潰後按 operation/export_id 和 manifest 對賬，清理無引用臨時文件前確認不含唯一責任證據。選擇 ZIP 僅作為有實際下載需求時的容器，固定排序和可重現元數據策略；業務 created_at 在記錄中保存，不把隨時間變化的字節誤當同一包摘要。

導出不默認複製原始數據庫/影像/信號、模型權重、.venv、緩存、令牌、真實崗位綁定或調試提示。下載走授權 API/受控資源服務，不返回裸服務器路徑；每次下載/續傳核對當前範圍和資格，返回最小結果。取消構建不刪除已經成立的責任記錄。

### 接手與驗證

中文 handoff 說明目標用途、資產類別/來源、固定版本、依賴準備、允許消費入口、未驗證/不適用項、重現方法和安全清理條件。導入檢查只驗證可讀性/完整性/契約兼容，不自動激活本地規則或本體，必須重新核對本院定義/身份/責任和 F009 條件。下載/導出例程當前尚未實現，未創建 ZIP 或大型產物。

共同合同見[實施合同](../../architecture/implementation-contracts.md#contracts-delivery)；驗證與狀態報告沿[評估計劃](../../evaluation-plan.md#release-gates)。

### 逐結果落地與驗證

**AC-F010-001 / 導出固定資產與依賴基線。** 逐資產固定 ID/版本/摘要/依賴/來源，使用同一聲明基線；來源更新不混入舊導出，必要依賴及不一致明確報告。 由 delivery/catalog.py、baselines.py 承接，以 多資產基線凍結與依賴一致性測試 檢查；manifest、依賴/版本及變化拒絕記錄 是必須保存的結果，不以界面提示或接口返回成功替代。

**AC-F010-002 / 授權、許可和來源角色限制導出。** 只含當前獲准且許可允許的內容，敏感原件/憑據/答案不默認加入；不能分發的依賴保留說明/允許引用，導出審計可追溯，不繞過評測隔離。 由 delivery/eligibility.py、access.py 承接，以 帶禁止資產的導出篩選與未讀取探針測試 檢查；包含/排除與理由、目標用途、許可/授權引用 是必須保存的結果，不以界面提示或接口返回成功替代。

**AC-F010-003 / 候選和醫院定製狀態不被升級。** 保留各自審核/驗證/准入狀態及適用機構/病種/版本；通用、醫療域、醫院定製可辨，接收方不能把導出噹噹地生產批准。 由 delivery/status.py、manifest.py、documentation.py 承接，以 資格/來源性質與導出狀態保真測試 檢查；資產狀態、限制和未放行記錄 是必須保存的結果，不以界面提示或接口返回成功替代。

**AC-F010-004 / 生成與重試不發佈半成品。** 只讓同基線完整提交結果可見，失敗保留最小原因/範圍；同操作不重複產生有效交付記錄，同鍵衝突拒絕，審計失敗不給完整成功。 由 delivery/build.py、jobs.py、repository.py 承接，以 資源/元數據提交邊界故障與冪等測試 檢查；臨時/已發佈狀態、摘要/操作ID和對賬結果 是必須保存的結果，不以界面提示或接口返回成功替代。

**AC-F010-005 / 接收檢查發現篡改、缺依賴與不兼容。** 合法範圍可定位來源/版本/說明；錯誤或缺依賴給出明確限制，不默默丟字段或自動激活語義/規則；核對成功也不代表醫學效果通過。 由 delivery/verify.py、compatibility.py 承接，以 完整性/依賴/Schema 的受限接收檢查 檢查；逐資產核對結果、可復現條件與拒絕原因 是必須保存的結果，不以界面提示或接口返回成功替代。

**AC-F010-006 / 下載與撤權遵守當前範圍。** 當前授權/用途/期限仍有效才讀取，ID/舊鏈接不作為永久許可；不暴露服務器路徑或其他病例信息，保留導出/下載歷史而不宣稱自動收回外部副本。 由 delivery/downloads.py、access.py 承接，以 當前授權/過期引用/撤權下載測試 檢查；實際下載範圍、拒絕與訪問審計 是必須保存的結果，不以界面提示或接口返回成功替代。

**AC-F010-007 / 資產查看與交接說明可操作。** 清單/計數/詳情同源，來源/狀態/版本/不含項可讀；階段真實、禁用原因明確；有中文重現/依賴/許可說明，不把模型或部署秘密放進產品界面。 由 delivery/query.py、documentation.py、正式資產界面 承接，以 代表資產選擇/受限導出旅程走查 檢查；可讀說明、兩視口、實際結果/返回狀態 是必須保存的結果，不以界面提示或接口返回成功替代。

**AC-F010-008 / 與准入/生產者交付同一事實。** 各項都對應真實來源與同一聲明版本，重複事件不造新批准；限制/撤權傳遞到當前下載，歷史原件/意見/簽字不被刪除或改寫。 由 delivery/handoff.py、events.py 承接，以 PG-005 真實生產者→交付消費合同測試 檢查；完整版本/責任鏈、當前限制與接手核對 是必須保存的結果，不以界面提示或接口返回成功替代。

### 上下游與獨立驗證

輸入：指定資產類型與版本、目標用途/接收範圍、F009 的批准或未放行決定、各生產模塊的來源/許可/依賴及驗證狀態、F001 當前導出授權。

輸出：ExportManifest、受控資產文件/引用、中文使用與限制說明、完整性/兼容檢查結果、審計及下載入口；接收方可檢查但不自動獲得本地生產資格。

初次可用顯式合成夾具檢驗字段/狀態和失敗語義；真實連接與業務/專業條件具備後再做組合驗收。對接時固定 request/operation、對象/Schema 版本、允許範圍、狀態/原因和證據引用，當前授權在執行/恢復時重驗。

## 實施順序

1. 核對下列 OQ 與相鄰合同，在項目內固定實際依賴/服務角色；明確合成夾具和正式樣本/用途，先處理實現就緒阻塞。
2. 按 [Tasks](tasks.md) 的局部依賴完成可觀察結果；每步涉及前後端/數據/校驗可一起交付，不按固定時長拆。
3. 為 [F010 用例](../../../evals/F010.json)綁定真實檢查，運行其對應最窄路徑；沒有執行的場景保留未運行，不能勾選任務。
4. 由 T009 彙總局部證據，並在相鄰真路徑具備後執行[產品套件](../../../evals/product.json)相應組合門檻，數據/醫學/身份/生產責任分別核對。

## 回退策略

撤回失敗或已失效包的新下載能力，保留已提交 export manifest、責任記錄和合法歷史；恢復只使用仍獲准的固定版本。臨時資源按無引用和保留條件清理，不刪除原始數據、專家原判或舊簽字。對已獲准下載的外部副本按真實責任約定管理，不聲稱技術撤權能自動召回。

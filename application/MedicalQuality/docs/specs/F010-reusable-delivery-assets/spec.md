# F010 · 醫療資產固化與複用交付規格

## 目標與可觀察結果

把同一固定基線的規則、本體語義/映射、權限模板、評測資產和責任流程交給獲准接收方，使其能理解來源、版本、適用範圍、依賴和驗證狀態，並核對資產完整性。交付不擴大數據授權，不把候選或未驗證資產包裝成已批准產品。

本輪依據用戶“補齊全部方案、Feature 與評估”的授權，在原 Map 邊界內展開。Spec ready 表示業務行為已可據此規劃；Plan draft / Tasks planned 保留尚未取得的運行與專業證據，不宣稱功能已完成。

## 來源與範圍

- 來源需求：REQ-019, NFR-001, NFR-002, NFR-004, NFR-005, NFR-006。
- 來源總規格：PSC-001, PSC-008, PSC-009, PSC-012, PSC-013。
- 本 Feature 包含：資產目錄與依賴、導出用途/許可篩選、固定 manifest、通用/醫療域/醫院定製劃分、受控生成與下載、可重複身份和完整性核對、交接說明及導出責任審計。
- 本 Feature 不包含：不默認打包原始病歷/影像/波形、憑據、個人身份映射或參考答案；不替 F009 批准、不直接部署或激活其他醫院，不為保存交付在普通 Git 添加大 ZIP/模型。
- 產品含義以 [PRD](../../PRD.md)、[Product Spec](../product-spec.md)及 [Feature Map](../feature-map.md#f010) 為準；局部驗收貢獻與產品組合驗收分開。

## 輸入輸出與迭代邊界

- 輸入與前置條件：指定資產類型與版本、目標用途/接收範圍、F009 的批准或未放行決定、各生產模塊的來源/許可/依賴及驗證狀態、F001 當前導出授權。
- 輸出、必要語義與消費方：ExportManifest、受控資產文件/引用、中文使用與限制說明、完整性/兼容檢查結果、審計及下載入口；接收方可檢查但不自動獲得本地生產資格。
- 可獨立調整：本模塊內部組織、查詢與呈現方式，前提是身份/版本、狀態、允許範圍和證據合同不變。
- 需協調上下游：共享對象/版本/錯誤、授權和責任事件變化同步生產者與消費者，不在局部把未判斷改為通過。原始資料與既有原型保持；正式行為由後端事實源提供。

## 功能行為

### 主流程

1. 已有資產和授權時，選擇固定交付基線；展示範圍/依賴/許可/狀態，結果為明確包含與排除，交給導出作業。
2. 基線滿足允許用途時，生成受控交付；保存清單、摘要和限制，結果為只發布完整已提交結果，交給獲准下載者。
3. 合法下載請求時，核對當前權限/用途；按同一清單取資產，結果為下載審計及可核對內容，交給接收方檢查。
4. 資產/權限變更時，重新導出或撤銷新下載；舊清單/責任記錄可查，結果為不漂移舊包身份，交給F009/資產維護者。

### 業務規則與邊界

- 資產同一基線固定版本，不能在生成過程中混用最新規則、本體或評測結果。
- 通用模板、醫療域規則和醫院定製分別說明；模板不攜帶某醫院實際人員權限/憑據。
- 候選/未驗證/未放行資產可在獲准用途下交付但必須保持狀態，不因導出升級專業資格。
- 必要依賴缺失或不可分發時說明受限/不能完整復現，不假稱完整可運行。
- 導出和下載分別核對當前授權；生成過一個包不意味著後續任何人都能訪問。

狀態名稱沿用 PSC 與主責模塊的共同含義；登記/計算/交接完成只說明該環節，不自動錶示專業確認或生產放權。所需技術字段在 Plan 與共享實施合同落實，本文不預填醫學閾值/真實賬號。

## 異常與恢復

| 情況 | 可觀察結果/處理 | 恢復條件 |
| --- | --- | --- |
| 無導出/目標用途權限 | 拒絕範圍外內容 | 修正允許範圍後新申請 |
| 許可/依賴未確定 | 受限或阻斷相應資產 | 核對合法來源/依賴，不以複製繞過 |
| 生成中失敗 | 不暴露半成品 | 按同一基線/操作對賬後重試 |
| 源版本變化 | 保留舊清單，新基線 | 不靜默用新版本替換 |
| 撤權或下載期限過期 | 禁止新下載 | 歷史導出記錄保留；已合法獲得副本按既定責任約定處理 |

## 驗收標準

每項 AC 是本 Feature 的可觀察貢獻；固定夾具驗證機制，真實相鄰模塊與專業材料驗證端到端目標。未實現時用例 check_ref 保持 null。

### AC-F010-001 · 導出固定資產與依賴基線

- 來源：REQ-019, NFR-002, NFR-005, PSC-001, PSC-012
- 對應 PRD 驗收：AC-023, AC-024
- Given 規則、本體/映射、權限模板、流程和評測各有新舊版本，生成中來源可能更新。
- When 選擇並固定交付清單。
- Then 逐資產固定 ID/版本/摘要/依賴/來源，使用同一聲明基線；來源更新不混入舊導出，必要依賴及不一致明確報告。

### AC-F010-002 · 授權、許可和來源角色限制導出

- 來源：REQ-019, NFR-001, NFR-004, PSC-008, PSC-009, PSC-012
- 對應 PRD 驗收：AC-023, AC-026, AC-017
- Given 資產含受限詞表、原始患者資料、參考答案、憑據/真實身份映射和可共享模板，接收用途不同。
- When 生成導出範圍。
- Then 只含當前獲准且許可允許的內容，敏感原件/憑據/答案不默認加入；不能分發的依賴保留說明/允許引用，導出審計可追溯，不繞過評測隔離。

### AC-F010-003 · 候選和醫院定製狀態不被升級

- 來源：REQ-019, NFR-002, NFR-005, PSC-001, PSC-012
- 對應 PRD 驗收：AC-023
- Given 有批准、未驗證、失敗及醫院特定資產，F009 未放行某用途。
- When 導出結構化包和說明。
- Then 保留各自審核/驗證/准入狀態及適用機構/病種/版本；通用、醫療域、醫院定製可辨，接收方不能把導出噹噹地生產批准。

### AC-F010-004 · 生成與重試不發佈半成品

- 來源：REQ-019, NFR-005, NFR-004, PSC-009, PSC-012
- 對應 PRD 驗收：AC-023, AC-024, AC-017
- Given 多文件生成期間中斷、同操作重試或相同冪等鍵不同請求體。
- When 生成併發佈下載結果。
- Then 只讓同基線完整提交結果可見，失敗保留最小原因/範圍；同操作不重複產生有效交付記錄，同鍵衝突拒絕，審計失敗不給完整成功。

### AC-F010-005 · 接收檢查發現篡改、缺依賴與不兼容

- 來源：REQ-019, NFR-002, NFR-005, PSC-001, PSC-012
- 對應 PRD 驗收：AC-023, AC-024
- Given 合法固定包及文件缺失、摘要錯誤、Schema 不兼容、許可/依賴不足的變體。
- When 執行接收方可復現的完整性/兼容核對。
- Then 合法範圍可定位來源/版本/說明；錯誤或缺依賴給出明確限制，不默默丟字段或自動激活語義/規則；核對成功也不代表醫學效果通過。

### AC-F010-006 · 下載與撤權遵守當前範圍

- 來源：REQ-019, NFR-001, NFR-004, PSC-008, PSC-009
- 對應 PRD 驗收：AC-016, AC-017, AC-023, AC-026
- Given 有權用戶生成包後權限撤銷，另有無權者拿到 export_id 或過期下載引用。
- When 請求下載/恢復傳輸或再次查看資產。
- Then 當前授權/用途/期限仍有效才讀取，ID/舊鏈接不作為永久許可；不暴露服務器路徑或其他病例信息，保留導出/下載歷史而不宣稱自動收回外部副本。

### AC-F010-007 · 資產查看與交接說明可操作

- 來源：REQ-019, NFR-002, NFR-006, PSC-001, PSC-012, PSC-013
- 對應 PRD 驗收：AC-023, AC-025
- Given 授權接手者查看長清單、多個狀態/依賴和醫院定製說明。
- When 篩選資產、查看限制、請求生成/下載並返回。
- Then 清單/計數/詳情同源，來源/狀態/版本/不含項可讀；階段真實、禁用原因明確；有中文重現/依賴/許可說明，不把模型或部署秘密放進產品界面。

### AC-F010-008 · 與准入/生產者交付同一事實

- 來源：REQ-019, NFR-001, NFR-005, PSC-001, PSC-008, PSC-009, PSC-012
- 對應 PRD 驗收：AC-023, AC-024, AC-026
- Given F001/F004/F005/F007/F008 資產及 F009 當前決定具備，並有重複/過期交接事件。
- When 從真實生產者組成交付並檢查歷史/當前基線。
- Then 各項都對應真實來源與同一聲明版本，重複事件不造新批准；限制/撤權傳遞到當前下載，歷史原件/意見/簽字不被刪除或改寫。

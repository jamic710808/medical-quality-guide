# F004 · 醫療上下文與病例工作臺規格

## 目標與可觀察結果

讓醫生和質控人員在授權範圍內連續定位同一病例、檢查原始表達與事件關係，並把解析缺口、身份衝突和當前責任狀態帶到後續質控與整改。病例視圖可回查，不因規範化或列表切換製造新的醫療事實。

REQ-003 / S01-04 的字段、段落和事件分散，落實為原值到證據的映射；REQ-004 / S01-10/11 的任務難定位，落實為同源篩選與詳情返回；REQ-014 的責任脫節，落實為消費 F007 已保存的責任節點。具體痛點來源見 PRD 的 S01/S02 登記。

本規格承接用戶選型落盤與必須接入醫療本體的要求：F004 的語義定義、映射、約束及固定版本消費為一期必需，具體實現見[TP-02](../../architecture/technical-points/semantic-query.md#tp-02)；業務邊界沿用 PRD / PSC。ready 表示行為可進入規劃；[Plan](plan.md)為 draft，運行條件尚未驗證，Feature 仍 planned。

## 來源與範圍

- 來源需求：REQ-003, REQ-004, REQ-014, NFR-001, NFR-002, NFR-003, NFR-005, NFR-006。
- 來源總規格：PSC-001, PSC-002, PSC-003, PSC-006, PSC-008, PSC-013。
- 本 Feature 包含：必需應用本體的定義/映射/約束和發佈版本消費，病例/就診身份、文書/字段/事件與時間線、未知/衝突/未關聯、授權集合查詢、列表/詳情/返回、處理結果與責任節點投影，以及給 F005/F006 的固定語義/上下文。
- 本 Feature 不包含：不執行質控規則或專業裁決，不合並無依據患者，不保存另一套整改/簽字狀態；F002/F003 負責來源與解析，F007 負責責任流程。圖數據庫、本體發佈和任意數據庫問答不構成獨立新功能。

## 輸入輸出與迭代邊界

- 輸入與前置條件：F003 EvidenceItem、結構字典、來源/解析版本、允許消費範圍和缺口，已驗證的業務映射，以及 F001 的當前授權；F006/F007 按共享合同提供已保存狀態。
- 輸出、必要語義與消費方：CaseContext、可回查字段/事件/關係、受限集合及瀏覽上下文；F006 取得固定快照，工作臺展示相同病例與責任狀態。關係/映射可獨立優化，但身份、原值、定位與版本變化要同步消費者。
- 可獨立迭代：在上述合同不變時調整內部查詢、映射、檢索或呈現實現；不得靜默改變共享身份、狀態、適用性、原值和證據精度。
- 需要協調的變化：共同對象/版本、權限/用途、失敗與恢復、消費者可用範圍；先更新受影響總規格與 Map，技術細節在 Plan 和共享技術專題維護一處。

## 功能行為

### 主流程

1. F003 證據和授權具備時，構建/更新限定病例上下文；原值、映射、缺口並列，輸出病例與事件能回查，交給F006 或工作臺。
2. 當前授權集合時，搜索、篩選、排序及翻頁；計數和結果使用同一範圍，輸出可進入選定病例詳情，交給查看文書與原文。
3. 病例詳情時，回查證據或返回列表；顯示來源版本、位置精度及返回上下文，輸出可複核或看到明確缺口，交給繼續當前任務。
4. F007 已保存新狀態時，刷新/接收變更；展示當前責任節點與有效版本，輸出不符合篩選的記錄退出並給出定位反饋，交給由對應責任崗位接續。

### 業務規則與邊界

- 來源命名空間、患者、就診、文書和證據身份分開；相似文本、同號或日期接近都不能直接確認同一患者/就診。
- 規範化值回指原表達；未知、缺失、衝突、未關聯分開，未記載不等於未實施。
- 本體/映射/形狀/值集固定為可回查版本；缺少有效基線時限制依賴它的自動消費，保留合法原文/人工路徑。概念定義、文書斷言、患者事實和專業決定不混同；發佈/升級不改寫舊結果。
- 結構化查詢的粒度與集合有依據；事件行數、住院數和患者數不混用。授權過濾同時影響結果、總數、詳情和原文。
- 任務狀態與處理意見由主責模塊提供；當前版本不能繼承舊版本簽字或核驗完成狀態，F004 不自行計算專業合格。

## 異常與恢復

| 情況 | 可觀察狀態 | 系統行為 | 恢復 |
| --- | --- | --- | --- |
| 沒有匹配病例 | 空集合與真實計數 | 保留有效篩選，不顯示系統失敗 | 修改篩選 |
| 授權過期/對象不可讀 | 拒絕且說明允許的恢復入口 | 不洩漏列表統計、詳情或證據正文 | 重新取得有效授權 |
| 字段/時間未知或關係衝突 | 保留原值和未知/衝突 | 限制依賴該前提的消費，不補造事實 | 核查來源或按新版本補充 |
| 來源版本/定位失效 | 受影響上下文不可用或部分 | 不靜默取最新文書替換舊引用 | 從 F002/F003 固定版本後重建 |
| 處理後記錄移出篩選或瀏覽遊標過期 | 真實集合和位置反饋 | 重新定位合法結果，不製造舊狀態 | 保留可複用篩選並刷新 |

## 驗收標準

以下 AC 說明本 Feature 的貢獻。跨 Feature 的最終結果仍需 product 套件組合驗證；固定夾具和消費者替身不能代替真實專業驗收。

### AC-F004-001 · 有據身份與未關聯

- 來源：REQ-003, NFR-002, PSC-001, PSC-003
- 對應 PRD 驗收：AC-004
- Given MIMIC 與 eICU 各含相同編號，兩條文書只具相似文本，另有源聲明的病例/就診關聯。
- When 組織病例和事件關係。
- Then 僅有依據的同命名空間關係被關聯；相同編號、相似文書與缺就診記錄仍明確未關聯或待核實，源標識不改寫。

### AC-F004-002 · 原值、時間與單位不被吞併

- 來源：REQ-003, NFR-002, PSC-003
- 對應 PRD 驗收：AC-004
- Given 字段含空白、0、未知、偏移日期、相對時間、缺單位，以及患者/家屬、否定/假設、歷史/當前等跨段語境差異。
- When 生成規範化字段與時間線。
- Then 原值與解釋依據可回查，主體/否定/時間/條件及未知/衝突分別保留；家屬、歷史或假設不被合併為患者當前事實，不恢復真實日曆或把未記載當未實施，不可比較時間不被強排成確定順序。

### AC-F004-003 · 結構化結果粒度與授權範圍一致

- 來源：REQ-003, REQ-004, NFR-001, NFR-002, PSC-003, PSC-008
- 對應 PRD 驗收：AC-004, AC-005, AC-026
- Given 一人多住院、一次住院多個檢查，部分記錄無就診號；主體只可查看其中兩個病例。
- When 查詢病例/事件集合及數量。
- Then 結果和數量使用相同授權與粒度，未知關聯不被靜默丟棄；不以檢索片段估算完整集合，不返回範圍外對象。

### AC-F004-004 · 列表定位與桌面入口可操作

- 來源：REQ-004, NFR-006, PSC-013
- 對應 PRD 驗收：AC-005, AC-025
- Given 授權病例跨多個列表頁，在 1280×800 和 1440×1000 視口包含長名稱與風險提示。
- When 搜索/篩選/排序後翻頁並進入詳情。
- Then 列表、計數及順序一致，主要動作可達；風險有文字、處理中/失敗有真實反饋，不能只用原型固定頁數模擬規模能力。

### AC-F004-005 · 崗位處理後接續同一任務

- 來源：REQ-004, REQ-014, NFR-006, PSC-006, PSC-013
- 對應 PRD 驗收：AC-005, AC-018, AC-025
- Given 用戶從篩選列表進入病例；F007 已保存改派或整改後的新狀態，記錄可能不再滿足原篩選。
- When 消費新狀態並返回列表。
- Then 詳情、列表、統計與當前責任節點反映同一已保存結果，保留有效瀏覽條件；退出篩選時給出可定位反饋，不把通知當處理完成。

### AC-F004-006 · 解析缺口在上下文中保持可見

- 來源：REQ-003, NFR-002, NFR-003, PSC-002, PSC-003
- 對應 PRD 驗收：AC-003, AC-004, AC-009
- Given F003 返回可用段落、定位缺失和未解析文書。
- When 顯示病例並向質控交接。
- Then 可用部分保留，缺口及影響範圍傳遞；部分病例不顯示全量資料完備，也不由 F004 作臨床通過判斷。

### AC-F004-007 · 更新上下文不改寫歷史

- 來源：REQ-003, REQ-014, NFR-002, NFR-005, PSC-001, PSC-003, PSC-006
- 對應 PRD 驗收：AC-004, AC-015
- Given 舊上下文已被質控運行引用，新的文書或語義映射改變關聯/時間解釋。
- When 形成新上下文並展示當前狀態。
- Then 新舊版本可區別回查；舊運行保留舊輸入，當前視圖不繼承舊完成/簽字；不覆蓋歷史意見或原件。

### AC-F004-008 · 交接對象可回到實際證據

- 來源：REQ-003, NFR-002, PSC-001, PSC-003
- 對應 PRD 驗收：AC-004, AC-008
- Given 一個上下文含有據字段、事件、衝突及原始附件，並有不兼容的輸入合同版本。
- When F006 合同消費者取得病例上下文並回查。
- Then 可取固定範圍的證據與未知/衝突；無來源支持不生成關係，不兼容版本明確拒絕；消費者替身通過不等於醫學判斷已通過。

### AC-F004-009 · 必需本體與可回查語義基線

- 來源：REQ-003, NFR-002, NFR-003, NFR-005, PSC-001, PSC-002, PSC-003, PSC-008
- 對應 PRD 驗收：AC-004, AC-009, AC-024
- Given 限定工作負載、來源字段和專業定義候選，含無依據、歧義及不同語義版本。
- When 建立並消費病例語義基線。
- Then 必須有可審閱定義、關係、映射/約束及來源和固定版本；本體不存在、未獲準或關鍵語義不明時限制依賴消費，不把字段字典當患者事實、也不以無本體路線聲稱完成；原文/人工路徑保留，舊解釋不漂移。

### AC-F004-010 · 語義建設、適配與運行權限分離

- 來源：REQ-003, NFR-001, NFR-002, NFR-003, NFR-005, PSC-001, PSC-003, PSC-008
- 對應 PRD 驗收：AC-004, AC-016, AC-026
- Given 語義候選格式、目標產品合同或工具能力不一致，且原生建設空間有自己的活動版本。
- When 轉換候選、發佈或請求運行語義。
- Then 類/實例、關係方向、等價/近似與條件分別核對，無法支持/有損轉換明確缺口而不偽造；原生工具支持或活動版本不自動成為產品批准，運行身份不能構建/演化/發佈；當前授權和固定版本約束持續成立。

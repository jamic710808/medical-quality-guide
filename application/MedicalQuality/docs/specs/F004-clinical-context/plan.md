# F004 · 醫療上下文與病例工作臺實施計劃

## 2026-10-14 實施更新

用戶 U10 已授權持續開發。本 Feature 的軟件已落地：命名空間與未關聯病例、臨床斷言、固定上下文、受控結構查詢、OWL/SHACL 包與原生語義橋接。 實際文件為 `backend/medical_quality/clinical_context/context.py`、`backend/medical_quality/clinical_context/query_catalog.py`、`backend/medical_quality/ontology.py`、`backend/medical_quality/native_semantic.py`。為保持模塊化單體簡單，下文最初規劃的多個職責文件合併在這些模塊中；它們不是另有待創建的第二實現。Spec 的業務語義不變。工程前置已有實測，Plan ready 不等於專業或完整驗收通過。逐用例結果與剩餘組合見[當前實現記錄](../../verification/F004-implementation.md)。28 個應用概念為工程基線；外部臨床詞表及專業等價映射未啟用，不能稱醫學本體已獲專業批准。

下文“現有上下文/擬建模塊”保留原設計階段背景；當前工程狀態以本節和實際文件為準。

## 現有上下文與複用

- 當前產品 backend 為空，frontend 只有品牌資源；靜態 Apple 風格原型僅作為已驗證交互輸入，不是正式授權、版本或存儲實現。
- 複用 F003 的證據/覆蓋合同與現有數據說明；複用 Product Spec 的共同對象和狀態，不另造醫學規則或責任決定。
- [一期技術決定](../../architecture/knowledge-retrieval.md)固定本次路線；本 Feature 的具體技術點是 [TP-01](../../architecture/technical-points/semantic-query.md#tp-01)、[TP-02](../../architecture/technical-points/semantic-query.md#tp-02)、[TP-09](../../architecture/technical-points/quality-orchestration.md#tp-09)。技術專題為細節事實源，本文負責實施歸屬和驗證映射。

- 當前 設計階段 Plan 原為 draft：已給出實現路徑和任務，但下列技術開放項尚未完成實際核查。Spec ready 和任務已列出都不等於開始實現或專業驗收通過。

## 實現方案

採用 TP-01 的源 sqlite3 只讀查詢及範圍過濾，核對真實鍵/粒度，再實現 TP-02 的必需應用本體、源綁定、原值與上下文快照。正式應用狀態用 PostgreSQL，React/TypeScript/Vite 工作臺經 FastAPI 消費同源列表/詳情/狀態；不重寫原始庫或靜態原型。框架、事務和臨床語境的細節見 [FA 基線](../../architecture/architecture.md)及 [TP-13～16](../../architecture/technical-points/platform-and-clinical-contracts.md)。

### 本體必需接入的實施細化

按[本體專項](../../data-preparation/governance-cleaning-handoff.md#ontology)在 clinical_context/ontology/ 承接本地 OWL 2 EL 定義、術語/映射/數據綁定、SHACL 和固定外部導入；ROBOT/ELK 與 RDFLib/pySHACL 負責離線核對，PostgreSQL 存只讀語義投影與發佈引用。原始病例和人工責任仍在原業務模塊；不增加獨立三元組服務或任意診斷推理。

- T001/T002 固定 OC/OR/OS 定義、中文概念卡、原字段/斷言映射及專業依據；候選與發佈分別保存。
- T007 固定 SemanticRelease 與 mapping/shape/value-set/依賴摘要、投影發佈和升級影響；舊上下文不漂移。
- T003/T006/T008 接本體定義/映射/值集/約束查詢，CaseContext 和 F005/F006 消費固定版本；缺版本、歧義和未審核映射返回受限，不繞過本體。
- T009 取得 CQ-01～14 的真實檢查與專業核對證據。例子或 Schema 通過不替代 OWL profile、SHACL、中文映射及端到端消費驗證。

F004 的語義發佈依據來自業務/數據/專業責任者，不依賴 F005 質控規則已經執行；F005 消費已發佈本體，避免互相成為建設前置。evo-semantic 僅按原生五類 Schema 提供候選/發現 adapter，非本體必需能力的替身。

### Skills 建設與 Agent 消費的交接

按[SB-01～12 構建步驟](../../data-preparation/governance-cleaning-handoff.md#semantic-skills-build)核對本地 build/explore/evolve-ontology 的真實 Core/MCP 接口，複用指定工作區/已有版本；沒有工具時不偽造配置和結果。T001/T002 的產品 adapter 記錄原生五類對象到本體包的映射/有損或缺口，T007 區分原生 active、SemanticRelease 和只讀投影；T008 提供[8.24 固定語義工具合同](../../data-preparation/governance-cleaning-handoff.md#agent-semantic-graph)並核對當前授權/版本/狀態。

原生髮布或演化 Accept 不自動激活產品本體；F006 調用當前批准 release，不在病例請求裡構建/演化。T009 結合現有 AC 取得 ASV-01～12 中由本 Feature 承擔的實際證據；構建回放不替代獨立專業驗收。

### 上下游對接

輸入：F003 EvidenceItem、結構字典、來源/解析版本、允許消費範圍和缺口，已驗證的業務映射，以及 F001 的當前授權；F006/F007 按共享合同提供已保存狀態。

輸出：CaseContext、可回查字段/事件/關係、受限集合及瀏覽上下文；F006 取得固定快照，工作臺展示相同病例與責任狀態。關係/映射可獨立優化，但身份、原值、定位與版本變化要同步消費者。

共享技術字段、數據流和版本見技術決定的“共同內部接口”。模塊可用固定合同夾具獨立驗證；真實組合需相鄰能力具備，不能把 Mock 通過寫成完整產品通過。正式框架按 FA 基線實現，目標身份/部署與真實接口仍須核驗，不增加對外 HIS/SDK 接入。

### 逐結果實施要點

- **AC-F004-001 / 固定命名空間與關聯證據規則**：僅有依據的同命名空間關係被關聯；相同編號、相似文書與缺就診記錄仍明確未關聯或待核實，源標識不改寫。 具體改動位於上表模塊，使用身份/關係反例集合測試驗證。
- **AC-F004-002 / 形成帶不確定性的字段、時間線與斷言**：原值和轉換依據可回查，未知/衝突保留；不恢復真實日曆或把未記載當未實施，不可比較時間不被強排成確定順序。 具體改動位於上表模塊，使用字段/時間/斷言語境測試驗證。
- **AC-F004-003 / 交付受控只讀查詢與集合口徑**：結果和數量使用相同授權與粒度，未知關聯不被靜默丟棄；不以檢索片段估算完整集合，不返回範圍外對象。 具體改動位於上表模塊，使用授權集合與獨立預期結果對照測試驗證。
- **AC-F004-004 / 實現同源病例列表與詳情入口**：列表、計數及順序一致，主要動作可達；風險有文字、處理中/失敗有真實反饋，不能只用原型固定頁數模擬規模能力。 具體改動位於上表模塊，使用一次代表旅程瀏覽器走查驗證。
- **AC-F004-005 / 接續 F006/F007 已保存結果**：詳情、列表、統計與當前責任節點反映同一已保存結果，保留有效瀏覽條件；退出篩選時給出可定位反饋，不把通知當處理完成。 具體改動位於上表模塊，使用狀態投影與返回路徑走查驗證。
- **AC-F004-006 / 傳播覆蓋與受限上下文**：可用部分保留，缺口及影響範圍傳遞；部分病例不顯示全量資料完備，也不由 F004 作臨床通過判斷。 具體改動位於上表模塊，使用部分覆蓋合同測試驗證。
- **AC-F004-007 / 固定上下文快照與變化影響**：新舊版本可區別回查；舊運行保留舊輸入，當前視圖不繼承舊完成/簽字；不覆蓋歷史意見或原件。 具體改動位於上表模塊，使用版本變更與舊引用回放測試驗證。
- **AC-F004-008 / 交付穩定 CaseContext 與回查合同**：可取固定範圍的證據與未知/衝突；無來源支持不生成關係，不兼容版本明確拒絕；消費者替身通過不等於醫學判斷已通過。 具體改動位於上表模塊，使用最小消費者與定位回放合同測試驗證。

### 本體交付的獨立結果

AC-F004-009 由 ontology/ 的候選/定義/映射/形狀/固定發佈和 snapshots 承接；T010 交付可核對本體包，包含真實形式檢查與專業狀態。AC-F004-010 由 native adapter、語義只讀服務與轉換/權限合同承接；T011 交付無歧義/有損/不支持結果、原生與產品版本隔離及真實工具能力檢查。具體策略沿既有本體專題，不另造本體 Schema。兩任務可先在受限候選上驗證，正式激活由 T007 固定發佈/當前資格。

## 回退策略

保留原始數據、固定版本與既有有效入口。新映射/索引/模型輸出驗證失敗時隔離受影響結果，舊版本只用於仍有效且獲授權的範圍；不能通過回退恢復已失效規則、已撤銷權限或當前簽字。中斷/錯誤保留最小診斷與真實未完成範圍，不做全工作區破壞性回滾。產品原型繼續獨立運行。

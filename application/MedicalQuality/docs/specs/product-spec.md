## 3. 產品對象與職責

<a id="psc-001"></a>
### PSC-001 來源與統一證據對象

來源版本記錄“來自哪裡、以何種授權和用途取得、對應哪個不可混淆的版本”。文件使用文件身份及內容版本；數據庫使用來源命名空間、表/結構身份、讀取範圍和數據快照身份。僅有讀取時間而沒有一致快照保證時必須說明一致性邊界，不能宣稱獲得整庫同時刻快照。

統一證據對象 `EvidenceItem` 的共同語義如下。它是下游消費合同，不要求把數據庫所有行塞進一個大對象，也不要求丟棄解析器原生結構；具體序列化、Schema 工具及存儲方式由後續設計決定。

| 信息組 | 共同語義與必需區分 |
| --- | --- |
| 身份與類型 | 對象身份、來源版本和內容類型；區分文檔/段落、表格、記錄、數據庫結構與附件 |
| 來源和位置 | 來源對象、文件/快照版本、記錄/字段或頁/段定位；沒有位置時記錄缺失與原因 |
| 內容與原值 | 原始值或可回查引用，保留層級/表結構、字段類型及原表達；規範化值另存並回指原值 |
| 原生結構 | 保留原始文件和原生解析結果的關聯；統一字段不足表達合併單元格或專有結構時不丟棄 |
| 解析過程 | 本次讀取/解析身份、工具或模型版本、配置與變換記錄；不等同醫學判斷 |
| 覆蓋與質量 | 完整、部分、失敗、阻斷、無法判斷、定位缺失等狀態及所影響的範圍 |
| 來源用途 | 公開脫敏醫院記錄、文獻病例、合成材料、授權生產記錄分別標識，不因轉換改變用途或許可 |

必需區分的格式定位：數據庫使用快照/表/記錄鍵與字段；無可靠主鍵時只聲明快照內定位，不製造跨版本唯一身份。CSV 使用邏輯記錄及字段而非誤用物理文本行；Markdown 保留原文行/段及轉換映射；JSON/JSONL 保留對象路徑、數組位置或邏輯記錄；PDF 保留可取得的頁碼/邊界框及座標語義，OCR 文字位置不得冒充原文件字節偏移。

<a id="psc-003"></a>
### PSC-003 病例與醫療上下文

按 PRD U07/DEC-010，一期語義能力必須接入醫療質控應用本體：定義、映射、關係/約束和來源可回查，F004～F006 固定使用匹配的本體/映射/形狀/值集版本。缺少有效版本或關鍵語義未確定時限制依賴消費，不能無本體運行卻稱完成；獲授權原文查看和獨立人工路徑保留。概念定義、來源主張、患者事實和專家決定分層；具體結構見[本體專項](../data-preparation/governance-cleaning-handoff.md#ontology)。

| 對象 | 身份與關係 | 負責 | 不負責 |
| --- | --- | --- | --- |
| 病例/就診 | 來源命名空間下的患者、就診標識及必要對應依據 | 組織同次就診的授權文書與當前任務 | 僅憑同名、相似文本或日期合併身份 |
| 文書版本 | 病例關係、文書身份、版本和原始內容 | 保留正文、字段、段落與版本鏈 | 覆蓋原始資料或恢復未經證實的真實日期 |
| 醫療上下文 | 字段、時間表達、檢查結果和事件到 EvidenceItem 的有據關聯 | 提供結構化視圖、原表達和不確定性 | 把待核實關係或模型解釋提升為已確認事實 |

原始病例來源保持只讀。醫生提交的整改版本屬於工作臺內的新文書版本，有明確父版本和責任人；HIS/原庫回寫不在本期範圍。原型的固定字符串匹配與會話狀態不構成此合同的正式實現。

<a id="psc-014"></a>
### PSC-014 原生圖譜對象與顯示合同

知識圖譜工作臺完整承接用戶指定 Ontology-Playground 的原生圖譜與設計器能力。原生搜索、路徑、節點/關係檢查、主題、格式與佈局等實際交互須可核對；純圖片、外觀仿製或簡版嵌入不能代替完成。來源能力清單與實現邊界見[原生集成決定](../architecture/ontology-playground-integration.md)，不將上游演示視為醫療能力已經成立。

| 共享對象/行為 | 約束及主責 |
| --- | --- |
| 圖譜視圖 | 由獲授權的固定語義/病例/文書/規則/問題版本生成的顯示投影，F011 主責；不是新的醫學事實源或正式推理庫 |
| 概念、實例、斷言、證據、問題、意見 | 保留原對象身份與層次；定義來自 F004，知識/規則來自 F005，問題來自 F006，責任意見來自 F007；圖位置/連接不作新診斷 |
| 關係與路徑 | 顯示原有方向、依據、明確/推導/候選與已知基數；未找到路徑只說明當前範圍，未知不填默認事實 |
| 證據和版本 | Inspector、畫布、原文和規則詳情使用同一版本集合及當前授權，歷史不漂移；覆蓋/定位/有損映射缺口可見 |
| 本體編輯候選 | 原生 Designer 可建/改/驗證/預覽/保存/提交；候選由 F004 同一建設與審核事實源承接，保存/原生 Validate 不發佈正式語義或修改病歷 |
| 導入/導出 | 可交換原生子集、顯示投影和完整正式包區分；完整 OWL/SHACL 仍保留原包，Turtle/複雜公理不能被前端默默裁剪，實例不轉 OWL 類 |
| 授權/域/責任 | 搜索、鄰居、統計、路徑、詳情、鏈接、候選與導出均受 F001 當前授權；公共分享/提交不承接患者數據，必要動作按 PSC-009 留痕 |
| 平臺操作 | Apple 式簡潔殼與完整原生圖並存，病例/規則入口直達相關對象，返回保留任務；故障恢復不切斷原合法原文/人工流程，也不豁免圖譜驗收 |

F011 消費既有合同，不改變 EvidenceItem、SemanticRelease、質控結果或簽字的事實源。原生草稿狀態與批准語義版本分開。中文名稱、外部 IRI、類/實例與關係基數轉換不能為了圖組件可渲染而破壞源語義；無法表達時保留缺口及原始依據。

<a id="psc-005"></a>
### PSC-005 問題與證據層次

問題屬於一次固定輸入及依據版本的質控運行，關聯明確的病例/文書和規則範圍。問題記錄至少表達：類型、建議嚴重度、人工確認嚴重度、規則與知識版本、原文定位/片段、理由、整改建議、產生環節、複核狀態和當前責任節點。未知字段保留未知及原因，不能為滿足必填項偽造內容。

來源事實、規則判斷、模型推斷和專家結論分層保存與展示；每層明確來源、產生者與版本。確定性/風險信號記錄校準狀態及適用範圍，僅輔助分流，不能據一個高分繞過人工責任或證據缺口。

<a id="psc-010"></a>
### PSC-010 評測參照

評測批次凍結樣本、來源類別、文書、規則、知識、模型/解析配置和評測口徑。雙人原判屬於兩個不同且具權限的複核者；仲裁是追加裁決，不能覆蓋原判。同一身份重複寫入不能計為雙人獨立複核。樣本內容在工作流中更新時，原批次仍回查凍結版本，另建後續批次檢驗新版本。

<a id="psc-012"></a>
### PSC-012 交付基線

交付基線由已選定版本的規則包、權限模板、評測結果和責任流程組成，附適用範圍、來源/許可、審核與驗證狀態。失敗或尚未驗證的資產可以按授權交付，但必須保持對應狀態，不能因導出成為已批准資產。基線與生成的導出文件關聯，其他項目不得把醫院特定規則自動作為通用標準。

## 4. 全局狀態與生命週期

<a id="psc-002"></a>
### PSC-002 接入與解析生命週期

| 對象/當前狀態 | 觸發與前置條件 | 允許結果 | 失敗與恢復 |
| --- | --- | --- | --- |
| 來源待登記 | 授權明確且類型可識別 | 已登記，固定來源版本與用途 | 無授權拒絕；類型/結構不明記錄原因，不默認解析成功 |
| 已登記/待解析 | 明確本次範圍和輸入版本 | 處理中 | 輸入無法讀取進入失敗或阻斷 |
| 處理中 | 逐項完成讀取、結構保留和定位 | 完成、部分成功、失敗或阻斷 | 覆蓋不足不得顯示完整成功；未知總數標明未知 |
| 部分成功/失敗/阻斷 | 相應條件補齊且授權仍有效 | 對受影響範圍重新處理併產生可識別運行結果 | 可複用未受影響結果；不重複登記同一有效輸出或改寫原件 |

“解析完成”僅說明本次聲明範圍已處理，不代表臨床事實正確、所有內容適用或整份病歷合格。具體不支持的格式、掃描/加密/損壞內容和定位缺口均屬於覆蓋結果。

<a id="psc-004"></a>
### PSC-004 規則與知識生命週期

候選 → 專業審核 → 特定用途/範圍可用 → 生效或失效。離線驗證可顯式選擇候選版本，但生產用途必須符合實際審核、生效與適用條件。無審核記錄或範圍不明時不得跳過到生產可用。

發佈、批准、業務生效、系統加載和失效時間語義不同。每次質控與再核驗固定輸入及依據版本；更新不能靜默改寫舊結果。依據失效或適用性改變時，受影響的當前結果標為需重新核驗/不適用，歷史結果保留當時條件。

<a id="psc-006"></a>
### PSC-006 責任任務與爭議流轉

任務明確處理範圍及其問題集合、當前病例/文書版本與責任人。任務結論與病例彙總分別表達；存在未處理事項時，不因某個任務結束就顯示整份病例已完成。

| 當前狀態 | 觸發者與動作 | 前置條件 | 結果 | 異常/退出 |
| --- | --- | --- | --- | --- |
| 待質控複核 | 質控確認問題並派發 | 當前版本可訪問，證據與適用條件足夠 | 待醫生處理，記錄意見和責任人 | 條件不足轉阻斷；理由記錄失敗則不聲稱已派發 |
| 待質控複核 | 質控駁回誤報 | 明確不成立依據 | 問題不成立終態 | 保留候選原文，不把整改/簽字階段標完成 |
| 待醫生處理 | 責任醫生提交整改 | 當前對象與崗位範圍匹配 | 新整改版本、待再次核驗 | 拒絕越權及過期版本提交；原始來源不回寫 |
| 待醫生處理 | 醫生提交申訴 | 當前問題與意見可定位 | 爭議複核中 | 原判斷保留，不自動撤銷問題 |
| 爭議複核中/已升級 | 被指派專家裁決 | 必要證據與裁決權限 | 要求整改、問題不成立或爭議升級 | 升級明確下一責任人；未決高風險不進入簽字 |
| 待再次核驗 | 執行檢查並由質控確認 | 最新範圍/版本與依據有效 | 條件滿足後待責任簽字；否則退回整改或阻斷 | 機器運行結束不自動作為專業確認 |
| 任一待人處理狀態 | 獲授權崗位改派、延期或升級 | 留下原因和前後責任信息 | 當前節點繼續，由新責任主體承接 | 截止時間到達只觸發提醒/升級，不代簽或默認同意 |

<a id="psc-007"></a>
### PSC-007 簽字及版本演進

待責任簽字 → 醫生/質控各自確認 → 當前範圍已簽字。兩崗位分別記錄實際簽署身份與權限；同一人或技術支持身份不得冒充另一責任崗位。只有該簽字範圍中的必要複核已完成，且無未解決高風險、爭議、證據缺口或版本失配時，才可進入簽字。

簽字固定病例、文書、質控結果、規則/知識、處理意見、問題範圍和時間；單方完成仍是待另一方。問題不成立是獨立終態，不能顯示為已整改/已簽字。

新文書版本或改變適用性的依據變更，建立新的核驗鏈並重新判斷當前簽字條件。舊簽字與舊範圍保持可查，不繼承或覆蓋。病例彙總僅在本輪聲明的全部必要任務完成後表示“本輪質控處理完成”，不表示疾病診斷正確或病例整體無風險。

### PSC-010 / PSC-011 評測與放權生命週期

評測批次準備 → 樣本與口徑凍結 → 兩份獨立原判 → 一致結果或待仲裁 → 可用於對應範圍的評測記錄。無法判斷及高風險待仲裁不等於通過；修改樣本/依據版本不能原地替換凍結參照。

離線驗證 → 獲授權的限定影子運行 → 人確認的輔助決策。每次轉換形成明確通過或阻斷的准入決定。影子結果不驅動臨床執行或病歷回寫；擴大病種、科室、規則、模型或適用範圍需新一輪相關評估和責任接受。門禁條件失效時暫停受影響能力，退回受控階段或人工路徑，並保留原因與歷史決定。

## 5. 跨 Feature 不變量與共享行為

- **PSC-001 / PSC-002 / PSC-003：原值與身份。** 編號前導零、長整數、空白/零/未知、日期表達與單位按來源語義保留；規範化或清洗另記映射，舊偏移不能定位被改變的新文本。數據庫未聲明的鍵關係、來源之間的患者同一性、未取得的文書內容不得推定為事實。
- **PSC-004 / PSC-005：依據與專業責任。** 規則只能在其用途/範圍內解釋輸入；檢索命中不證明指南適用，規則通過不證明整份病歷合格，LLM 不替代專家確認。嚴重度建議、確認值和風險分流信號分別表達。
- **PSC-006 / PSC-007：原文和簽字不可漂移。** 修改由獲授權醫生提交為新版本；舊原文、意見與簽字仍回查其歷史版本。任務結束、已通知、單條問題處理與全病例當前範圍完成不互相代替。
- **PSC-009：重複與併發。** 一次有效業務操作對應一個可識別結果；重複提交或恢復重試不重複派發、創建同一有效問題或簽字。持有過期版本的操作者必須重新核對當前狀態，不能覆蓋他人的較新結果。這是業務結果合同，不預定事務、隊列或通信實現。
- **PSC-010：指標口徑。** 規則召回按適用且經專業參照確認的機會計算 TP/(TP+FN)；提示誤報佔比使用 FP/(TP+FP)，需要傳統誤報率時另聲明負樣本分母，不能混稱。證據定位、解釋和建議可用性分別記錄專業判斷、分母和不可用原因。
- **PSC-010 / PSC-011：覆蓋與風險。** 無效輸入、範圍外、解析失敗、棄答/人工移交均進入覆蓋說明，不能通過刪除困難樣本提高指標。未執行項不產生實測數字；無法判斷不計為命中或通過。任一已確認高風險漏報阻止晉級，不以平均分抵消；零次觀察漏報不證明總體無風險。
- **PSC-012：導出不改變資格。** 資產包引用版本、適用範圍和驗證狀態；導出不生成專業批准、不延長授權、不默認攜帶原始敏感病歷。相同基線重複導出能識別為同一內容基線，不能構成新的驗收事實。

## 7. 安全、權限、失敗與恢復

<a id="psc-008"></a>
### PSC-008 角色、對象與數據域

角色決定可執行動作，對象屬性進一步限制科室、責任病例、任務指派、用途和期限。無明確身份或授權時拒絕。醫生只處理自己的責任範圍；質控不能代醫生改寫或簽字；專家在獲指派範圍裁決；信息科、管理與供應商的技術/管理職責不自動授予病歷正文權限。

保留期限、數據責任部門、處置方式與保全例外需要明確後才啟用生產策略。未完成身份接入、數據授權或責任接受時，不得用原型崗位切換或默認配置代替實際條件。

## 實現方案

本體是一期必需輸入：消費 F004 的 SemanticRelease/病例斷言和 F005 的規則/值集/知識資格，在既有顯式圖中固定語義解析與約束核對引用。具體合同見[本體專項](../../data-preparation/governance-cleaning-handoff.md#ontology)。ontology/mapping/shape/value-set 不匹配、未映射或必要語義不可用時按現有 Fail Closed 限制受影響檢查；LLM 不批准概念/映射、無權改活動本體。規則結果仍區分適用、覆蓋和條件判定，原文及人工路徑保持。

按 TP-07 的固定規則註冊表與必要輸入執行有限任務；TP-08 選定 Qwen3-4B-GGUF Q4_K_M / llama.cpp 作為本地離線候選模型，輸入只包含允許上下文與依據，結構與引用再次校驗；TP-09 保留四層證據、覆蓋、阻斷與版本依賴。SQL 與知識查詢分別由 F004/F005 承擔，F006 不再複製索引或另建規則批准流程。

### 顯式執行圖與恢復

用 LangGraph StateGraph 實現[SG-01～10](../../data-preparation/governance-cleaning-handoff.md#agent-semantic-graph)：固定授權/輸入與 SemanticRelease，取同版上下文/規則需求，解語義/查詢批准關係，核對形狀與完整性，取依據，執行檢查/必要模型候選，核對支持後保存並交接。graph/schema/run/attempt/thread 和 ontology/mapping/shape/value-set 全部固定；模型不決定跳過規則/本體或開放寫工具。

必要的 quality/semantic_gateway.py 僅適配 F004 只讀合同、返回版本和限制，不新建另一套詞表/推理器；同進程服務為主，確需 MCP 時才按真實 Schema 接受允許工具集。SB 構建/演化接口不進運行工具列表，節點不得用原生 active 隨機替代凍結 release。對空形狀圖、unknown/歧義、無命中分別傳播限制；圖狀態流經服務端允許字段投影后才到 UI。

應用 QualityRun 與 checkpoint 分別持久化，節點可重入、已提交結果按輸入/配置身份複用。取消本次計算不撤銷業務任務；版本不兼容或權限失效受控停止。模型響應丟失可能重複消耗計算，但不得重複發佈有效問題。F007 在自己的責任流程中等待真人決定，F006 只提供固定結果和再次核驗能力。

### 上下游對接

輸入：F004 固定 CaseContext、原表達/關係/覆蓋與語義版本，F005 適用規則/知識與檢索結果，F001 授權範圍；來自 F007 的整改新版本通過原接入鍊形成新上下文。

輸出：QualityRun、逐檢查結果/覆蓋、帶來源與版本的問題候選、事實/規則/模型層次、缺口/阻斷/恢復條件；供 F007 人工處理、F008 專業評測，F004 展示同一已保存結果。

共享技術字段、數據流和版本見技術決定的“共同內部接口”。模塊可用固定合同夾具獨立驗證；真實組合需相鄰能力具備，不能把 Mock 通過寫成完整產品通過。正式框架按 FA 基線實現，目標身份/部署與真實接口仍須核驗，不增加對外 HIS/SDK 接入。

### 逐結果實施要點

- **AC-F006-001 / 凍結質控輸入與用途**：固定實際允許的病例/文書/規則/知識/語義/模型配置；不適用或未授權部分明確拒絕，不從最新視圖暗中換輸入。 具體改動位於上表模塊，使用啟動前置與版本凍結測試驗證。
- **AC-F006-002 / 落實 8 條規則的職責和必要輸入**：逐項輸出條件成立、不成立或無法判斷及證據範圍；不從無檢索命中推斷臨床缺失，不生成診斷或病歷修改。 具體改動位於上表模塊，使用規則處理器的獨立預期夾具測試驗證。
- **AC-F006-003 / 產生受限的跨段語義候選**：模型只返回有來源的疑點與待確認建議，保留主體/否定/時間/條件；必要證據缺失或截斷時明確無法判斷，不自填專家結論、真實診斷或處方指令。 具體改動位於上表模塊，使用固定樣本的結構化候選與支持性核對驗證。
- **AC-F006-004 / 交付可複核的問題與證據解釋**：類型、建議/確認值區別、理由、建議、產生環節和版本可見；四層信息分開，實際定位粒度與失效明確，不能把鏈接存在視為支持主張。 具體改動位於上表模塊，使用問題響應與證據對照走查驗證。
- **AC-F006-005 / 傳播缺口與失敗關閉**：保留未判斷/未執行分母、阻斷原因及受影響範圍；不能以其他項成功判整份通過，授權人工仍可查看與補充材料。 具體改動位於上表模塊，使用混合失敗運行聚合測試驗證。
- **AC-F006-006 / 限制風險信號的用途**：未校準/範圍不符明確表示，不轉成虛假可信百分比；任何分數不能繞過證據缺口、人工複核或高風險爭議。 具體改動位於上表模塊，使用分流信號與禁用條件測試驗證。
- **AC-F006-007 / 實現受影響範圍再次核驗**：變化產生新運行鏈，舊依據不漂移；同一有效請求不重複生成結果，影響不明則核查聲明全範圍，機器通過不等於人工確認或繼承舊簽字。 具體改動位於上表模塊，使用版本依賴與冪等重核測試驗證。
- **AC-F006-008 / 交接同一質控結果與責任前提**：各消費者取得相同版本、證據、覆蓋和阻斷；F006 不代寫複核/仲裁/簽字，未判斷不因交接從評測分母消失。 具體改動位於上表模塊，使用跨模塊結果消費者合同測試驗證。
- **AC-F006-009 / 約束模型能力與失敗數據流**：正文作為數據，模型無改庫/簽字/任意工具權限；未授權外發拒絕，假引用不得發佈為有依據問題，錯誤日誌不復制不必要正文。 具體改動位於上表模塊，使用模型邊界和引用負例測試驗證。

### 新增語義消費驗收的實現

AC-F006-010 由現有 graph/semantic_gateway/preconditions/coverage/evidence_review 落實；T011 將 SG 節點的實際語義返回、形狀範圍、覆蓋和業務三值判斷分開，並證明無本體/錯版本/歧義不被繞過。它複用 F004 服務與 F005 資格，不重複建設本體。T007 在此基礎上核對重放/失效，T010 彙總全部用例。

## 回退策略

保留原始數據、固定版本與既有有效入口。新映射/索引/模型輸出驗證失敗時隔離受影響結果，舊版本只用於仍有效且獲授權的範圍；不能通過回退恢復已失效規則、已撤銷權限或當前簽字。中斷/錯誤保留最小診斷與真實未完成範圍，不做全工作區破壞性回滾。產品原型繼續獨立運行。

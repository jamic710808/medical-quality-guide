### 必需本體的消費

按[本體專項](../../data-preparation/governance-cleaning-handoff.md#ontology)消費 F004 已發佈 SemanticRelease、批准映射和用途值集；版本/資格服務、chunks/retrieval/index_versions 固定該引用，檢索擴展保留原 query 和概念路徑。規則號直達和 BM25/BGE-M3/RRF 保留，不能用本體猜出源證據或讓模型寫活動映射。沒有匹配版本/必要映射時限制該路由，並保留原文查看、未審核規則登記等獨立合法路徑。

F005 完整消費新增 F004 語義基線前置；不依賴 F004 所有界面都已實現，規則候選/來源登記可先按合同推進。形狀、公理和詞表更新的影響傳遞給索引/規則消費者，不復制另一份本體維護源。

### 上下游對接

輸入：F003 的規則/知識 EvidenceItem、來源類別/許可/定位/覆蓋，規則責任人及審核記錄，F001 的動作/數據域授權，以及 F004 的已批准 SemanticRelease、映射/值集和語義接口；檢索請求含用途、範圍、適用時間和所需版本。候選登記/原文查看可獨立推進，完整語義消費必須滿足 F004 前置。

輸出：可選或被拒絕的規則/知識版本、原文與檢索結果、適用/失效/衝突依據、變化影響和基線；供 F006/F008 固定使用，F010 消費已形成資產。

共享技術字段、數據流和版本見技術決定的“共同內部接口”。模塊可用固定合同夾具獨立驗證；真實組合需相鄰能力具備，不能把 Mock 通過寫成完整產品通過。正式框架按 FA 基線實現，目標身份/部署與真實接口仍須核驗，不增加對外 HIS/SDK 接入。

### 逐結果實施要點

- **AC-F005-001 / 建立規則與知識版本目錄**：規則、知識、索引身份分開且有來源；候選不自動生效，舊版本可回查，上游參考不自動成為執行包。 具體改動位於上表模塊，使用版本/狀態轉換合同測試驗證。
- **AC-F005-002 / 執行規則資格與訪問過濾**：只有資格與授權同時滿足的版本可用；不明確條件返回原因和衝突，不能默認選最新或越權讀取。 具體改動位於上表模塊，使用適用性與權限矩陣測試驗證。
- **AC-F005-003 / 保留條款結構與詞法入口**：指定編號/版本不會被相似條文替換；返回支持理解的原文與父上下文、定位和來源性質，不能只返回生成解釋。 具體改動位於上表模塊，使用固定條款索引與回查測試驗證。
- **AC-F005-004 / 交付可核對的混合召回**：命中帶實際模式、原生名次/分數、資格及證據定位；近義不替代適用性，排序分數不變成醫學可信概率。 具體改動位於上表模塊，使用同問題集的基線/混合檢索對照驗證。
- **AC-F005-005 / 明確空結果和受限檢索**：無命中、失敗、資格不明與部分結果分別表達，返回影響範圍；不編造指南、不用其他版本頂替，也不宣稱所需語義覆蓋已完成。 具體改動位於上表模塊，使用空結果/故障範圍測試驗證。
- **AC-F005-006 / 管理索引生命週期與失效範圍**：資格與索引狀態分開；未完整提交不給成功，撤權內容不再進入模型/緩存返回；重試不重複生效，回退不重啟失效依據。 具體改動位於上表模塊，使用發佈/失效與故障恢復測試驗證。
- **AC-F005-007 / 交付版本化規則知識基線**：舊運行仍對應舊版本，原文回查受當前權限；基線包含用途/來源/狀態，不因導出或新版本出現改寫舊資格。 具體改動位於上表模塊，使用歷史引用與資產消費者合同測試驗證。
- **AC-F005-008 / 守住檢索模型的授權域**：未授權提交被拒絕，正文不會進入普通錯誤日誌；語義分支不可用如實返回，不能把本地索引配遠程調用宣稱全程域內。 具體改動位於上表模塊，使用域內嵌入與錯誤路徑探針測試驗證。

## 實施順序

上游治理與檢索視圖按[數據治理專題的 RAG 交接](../../data-preparation/governance-cleaning-handoff.md#rag)落實：資格和當前授權先於索引消費；chunk 保存原文/檢索副本的版本與回映射、父條款/表頭和來源角色，不能跨病例/權限/規則版本合併；部分覆蓋不能用於完整缺失判斷。sources/evidence/cleaning/chunk/embedding/index 依賴用於更新與撤回，回退不能啟用已失效來源。複用現有 AC-F005-001～008 與版本/分塊/檢索任務，不改變 BM25+BGE-M3/RRF、pgvector 或任務狀態。

1. 對照本 Feature OQ 完成必要技術核查，確定依賴/模型 revision、實際接口與可用樣本；補齊已選技術的實施條件再將 Plan 標 ready。當前僅落盤計劃，不下載模型。
2. 按 [Tasks](tasks.md) 的無環依賴逐結果實施，優先穩定對象/版本/範圍，再處理查詢、呈現或候選推斷；不先搭建其他 Feature 的通用平臺。
3. 將真實檢查入口綁定到 [本 Feature 用例](../../../evals/F005.json)，記錄本輪必要結果；未變的有效證據複用。
4. 上下游真路徑具備後執行 [相關組合用例](../../../evals/product.json)，部分組合覆蓋不等於整條業務閉環。F007/F008 的消費屬於後續組合，不成為本模塊建設的反向依賴。

## 回退策略

保留原始數據、固定版本與既有有效入口。新映射/索引/模型輸出驗證失敗時隔離受影響結果，舊版本只用於仍有效且獲授權的範圍；不能通過回退恢復已失效規則、已撤銷權限或當前簽字。中斷/錯誤保留最小診斷與真實未完成範圍，不做全工作區破壞性回滾。產品原型繼續獨立運行。

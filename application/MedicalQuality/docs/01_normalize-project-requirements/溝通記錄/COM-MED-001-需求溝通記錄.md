# 項目範圍與需求溝通記錄

依據[需求來源](../../../../Raw/confirmed-requirements/communication-records/需求溝通與範圍決定.md)整理，供需求分析、方案討論與 Playground 使用。數據範圍和使用條件見[醫療數據說明](../../../../Data/醫療病歷質控/README.md)。

<a id="com-med-001-01"></a>
## COM-MED-001-01 項目目標與本輪交付範圍

來源定位：[原始文件](../../../../Raw/confirmed-requirements/communication-records/需求溝通與範圍決定.md#com-med-001-01)第 10—20 行；依據條目 286, 287, 318。

項目建設病歷質控、證據定位與整改協同 Copilot，複用已有交付骨架，圍繞敏感數據、專業責任和高風險錯誤重新設計方案。

用戶要求直接整理可用於下一階段 Playground 的標準需求文件，並採用實際項目的業務表述。當前交付包括客戶需求、業務約定、本需求溝通記錄，以及由這些資料提煉的 board-data.json。

本輪完成需求資料交接；Playground 頁面、業務實現、運行環境和系統接入按後續任務推進。

<a id="com-med-001-02"></a>
## COM-MED-001-02 一期範圍與實施順序

來源定位：[原始文件](../../../../Raw/confirmed-requirements/communication-records/需求溝通與範圍決定.md#com-med-001-02)第 21—36 行；依據條目 290, 291, 296, 309。

| 約定編號 | 項目約定 | 實施要求 |
| --- | --- | --- |
| DEC-MED-01 | 單一內科病區、成人肺炎住院病例、出院前文書質控 | 先完成有限範圍的閉環，接入前驗證樣本覆蓋與適配 |
| DEC-MED-02 | 8 條文書完整性與一致性規則 | 覆蓋確定性檢查、跨段疑點、證據不足與人工裁決；執行前完成專業審核 |
| DEC-MED-03 | 獨立工作臺優先，API/SDK 與 HIS 內嵌納入接入方案比較 | 先貫通閉環，再確定身份、證據與結果交換接口 |
| DEC-MED-04 | 按崗位分配責任，簽字綁定凍結版本 | 接入前落實具名責任人、身份賬號及簽署權限 |
| DEC-MED-05 | 高風險漏報一票否決 | 其他指標閾值由業務與專業責任人根據評測基線確定 |
| DEC-MED-06 | 區分公開脫敏、合成和生產資料 | 測試輸入保留來源標籤，生產驗收使用相應業務證據 |

“不自動診斷、無人確認不改病歷、Fail Closed、專家責任”是項目業務邊界，不能因接入形式或交付階段變化而放鬆。

<a id="com-med-001-03"></a>
## COM-MED-001-03 交付骨架複用與醫療場景適配

來源定位：[原始文件](../../../../Raw/confirmed-requirements/communication-records/需求溝通與範圍決定.md#com-med-001-03)第 37—47 行；依據條目 286, 316, 317, 318。

實施順序為“已有交付骨架→醫療約束→需調整的變量→驗證證據→可複用資產”。

沿用需求發現、系統調查、證據追溯、評測與門禁的組織方式；重新設計數據域、專家複核、爭議仲裁、責任簽字與放權規則。具體代碼、組件與部署配置在複用前核對接口和適用性。

交付覆盤區分通用流程改進、醫療領域能力與醫院業務定製；形成帶版本、來源和驗證狀態的規則包、權限模板、專家評測資產及責任流程組件。

<a id="com-med-001-04"></a>
## COM-MED-001-04 標準資料交接與待完成事項

來源定位：[原始文件](../../../../Raw/confirmed-requirements/communication-records/需求溝通與範圍決定.md#com-med-001-04)第 48—58 行；依據條目 293, 295, 313, 314, 315。

後續 Playground 直接使用標準資料索引和 board-data.json。三份資料中的穩定編號用於追溯業務需求、約定及範圍決定，頁面圍繞痛點、功能和預期效果展開。

待完成事項包括樣本適配、正式規則/指南審核、授權域與保留期限、具名專家及簽字權限、評測基線與閾值、接入方案、業務驗收及責任接受。每項隨實施推進記錄責任人、結果與證據。

PRD、Product Spec 與 Feature Map 承接需求基線並進一步形成工程合同。需求材料就緒不替代功能開發、評測、簽字或上線驗收。

# 醫療病歷質控需求上下文索引

本目錄保存病歷質控、證據定位與整改協同 Copilot 的項目需求基線，供方案討論與下一階段 Playground 使用。

## 項目範圍與資料狀態

- 一期覆蓋單一內科病區、成人肺炎住院病歷與 8 條文書完整性/一致性規則，優先採用獨立工作臺。
- 客戶需求、業務約定、需求溝通記錄各有一份來源和一份規範化文檔，共 32 個穩定條目。
- 來源主題 286—318 共 33 項均已映射到標準需求與看板行；原始輸入歸檔保留，正文按項目業務口徑組織。
- [醫療數據說明](../../../Data/醫療病歷質控/README.md)提供現有資料範圍、來源和許可；原始病例、影像、心電及數據庫不屬於本次需求規範化對象。
- 樣本適配、規則審核、身份接入、評測、簽字與上線驗收隨實施階段完成，狀態和結果以實際記錄為準。

## Playground 數據入口

[一期需求 Playground](../02_requirement-playground/index.html)已提供標準三列看板，包含字號、行距與留白調節，可離線打開。

[board-data.json](../02_requirement-playground/board-data.json) 使用下游 Skill 的 schema_version 1，包含 14 組“痛點—功能—預期效果”。每行 references 指向標準條目，sources 保留來源相對路徑和 SHA-256。

下游入口：[review-project-requirements](../../../.agents/skills/review-project-requirements/SKILL.md)。從外層工作區執行：

```bash
<USER_HOME>/.local/bin/python3.12 -B MedicalQuality/docs/02_requirement-playground/build.py
```

項目生成腳本複用 Skill 的三列模板，添加 FF Logo 與署名；不要直接改寫輸出 HTML。來源變化時先複核業務行及定位，再更新來源校驗值；14 行是需求關聯，不自動等於 14 個頁面或 Feature。

## 一期約定與實施前置條件

一期範圍及實施順序見 [COM-MED-001-02](溝通記錄/COM-MED-001-需求溝通記錄.md#com-med-001-02)。規則包需要專業審核，運行時按已生效版本和適用範圍判斷。

接入前完成樣本適配、數據授權與保留期限、規則/指南審核、具名專家與簽字權限、評測基線和指標閾值、系統接入及回退安排，見 [AGR-MED-001-14](業務約定/AGR-MED-001-業務約定.md#agr-med-001-14)。

本目錄保留需求背景及來源；當前一期工程合同以已收斂為 confirmed 的 [PRD](../PRD.md)、[產品總規格](../specs/product-spec.md)和[Feature Map](../specs/feature-map.md)為準。背景條目編號不替代正式 REQ/NFR/PSC；來源差異按實際確認關係核對。

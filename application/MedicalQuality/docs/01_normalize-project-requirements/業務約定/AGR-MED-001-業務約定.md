# 醫療病歷質控業務約定

依據[需求來源](../../../../Raw/confirmed-requirements/business-agreements/業務約定.md)整理，供需求分析、方案討論與 Playground 使用。數據範圍和使用條件見[醫療數據說明](../../../../Data/醫療病歷質控/README.md)。

<a id="agr-med-001-01"></a>
## AGR-MED-001-01 產品與責任邊界

來源定位：[原始文件](../../../../Raw/confirmed-requirements/business-agreements/業務約定.md#agr-med-001-01)第 10—25 行；依據條目 287, 288, 289, 299, 314。

系統定位為輔助質控、證據定位與整改協同。系統或供應商不得以工具輸出替代醫生診斷、專家裁決和業務責任接受；沒有人工確認不得修改病歷。當前也未授權任何病歷回寫或生產集成。

| 主體 | 應承擔的職責 | 不自動獲得的權限 |
| --- | --- | --- |
| 責任醫生 | 解釋原始病歷，申訴或提交整改，承擔其簽署內容的責任 | 不能刪除質控意見或代替他人簽字 |
| 質控人員 | 複核疑似問題、記錄依據、核查整改與證據 | 不直接代寫醫生病歷，不把系統建議當作終審 |
| 專家/仲裁人 | 處理爭議、例外、高風險結論並保留理由 | 不以無來源判斷覆蓋原始事實 |
| 信息科 | 維護接入、身份、授權、數據流和運行保障 | 技術管理權限不等於專業裁決或任意病歷訪問權 |
| 管理部門 | 確認業務範圍、組織驗收與責任接受 | 不以經營目標豁免證據缺口或高風險漏報門禁 |
| 系統供應商 | 保證實現與已確認合同一致，提供可追溯、故障與版本支持 | 無默認生產數據訪問權，無專業代簽權 |

<a id="agr-med-001-02"></a>
## AGR-MED-001-02 一期範圍與有限規則清單

來源定位：[原始文件](../../../../Raw/confirmed-requirements/business-agreements/業務約定.md#agr-med-001-02)第 26—45 行；依據條目 290, 294, 296, 309。

一期範圍：單一內科病區，成人肺炎住院病歷，出院前文書完整性與一致性輔助檢查。以下 8 條規則組成候選規則包 MED-QC-v0.1，狀態為待專業審核，生效時間待審核後確定。病種僅用作資料篩選標籤，不設計自動診斷；規則在適用資料齊備且人工確認條件後方可試運行。

| 規則編號 | 檢查主題 | 輸入與可觀察結果 | 邊界/人工處理 |
| --- | --- | --- | --- |
| MQC-DOC-001 | 約定文書或必要段落缺失 | 對照該場景已明確的文書清單，指出缺失項與檢查範圍 | 未配置文書清單時報告無法判斷；不憑空引用法定要求 |
| MQC-DOC-002 | 病例/就診標識不一致 | 顯示衝突字段和來源文書，阻斷跨病例拼接 | 不自動合併身份，交人工確認 |
| MQC-DOC-003 | 文書時間線內部矛盾 | 對照可比較的原始時間表達標記順序矛盾候選 | 時間偏移、相對時間或缺時區時保留不確定性 |
| MQC-DOC-004 | 已提及檢查結果缺少可定位來源 | 從引用文字跳轉結果記錄；缺少時記錄證據缺口 | 只表示當前材料不足，不能斷言臨床未檢查 |
| MQC-DOC-005 | 過敏相關記載跨段衝突 | 並列呈現原文片段和文書版本，供高風險人工複核 | 不決定真實過敏狀態，不自動改寫病歷 |
| MQC-DOC-006 | 診斷名稱或描述跨段不一致 | 標記待解釋的差異與上下文 | 病情演變、鑑別診斷和術語差異須由醫生解釋，不自動診斷 |
| MQC-DOC-007 | 用藥記錄文本要素缺失或互相矛盾 | 指出已有用藥記載的劑量/單位/頻次字段缺失或相互衝突 | 不補造值，不判斷處方是否合理，不給治療指令 |
| MQC-DOC-008 | 作者/簽署/版本記錄缺口 | 對照已約定元數據列出缺口，阻止無責任記錄關閉任務 | 簽署身份、權限及電子簽名方案須按接入要求驗證 |

越出科室、病種、語言、文書清單、版本或規則適用條件的輸入標記範圍外/無法判斷，不自動判合格。影像與心電本期僅可討論附件關聯，不進行影像或波形診斷。

<a id="agr-med-001-03"></a>
## AGR-MED-001-03 數據來源分級與當前材料邊界

來源定位：[原始文件](../../../../Raw/confirmed-requirements/business-agreements/業務約定.md#agr-med-001-03)第 46—56 行；依據條目 291, 292, 293。

每個輸入及派生結果至少保留 source_kind、source_id、source_version、用途與授權範圍。來源類別包括：公開脫敏醫院記錄、文獻病例敘述、合成材料、獲授權真實生產記錄；類別不可僅因複製目錄而改變。

本地現有數據包含公開脫敏結構化醫院記錄、文獻病例、中文質控材料與參考標註、影像和心電；中文參考標註含發佈方模型輔助加工，不是本項目專家金標準。沒有現成真實生產複核、申訴、整改前後版本或簽字證據。

接入前完成中文成人肺炎住院病歷樣本適配，核對文書完整性和流程所需證據。測試需要合成材料時應顯式標記，與生產樣本分開管理；數據使用和分發條件沿用數據 README 中的許可約定。

<a id="agr-med-001-04"></a>
## AGR-MED-001-04 域內邊界、最小化與保留週期

來源定位：[原始文件](../../../../Raw/confirmed-requirements/business-agreements/業務約定.md#agr-med-001-04)第 57—67 行；依據條目 293, 310。

處理域需要明確存儲、解析、檢索、模型、遙測、日誌、備份及導出流向。敏感正文、證據片段、可還原身份的標識、敏感嵌入不默認發送到域外；供應商調試只取得經批准的必要材料。規則和指南訪問同樣檢查所用請求是否夾帶病例內容。

任務只讀取必要字段，普通日誌記錄標識、動作與結果，避免重複保留病歷全文；業務證據快照與審計記錄採用各自權限。數據類別分別制定保留期限、依據、負責人、到期處置和保全例外；具體天數由數據責任部門確認。期限未明確不得宣稱生產留存策略已生效。

到期處置要能處理主存儲、派生索引和備份的適用安排，並保留必要的處置審計；存在經確認的保全要求時走例外流程。以上是設計要求，當前未執行任何刪除或策略變更。

<a id="agr-med-001-05"></a>
## AGR-MED-001-05 原文、結構化值與時間線

來源定位：[原始文件](../../../../Raw/confirmed-requirements/business-agreements/業務約定.md#agr-med-001-05)第 68—78 行；依據條目 292, 294, 302。

結構化單元保留來源文件/記錄、病例與就診標識、文書版本或內容哈希、字段路徑/段落標識、原文片段和可重放的定位。只有能夠驗證的字符範圍才記錄字符偏移；定位失效需顯式報告，不製造精確座標。

規範化術語、日期、單位或關係是派生解釋，必須回指原表達；未知、缺失、衝突和未關聯分別保留。跨患者和跨來源身份不能僅憑相似文本、編號或日期自動合併。時間偏移或相對時間不能恢復成未經證實的真實日曆。

罕見病種、長尾寫法與不足以解釋的事件交專家處理，未記錄不能直接推為未實施。檢索和上下文圖要返回實際取到的來源，不根據模型記憶補出不存在的指南引用。

<a id="agr-med-001-06"></a>
## AGR-MED-001-06 規則與知識版本的適用性

來源定位：[原始文件](../../../../Raw/confirmed-requirements/business-agreements/業務約定.md#agr-med-001-06)第 79—89 行；依據條目 295, 297。

規則記錄 rule_id、rule_version、適用範圍、生效/失效時間、審批狀態和變更理由；知識依據另記錄 knowledge_id、版本、發佈方、來源定位、適用範圍和可訪問正文。時間需區分發布、批准、業務生效和系統加載。

執行前同時判斷輸入是否在範圍內、規則是否已被批准、採用哪個時間口徑。執行結果固定所用病例、規則、知識與模型版本。版本更新產生新運行記錄；舊結論保留原版本，不靜默覆蓋。

目前未引入經醫院專家批准的完整指南正文；2016 年病案首頁 PDF 是參考資料，不能據文件存在認定現行效力或適用於全部場景。發佈方中文規則也須複核。知識不可取得、適用性不明或版本衝突進入人工處理。

<a id="agr-med-001-07"></a>
## AGR-MED-001-07 聯合判斷與 Fail Closed

來源定位：[原始文件](../../../../Raw/confirmed-requirements/business-agreements/業務約定.md#agr-med-001-07)第 90—106 行；依據條目 296, 297, 298, 299, 300, 304, 305。

確定性規則只執行可枚舉的已明確條件；檢索返回依據，不作最終裁決；LLM 輸出候選推斷和建議；專家負責爭議與最終專業判斷。記錄每個結果的產生環節及其輸入版本，不以 LLM 重試或高分覆蓋衝突的規則事實。

| 條件 | 系統動作 | 恢復前提 |
| --- | --- | --- |
| 原文證據不足或定位失效 | 暫停自動推進，顯示缺口及責任節點 | 補充有效材料並重核受影響判斷 |
| 規則/知識衝突或版本適用性不明 | 固定衝突記錄，轉質控/專家處理 | 明確採用的版本與裁決理由 |
| 模型不確定或超出能力範圍 | 標記未判斷或候選，不自動判通過 | 人工解釋或補充可驗證依據 |
| 權限拒絕、解析失敗或服務不可用 | 返回真實失敗與範圍，不做假成功 | 權限/服務恢復後按原版本重新發起 |
| 存在未解決高風險問題或爭議 | 阻斷進入簽字和關閉 | 指派責任人並完成人工複核/仲裁 |

阻斷對象是自動通過、自動回寫、簽字准入等推進動作，不禁止人工查看、補充證據和處理任務。風險/確定性信號需綁定校準集合、方法、版本和適用域，僅用於隊列分流；未校準時明確顯示未校準，不用固定百分比分代替專業確認。

<a id="agr-med-001-08"></a>
## AGR-MED-001-08 質控結論最小證據契約

來源定位：[原始文件](../../../../Raw/confirmed-requirements/business-agreements/業務約定.md#agr-med-001-08)第 107—124 行；依據條目 301, 302, 303, 304, 305。

| 字段組 | 必須表達的內容 |
| --- | --- |
| 結果身份 | 問題 ID、病例/就診、文書與結果版本、生成時間、輸入來源類別 |
| 問題與風險 | 類型、建議嚴重度、人工確認嚴重度、適用範圍、當前狀態 |
| 規則與依據 | 規則編號/版本、知識編號/版本、來源與原文定位、適用理由 |
| 病歷證據 | 字段或段落、原文片段、文書內容哈希、已驗證定位或定位缺失原因 |
| 判斷分層 | 來源事實、規則判斷、模型推斷、專家結論分別標識產生者與版本 |
| 理由與建議 | 可解釋的疑似問題理由、待醫生確認的整改建議、已知限制 |
| 責任與恢復 | 當前責任人、複核意見、爭議/例外、阻斷原因、下一動作 |
| 分流信號 | 校準狀態、適用域、信號來源與版本；不得替代確認 |

“必填”表示必須表達該項是否存在；缺失時填缺失原因並觸發適用的阻斷，不能偽造一個來源。單條結論需能從問題追到具體原文和規則。整改後的新版本與舊結果有明確關聯，原證據不因更新消失。

<a id="agr-med-001-09"></a>
## AGR-MED-001-09 整改工作流與簽字版本綁定

來源定位：[原始文件](../../../../Raw/confirmed-requirements/business-agreements/業務約定.md#agr-med-001-09)第 125—142 行；依據條目 306, 307, 308。

| 當前狀態 | 操作與主體 | 結果與所需記錄 |
| --- | --- | --- |
| 疑似問題/待質控複核 | 質控接受問題或駁回誤報 | 接受後進入待醫生處理；駁回後以“不成立”結案，留理由與證據，不冒稱已整改 |
| 待醫生處理 | 責任醫生接受並整改，或提交申訴 | 整改保存新版本後重新提交；申訴保留原判斷進入爭議複核 |
| 爭議複核 | 質控/被指派專家裁決或升級 | 撤銷問題、要求整改或進入更高層仲裁；記錄依據、責任人與原意見 |
| 待再次核驗 | 按凍結的新版本核驗，由質控確認 | 未通過退回整改/爭議；通過且無阻斷項進入待簽字 |
| 待簽字 | 有權限的責任醫生及複核責任人確認 | 綁定病例、整改、規則、知識、意見及驗收版本，形成已簽字記錄 |
| 已簽字 | 後續新增病歷版本或重開問題 | 新建核驗鏈，舊簽字只適用於舊版本；禁止覆蓋歷史 |

接受、駁回、修改、重提和升級均可追溯。任務含責任醫生、複核人、當前處理人、截止時間及期限來源。逾期只提醒/升級，不自動代簽或視為同意。規則檢查通過不自動觸發簽字，未解決的高風險問題、爭議或證據缺口不能關閉。

簽字接入前需驗證身份認證、簽署權限和電子簽名方案；簽署人、時間及對應版本由實際操作形成。

<a id="agr-med-001-10"></a>
## AGR-MED-001-10 角色與屬性權限矩陣

來源定位：[原始文件](../../../../Raw/confirmed-requirements/business-agreements/業務約定.md#agr-med-001-10)第 143—160 行；依據條目 289, 307, 310。

| 角色 | 允許的任務動作 | 對象/條件限制 |
| --- | --- | --- |
| 醫生 | 查看證據、解釋、接受、整改、申訴和本人簽字 | 被授權的本人責任病例及當前任務；不得刪除複核意見 |
| 質控人員 | 複核、駁回、退回、改派、再次核驗與複核簽字 | 所屬授權科室/任務範圍；不得代寫病歷或代簽 |
| 專家 | 查看必要上下文、爭議複核與仲裁 | 被指派事項及授權期間；結論必須留依據 |
| 信息科 | 管理接入與訪問策略，排查運行故障 | 技術管理範圍；敏感內容訪問另有授權與必要性 |
| 管理部門 | 查看獲准彙總、驗收範圍與責任記錄 | 明細訪問另行授權；不默認擁有所有病歷全文 |
| 供應商支持 | 獲准的診斷信息與運行支持 | 默認無生產病歷權限；按臨時授權目的和期限限制 |

角色允許某動作後，仍需檢查科室、責任病例、任務歸屬、目的與有效期等屬性。禁止跨對象越權、用共享賬號代簽或把前端隱藏當權限校驗。接入前須完成崗位與身份賬號映射，並驗證授權策略。

審計覆蓋允許和拒絕的訪問、查詢/導出、規則變更、改派、意見、狀態轉換與簽字；記錄行為身份、時間、對象版本、前後狀態、理由及關聯請求，日誌不默認含病例全文。

<a id="agr-med-001-11"></a>
## AGR-MED-001-11 評測口徑、雙人複核與高風險否決

來源定位：[原始文件](../../../../Raw/confirmed-requirements/business-agreements/業務約定.md#agr-med-001-11)第 161—181 行；依據條目 311, 312, 313。

| 評測維度 | 口徑與必須報告的信息 |
| --- | --- |
| 規則召回/漏報 | 對適用且經專家形成參照的規則機會，統計 TP/(TP+FN)；按嚴重度與規則拆分，明確機會定義 |
| 誤報與工作負擔 | 同時報告 FP/(TP+FP) 所代表的提示誤報佔比、每份病歷的多餘提示；需要傳統 FPR 時另定義負樣本分母，不混用 |
| 證據定位 | 對所有輸出的問題核查原文、版本、定位和語義支持；缺定位或定位錯不能按可用證據計入 |
| 解釋可用性 | 專家判斷理由是否可理解、與原文及規則一致、能支持複核；保留不可用原因 |
| 整改建議 | 專家判斷是否具體、可執行、不過度延伸，且不自動診斷或給出未經確認治療指令 |
| 安全覆蓋 | 報告範圍外、無效輸入、解析失敗、棄答和人工移交比例，避免只在成功子集計算 |
| 專家一致性 | 雙人獨立原判、分層一致率及爭議分佈；仲裁後的結論與原判分開，不用仲裁一致冒充原始一致 |

分層覆蓋病種/規則、嚴重度、資料來源、長尾寫法、缺失與跨段矛盾；開發示例與獨立驗收樣本分開。已有模型輔助參考標註只能作候選參考，不能直接當本項目金標準。

真實陽性被系統直接判通過且未告警/移交，按漏報處理；棄答/阻斷另報並進入人工處理，不以棄答增加 TP，也不通過刪除棄答樣本提高覆蓋。具體專家口徑在實際標註前凍結。

任一驗收集合中經專家確認的高風險漏報觸發一票否決，阻止晉級/擴大受影響範圍並要求糾正後重驗。未完成仲裁的高風險爭議也不得作為通過證據。其他指標閾值、樣本量和抽樣週期尚未設定；零觀察漏報不代表總體無風險。

## AGR-MED-001-12 產品形態、影子運行與上線門禁

來源定位：[原始文件](../../../../Raw/confirmed-requirements/business-agreements/業務約定.md#agr-med-001-12)第 182—198 行；依據條目 309, 314, 315。

一期以獨立工作臺承載完整閉環，輸入採用授權的離線資料；API/SDK 設計只讀接入與結果交換邊界，HIS 內嵌討論身份映射、上下文、性能和責任分工。當前不生成可執行的醫院回寫契約或上線配置。

| 階段 | 能力與用途 | 進入下一階段的條件 |
| --- | --- | --- |
| 離線驗證 | 用來源明確的公開/合成資料驗證規則、證據和責任流程 | 樣本與適用範圍明確，完成必要評測；不能直接據此生產上線 |
| 限定範圍影子運行 | 在實際授權後旁路觀察，與專業判斷比較；不驅動臨床操作、不回寫 | 凍結範圍和版本，完成專家評測、風險處置與關鍵人驗收 |
| 人確認的輔助決策 | 責任人查看、複核與接受後執行其職責 | 僅在當前批准的範圍運行；擴大範圍另行評估與批准 |

准入/擴大範圍記錄包括病例樣本與應用、規則、知識、模型版本，覆蓋範圍、指標分母和結果、專家複核/仲裁、殘餘風險、關鍵崗位意見、業務簽字與責任接受時間，以及停止條件和回退安排。沒有真實結果時不填“已通過”或虛構簽名。

發生高風險漏報、證據/權限鏈失效或版本不匹配時，停止受影響能力的自動推進並回到人工流程；保留證據，修復後重新驗收。供應商技術可用性不替代醫院業務責任接受。

## AGR-MED-001-14 下游交接與實施前置條件

來源定位：[原始文件](../../../../Raw/confirmed-requirements/business-agreements/業務約定.md#agr-med-001-14)第 214—224 行；依據條目 290, 293, 295, 313, 314, 315。

本批需求材料作為項目需求基線，直接用於需求 Playground 的製作。頁面以業務問題、功能動作和預期效果組織內容，並保留適用範圍、責任分工及阻斷條件。

實施前需由相應責任主體完成：科室/病種/語言和樣本適配、規則及指南版本與生效範圍、敏感數據授權域與保留期限、具名複核/仲裁/簽字權限、評測樣本和指標閾值、接入系統及放權/回退安排。

效果指標在評測後填寫實測值；訪談、驗收、責任接受和簽字按實際執行記錄。尚未完成的環節以待完成狀態跟蹤，不阻塞當前需求看板製作。

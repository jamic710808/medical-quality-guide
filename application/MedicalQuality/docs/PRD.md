## 2. 背景、問題與目標

項目複用已有交付骨架，在敏感數據、專業責任及高風險錯誤約束下建設病歷質控能力。當前問題集中在：多格式資料難以保留原始結構和證據位置；跨段判斷缺少可複核依據；問題發現之後複核、申訴、整改、再核驗和簽字難以銜接；平均分不能支撐安全放權。

目標是讓獲授權人員在有限範圍內定位疑似問題、查看同版本證據、完成責任閉環，並以專業評測與責任接受記錄決定放權。用戶與系統的判斷職責按 S01-01/07 和 S02-01/07 分開。

本地資料的可用性與限制沿用 S05，不能將資料數量、原型樣例或參考標註視為真實效果。具體醫院身份、樣本適配、正式規則、指標閾值及生產授權屬於實施前置條件，見 OQ-003、OQ-005、OQ-006；其缺失時的產品行為已經定義為限制用途或阻斷，不猜補數據或放行。

## 6. 產品範圍

### In-Scope

- 單一內科病區、成人肺炎住院病歷的出院前文書完整性與一致性質控，採用獨立工作臺。
- 數據庫結構與記錄，以及 PDF（文本/掃描）、Markdown、CSV、JSON/JSONL 的讀取與統一證據輸出；原生結構、位置、來源及錯誤覆蓋均保留。其他格式可識別為附件或明確不支持，不冒稱完成解析。
- 8 條候選規則：必要文書/段落、病例身份、時間線、檢查引用、過敏記載、診斷描述、用藥文本要素、作者/簽署/版本。規則執行條件和專業審核範圍沿用 S02-02/06，不擴展為自動診療。
- 證據解釋、工作臺、人工複核、整改/申訴、仲裁、再次核驗、責任簽字、權限審計、專家評測與階段放權。
- 按 U07 必須接入限定醫療質控應用本體，使術語定義、關係/約束、來源映射與版本可回查並供上述流程消費；不擴大到全域醫學圖譜或自動診斷，具體實現由 Architecture/Plan 承接。
- 按 U09 完整採用指定 Ontology-Playground 原生知識圖譜工作臺與設計器，提供本體與術語、病例證據、規則影響的詳細展示和業務聯動；總體簡潔、圖譜表現完整，保留醫療授權/來源/候選審核邊界。
- P1 固化規則包、權限模板、專家評測資產和責任流程；仍屬本期範圍，優先順序晚於核心安全閉環，不標記為已批准延期。

### Out-of-Scope

- 自動診斷、治療決策、未經醫生確認修改病歷、替代專家最終責任。
- 全院全病種擴展、影像或心電自動診斷、將公開/合成數據直接當作生產驗收依據。
- 本期不實施 HIS 內嵌、外部 API/SDK 對接或原系統病歷回寫；保留後續接入邊界，優先把獨立工作臺閉環落實。
- 具體解析器、模型、數據庫產品、部署拓撲、代碼結構與運行成本選型留給 Architecture/Plan。
- 原 U02/U08/U09 的停止點作為歷史保留，已由 U10 的連續開發授權替代。當前軟件已落地，實際驗證與剩餘驗收按開發報告記錄；專業/生產責任不因開發授權自動具備。

## 10. 驗收標準

<a id="ac-001"></a>
### AC-001 · 來源、數據庫結構與記錄可識別

- 來源：REQ-001, NFR-001, NFR-002
- Given 具備授權的數據源，其中包含數據庫表結構、記錄和具有來源類別的文件。
- When 登記來源並讀取聲明範圍。
- Then 表結構與記錄分別可查，保留類型/鍵約束、文件或數據快照版本、來源類別、用途及覆蓋；未聲明的關係標為未知，來源未被改寫。

<a id="ac-002"></a>
### AC-002 · 多格式結果形成統一證據接口

- 來源：REQ-002, NFR-002
- Given 數據庫結構/記錄、文本與掃描 PDF、Markdown、CSV、嵌套 JSON/JSONL 的代表輸入。
- When 完成讀取並輸出解析結果。
- Then 每項結果有穩定身份、內容類型、來源版本、相應位置、原值/結構及解析過程；下游按共同契約消費，格式專有結構仍可回查。

<a id="ac-003"></a>
### AC-003 · 部分解析失敗不冒充完整成功

- 來源：REQ-002, REQ-008, NFR-003
- Given 同一批次中有可讀記錄、損壞內容和無法定位的片段。
- When 執行解析並重試失敗部分。
- Then 保留已成功結果和失敗清單，顯示覆蓋分母及影響範圍；缺失片段不計為完整成功，不靜默刪除或改走未授權外部服務。

<a id="ac-004"></a>
### AC-004 · 醫療上下文保留未知與衝突

- 來源：REQ-003, NFR-002
- Given 已解析的多個文書含長尾寫法、相對時間、缺失及跨段矛盾。
- When 組織病例字段、事件和時間線。
- Then 規範化值可回指原表達；未知、未關聯和矛盾分別保留，無可靠身份依據時不跨病例合併，未記載不被判為未實施。

<a id="ac-005"></a>
### AC-005 · 列表、詳情和崗位接續一致

- 來源：REQ-004, REQ-014, NFR-006
- Given 獲授權的病例集合跨多個列表頁，某個任務可被處理。
- When 搜索/排序/篩選後進入詳情，完成允許動作並返回。
- Then 保留有效瀏覽上下文，範圍計數、列表狀態、詳情和當前責任崗位一致；不再匹配篩選的記錄按新狀態退出結果集並給出可定位反饋。

<a id="ac-006"></a>
### AC-006 · 規則依據按適用版本運行

- 來源：REQ-005, NFR-002
- Given 同一規則存在候選、生效或失效版本，以及範圍不明的知識依據。
- When 選擇運行範圍或更新規則包。
- Then 僅在相應用途許可下使用版本，生產未審核/適用性不明時阻斷；舊結果保持舊版本，新運行記錄新的版本及變更影響。

<a id="ac-007"></a>
### AC-007 · 聯合判斷遵守職責

- 來源：REQ-006, REQ-015, NFR-003
- Given 可枚舉條件、跨段語義疑點與專業爭議並存。
- When 執行質控並展示結果。
- Then 分別說明規則、檢索、模型與專家的職責和輸入版本；只輸出候選問題，不自動診斷或未經醫生確認修改病歷。

<a id="ac-008"></a>
### AC-008 · 單條結論有可檢查證據

- 來源：REQ-007, NFR-002
- Given 一條候選問題使用病歷原文與規則/知識依據。
- When 查看問題及其證據鏈。
- Then 類型、嚴重度建議與確認值、規則版本、理由、建議和定位可見；事實、規則判斷、模型推斷、專家結論分層，引用失效明確顯示。

<a id="ac-009"></a>
### AC-009 · 安全阻斷與恢復

- 來源：REQ-008, NFR-003
- Given 存在證據不足、身份衝突、範圍外、失效依據或未校準確定性信號。
- When 嘗試自動通過、進入簽字或恢復處理。
- Then 相關推進被阻斷並給出責任節點；人工可查看授權材料、補充或裁決，條件補齊後重核受影響項；未校準分數不作為通過依據。

<a id="ac-010"></a>
### AC-010 · 複核結果與駁回含義正確

- 來源：REQ-009, NFR-004
- Given 質控人員查看有完整依據的候選問題。
- When 記錄確認意見並派發，或記錄駁回理由。
- Then 確認產生明確醫生待辦；駁回保留原證據並標記問題不成立，不顯示未執行的整改、再核驗或簽字已完成。

<a id="ac-011"></a>
### AC-011 · 醫生整改產生新版本

- 來源：REQ-010, NFR-002, NFR-005
- Given 責任醫生獲派處理當前版本的問題。
- When 提交修改內容及說明。
- Then 生成新的整改版本和待核驗狀態，原始來源與舊意見不被覆蓋；系統不自行回寫原庫/HIS，未經授權的醫生不能提交。

<a id="ac-012"></a>
### AC-012 · 申訴和仲裁有明確出口

- 來源：REQ-010, REQ-011, NFR-003, NFR-004
- Given 醫生對已確認問題提出異議。
- When 提交申訴，由獲指派專家保留依據後裁決。
- Then 原判保留，結果進入要求整改、問題不成立或爭議升級之一；升級記錄下一責任主體，未決高風險爭議不能簽字或關閉。

<a id="ac-013"></a>
### AC-013 · 再核驗與人工確認分離

- 來源：REQ-012, REQ-008, NFR-003
- Given 整改後形成新的文書版本。
- When 重新執行受影響檢查並由質控人員複核。
- Then 通過、未通過、無法判斷分別表達；未滿足時退回補充，只有人工確認且範圍內無阻斷項才進入待簽字。

<a id="ac-014"></a>
### AC-014 · 責任簽字綁定範圍與雙崗位

- 來源：REQ-013, REQ-015, NFR-004
- Given 當前簽字範圍已完成必要複核，無未解決高風險、爭議或證據缺口。
- When 責任醫生與質控複核人分別確認簽署。
- Then 每個簽署人只能完成自身職責，簽字關聯範圍、文書、規則、結果及意見版本；單方仍顯示待另一方，局部完成不代表整份病歷合格。

<a id="ac-015"></a>
### AC-015 · 新版本不繼承舊簽字

- 來源：REQ-013, NFR-005
- Given 已有簽字記錄的任務出現新的文書或改變判斷適用性的依據版本。
- When 提交該版本並繼續處理。
- Then 建立新核驗鏈，舊簽字留在舊版本與原範圍；當前版本不能顯示為已簽字或沿用舊通過結論。

<a id="ac-016"></a>
### AC-016 · 角色與對象授權同時生效

- 來源：REQ-015, NFR-001, NFR-004
- Given 不同責任組、科室、任務指派和授權期限的身份。
- When 嘗試查看、修改、仲裁、導出或簽字。
- Then 只有角色動作和對象範圍同時滿足才允許；身份/授權缺失或過期拒絕，信息科/管理/供應商不因崗位名獲得病歷正文。

<a id="ac-017"></a>
### AC-017 · 關鍵操作與審計共同可追溯

- 來源：REQ-016, NFR-004
- Given 已有病例、規則、評測及授權範圍。
- When 執行查看/導出/拒絕或關鍵業務變更，並出現審計保存失敗情形。
- Then 正常操作可回查操作者、時間、版本、理由和前後狀態；關鍵變更若缺少責任記錄，不顯示完整成功，並提供可恢復狀態。

<a id="ac-018"></a>
### AC-018 · 改派、延期和逾期不代替責任

- 來源：REQ-014, REQ-016, NFR-004
- Given 任務具有責任醫生、複核人及截止時間。
- When 改派、延期、退回或發生逾期。
- Then 保留理由和前後責任信息，當前處理人可定位；逾期僅提醒或升級，不自動同意、結案或代簽。

<a id="ac-019"></a>
### AC-019 · 雙人原判、仲裁與一致性獨立

- 來源：REQ-017, REQ-015
- Given 固定版本的評測樣本分配給兩名獨立且具權限的複核者。
- When 記錄兩份判斷並處理分歧。
- Then 原始意見、身份和依據保留，分歧需仲裁，仲裁不改寫原判和原始一致性；同一身份重複提交不被計算為雙人獨立複核。

<a id="ac-020"></a>
### AC-020 · 指標保留覆蓋和棄答分母

- 來源：REQ-017, NFR-002, NFR-003
- Given 分層樣本中包含陽性、陰性、失敗、無效輸入與無法判斷。
- When 形成規則、證據、解釋和建議的評測結果。
- Then 各指標有口徑、分母、版本和缺失說明，另報棄答/人工移交及覆蓋；不刪除困難樣本抬高指標，未執行項不顯示數值成果。

<a id="ac-021"></a>
### AC-021 · 高風險漏報和未決爭議否決晉級

- 來源：REQ-017, REQ-018, NFR-003
- Given 驗收範圍存在任一經專家確認的高風險漏報，或未解決的高風險分歧/無法判斷。
- When 進行准入檢查。
- Then 拒絕晉級或擴大受影響範圍並列明原因，修正後重驗；其他平均分或零次觀察漏報不能替代風險判斷。

<a id="ac-022"></a>
### AC-022 · 階段放權與回退受證據約束

- 來源：REQ-018, NFR-003
- Given 請求從離線進入影子運行或從影子進入人確認輔助決策。
- When 檢查固定範圍/版本、授權、正式規則、評測、關鍵人驗收及責任接受。
- Then 全部必要條件明確滿足才記錄批准範圍；缺失或合成資料不能證明生產准入；條件失效停止受影響能力並保留證據回到人工流程。

<a id="ac-023"></a>
### AC-023 · 交付資產可複用且不擴大授權

- 來源：REQ-019, REQ-005, REQ-015
- Given 已有可導出的規則、權限、流程和評測結果。
- When 按選定交付基線導出結構化資產。
- Then 包含來源、版本、適用範圍、驗證狀態和許可/授權說明，區分通用與醫院定製；未批准或未驗證狀態不被升級，原始敏感病歷不被默認打包。

<a id="ac-024"></a>
### AC-024 · 重試與併發不製造新事實

- 來源：REQ-012, REQ-013, REQ-016, NFR-005
- Given 同一確認請求重複提交或兩個操作者持有不同對象版本。
- When 重試操作或基於過期版本提交變更。
- Then 同一有效操作僅有一個可識別業務結果，過期操作提示重新核對而不覆蓋更新；可追溯對應的責任記錄與版本。

<a id="ac-025"></a>
### AC-025 · 桌面工作路徑可操作

- 來源：REQ-004, NFR-006
- Given 目標崗位在 1280×800 或 1440×1000 桌面視口處理較長內容及多頁記錄。
- When 定位對象、查看對照證據、執行允許動作並返回。
- Then 主要內容和動作可讀可達，風險含文字語義，禁用原因及真實處理進度可見；分頁/計數對應結果集，不以假成功掩蓋錯誤。

<a id="ac-026"></a>
### AC-026 · 數據域約束不因工具失敗放寬

- 來源：REQ-001, REQ-002, REQ-015, NFR-001
- Given 輸入包含敏感正文、標識或證據片段，且某處理工具失敗或配置指向未授權端點。
- When 執行、重試、導出或配置生產留存。
- Then 數據留在授權域，未授權外發被拒絕並記錄；留存期限與責任條件未明確時不能啟用生產策略，錯誤日誌不復制不必要的病例全文。

<a id="ac-027"></a>
### AC-027 · 原生圖譜完整且符合平臺使用習慣

- 來源：REQ-020, NFR-006
- Given 用戶指定的原生知識圖譜項目和有代表性的本體/關係輸入，使用 1280×800 或 1440×1000 桌面視口。
- When 在本系統探索、搜索、查看屬性/路徑、切換主題、使用設計器及相應格式功能。
- Then 原生能力及交互深度可逐項核對，不能只模仿外觀或簡版嵌入；簡潔外殼中的主圖、中文名稱、風險、操作與鍵盤路徑可讀可達，大圖限制和恢復真實可見。

<a id="ac-028"></a>
### AC-028 · 圖譜與醫療證據及原工作上下文一致

- 來源：REQ-020, REQ-003, REQ-007, NFR-002, NFR-003, NFR-005, NFR-006
- Given 同一問題有不同文書斷言、規則和本體版本，部分證據缺失或相互矛盾。
- When 從病例或規則進入圖，查關係、路徑和原文，再查看歷史或返回任務。
- Then 概念/實例、來源事實/規則/模型/專業結論分層且不混版本；關係回查真實依據，缺口不被補造；路徑不是醫學推理結論，返回保留原對象、頁籤和列表條件，不改變責任狀態。

<a id="ac-029"></a>
### AC-029 · 圖譜編輯、格式與出域受既有醫療邊界約束

- 來源：REQ-020, REQ-015, REQ-016, NFR-001, NFR-002, NFR-003, NFR-004, NFR-005
- Given 有讀圖、候選維護和導出權限差異，導入物含中文、未支持語義與患者實例，且授權或候選版本可能過期。
- When 導入、編輯/保存、驗證/提交、詳情/鄰居查詢、分享或導出。
- Then 所有入口遵守當前對象授權/許可及審計；未表達語義與未知基數有說明，候選不能直接發佈或改病歷，實例不導成類；鏈接不攜帶病歷載荷，醫療內容不提交公共站/倉庫，過期/失敗不假報成功。

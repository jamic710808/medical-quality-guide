## 本輪驗證條件

工程身份、合成小樣本與真實本地數據庫/組件共同驗證軟件行為。真實資料讀取、OCR、本地模型和原生語義工具另有實際收據，不與測試替身混稱。詳見[彙總報告](development-report.md)。本輪 `pass` 只表示臺賬聲明的工程範圍；不表示生產效果或醫院接受。

復現相關後端檢查（會重建獨立測試庫，不清理試用庫）：

```sh
backend/.venv/bin/python scripts/test_backend.py -q tests/test_evaluation_delivery.py tests/test_workflow_graph.py
```

界面按 `frontend/e2e/` 與最終報告復現；原生組件檢查為 `npm --prefix frontend test`。一次有效結果複用於相關用例，不為每行重複運行整個套件。

## 交接與剩餘條件

直接消費者沿 Feature Map 接收同一版本/權限/證據合同。真實專家、目標病區樣本、獨立參照與專業門檻仍待落實；沒有生成臨床成績。 不讀取參考答案來補造金標準，不填寫默認臨床閾值。

上述未覆蓋組合保留原用例，不刪除要求或把部分執行寫成全套通過。當前軟件可進行本地試用；本 Feature 的最終完整驗收任務仍按臺賬結果保留。

新來源進入評測時，質控人員必須有 evaluation/assign 權限；明確選擇兩名原判者和仲裁者後，只授予選定病例範圍並在同一事務寫入指派審計。專家不能通過創建批次自行擴大權限；生產資料另需真實身份映射。該路徑已通過測試和瀏覽器的新來源病例走查。

# FF - 醫療病歷質控 產品原型

採用淺色、系統字體、藍色主操作和剋制的玻璃側欄。圍繞同一份病例連接質控工作臺、證據、整改版本、規則、專家評測與操作審計。

設計依據：[體驗設計記錄](../03_prototype-design/design.md)。驗看結果：[verification.md](../03_prototype-design/verification.md)。

## 啟動

在 `MedicalQualityCase/MedicalQuality/` 執行：

```bash
<USER_HOME>/.local/bin/python3.12 -B -m http.server 5199 --bind 127.0.0.1 --directory docs/04_frontend-prototype
```

訪問 **http://127.0.0.1:5199/**。端口被佔用時換用空閒端口，不停止其他項目服務；按 `Ctrl+C` 停止當前預覽。

原型使用多頁 HTML、CSS 和原生 JavaScript，無需安裝 npm 依賴或執行構建。通過 HTTP 打開以保持各頁面的同源會話狀態；不將 file:// 作為標準入口。

## 建議體驗順序

1. 默認崗位為“質控人員”。在工作臺搜索、篩選風險、切換頁碼，打開病例後返回；原篩選和頁碼保留。
2. 打開“陳** · 28床 / ZY202610-0281”，對照入院與出院記錄，查看上下文與規則依據，確認問題並派發。
3. 右上角切換為“責任醫生 · A組”，選擇“提交整改”；可點擊“引用入院記錄”填入已有原文，再填寫核實說明並提交新版本。
4. 切換為“質控人員”，開始再核驗並確認結果。再分別切換醫生和質控人員完成各自責任簽字；返回列表可見已簽字狀態。
5. 醫生在已簽字病例中補充新版本時，需要重新核驗；舊簽字留在原版本，不繼承到新版本。
6. “王** · 06床”可體驗醫生申訴與專家仲裁；“李** · 12床”可體驗缺少報告時停止推進、補充報告後重新複核。
7. 在“評測與准入”創建批次，切換“複核專家”，分別記錄兩份原判。出現分歧後進行仲裁，高風險漏報會使准入門禁失敗；原判與一致性統計保留。
8. 在“權限與審計”檢查 A/B 責任組和跨科室訪問邊界，查看之前操作形成的記錄；規則包、權限模板、評測資產和責任流程可以導出 JSON。

“責任醫生 · B組”承接 B組病例，A組醫生不能處理 B組病例。信息科、管理部門和供應商支持不會因崗位名稱自動獲得病歷正文權限。

## 狀態與重置

病例、角色、篩選、意見、簽字及評測保存在當前標籤頁的 `sessionStorage`。同一標籤頁導航與刷新繼續當前操作；其他獨立標籤頁不提供協同同步。

左下角“重置工作區”恢復初始 12 份病例及所有本地狀態。另有 2 份待接入資料用於體驗接入與去重。重置只清除此原型的存儲鍵，不修改源文件、原始數據或其他應用存儲。

## 數據和實現邊界

- `assets/mock-data.js` 集中保存合成病例、文書片段、規則和預置處理狀態；病例界面顯示來源類型。沒有讀取或改寫 `Data/醫療病歷質控/` 的真實資料。
- 再核驗只對預置片段執行固定條件匹配，支持通過、未通過及人工確認的體驗，不是臨床規則引擎、醫學判斷或模型效果。
- 崗位切換與前端動作約束用於表達未來權限和責任流程，不是實際身份認證。責任簽字屬於會話中的操作記錄，不是生產電子簽名。
- 專家評測允許體驗兩份判斷與仲裁，但不能據此證明實際雙人獨立複核或醫學準確率。沒有複核數據時不顯示虛構準確率；合成樣本、未生效規則及未完成業務責任接受始終阻止生產放行。
- 沒有後端、HIS/API/SDK 接入、外部模型、數據庫或網絡數據外發。下載文件是本地生成的 JSON 資產。
- FF Logo 是工程品牌原文件的逐字節副本，方便原型目錄獨立預覽；其原始來源是 `../../frontend/public/brand/ff-logo.png`，不得重繪或改色。

## 文件

| 文件 | 用途 |
| --- | --- |
| `index.html` | 工作臺入口 |
| `case.html` | 同一病例的證據、整改版本、操作記錄與責任處理 |
| `rules.html` | 規則與依據、版本範圍、資產導出 |
| `validation.html` | 雙人複核、爭議仲裁與准入條件 |
| `governance.html` | 權限矩陣、審計、數據域與接入邊界 |
| `assets/styles.css` | 共享視覺與響應式佈局 |
| `assets/app.js` | 頁面渲染、會話狀態和必要交互 |
| `assets/mock-data.js` | 集中合成資料 |

本輪主要驗看桌面 1440×1000 和 1280×800，不作為完整移動端適配或生產功能驗收。

# 醫療病歷質控產品原型設計

> 2026-10-13 增量：用戶明確要求採用 Ontology-Playground 原生圖譜。下文原有五頁描述仍對應現有靜態原型；新增設計見[知識圖譜工作臺](#knowledge-graph-design)，屬於下一輪開發目標，尚未寫入 04 頁面或完成視覺驗收。

## 目標與依據

依據 [需求索引](../01_normalize-project-requirements/index.md)與 [14 組需求看板](../02_requirement-playground/board-data.json)，提供可與客戶一起操作、討論的產品原型。用戶要求採用 Apple 風格：淺色、剋制的藍色強調、系統字體、清晰層級、輕量玻璃側欄和細膩反饋。

唯一工程為 [04_frontend-prototype](../04_frontend-prototype/README.md)。需求看板繼續保留，原型不覆蓋它。正式前後端和 PRD/Spec 狀態不因本輪原型實現改變。

## 代表性場景

1. 質控人員在工作臺定位“陳** / 28床”的過敏記載衝突，進入證據頁對照入院記錄與出院小結，確認問題並派發；責任醫生填寫整改原文與說明；質控執行再核驗並確認；醫生和質控分別簽字。列表、版本和審計保持一致。
2. 醫生對待處理問題申訴，專家保留意見後要求整改或撤銷問題；撤銷以“問題不成立”結案，不標成已整改。升級爭議保留當前責任狀態。
3. 病例缺少所引用的檢查報告時顯示證據缺口，阻斷確認與簽字；補充已有資料並重新核查後才進入待複核。身份衝突/範圍外不能借由同一按鈕跳過。
4. 從篩選後的第二頁進入病例，再返回保持列表上下文；切換角色時可看到對應動作或清楚的等待責任人，不允許其他角色代簽。
5. 專家在評測批次中分別記錄兩份判斷；分歧進入仲裁，高風險漏報立即使門禁失敗。准入檢查同時說明數據性質、正式規則審核與責任接受條件，不用總體平均值抵消高風險。

## 視覺與交互

- 面向日常桌面工作，目標視口 1440×1000 與 1280×800；本輪不擴展為移動醫療端。小視口作自然收縮，但不承諾完整移動工作流。
- 固定 224px 側欄，64px 頂欄，主內容滾動；工作臺表格可局部滾動並固定表頭。詳情證據與處理面板同屏，長記錄按頁籤分組。
- 字體使用系統字體；正文與常用操作 16px，標題 28–32px，表頭/來源等輔助信息 14px，品牌腳註等次要內容至少 12px。背景 #f5f5f7，正文 #1d1d1f，主操作 #0071e3，風險用紅/橙並輔以文字。
- 14–20px 圓角、細邊界及輕陰影；FF 原始 Logo 放在完整產品名前，應用殼底部保留統一署名。
- 高頻導航、篩選立即響應；按鈕按壓使用輕微縮放，抽屜/反饋控制在 200ms 左右。減少動態效果時禁用位移；對話框支持 Escape、關閉與焦點恢復。
- 主列表以 12 份代表性記錄展示跨頁瀏覽，另有 2 份可接入資料；數量只用於原型體驗。搜索、篩選、排序與分頁基於同一結果集，狀態改變後重新計算統計。

## 實現與邊界

採用多頁 HTML、共享 CSS、原生 JavaScript 和集中 `mock-data.js`，無需 npm 構建或真實 API。會話狀態保存在當前標籤頁 sessionStorage；跨頁共享病例、角色、評測和審計，提供“重置工作區”入口，僅清除本原型狀態。

病歷、檢查結果與語義判斷為合成預置內容；修改、核驗和簽字是前端狀態表達，不改動原始醫療數據、不調用模型或醫院服務。簽字展示當前崗位及操作時間，不冒充生產電子簽名。正式規則審核、指標閾值、專業評測與真實准入尚需實施階段完成。

此次呈現方案用於客戶走查，未取得客戶對界面或交互的驗收。後續反饋在本文件與同一工程中修訂，不創建平行版本。

## 知識圖譜工作臺：整體產品增量設計

### 需求、來源與使用者

依據 PRD U09、REQ-020、AC-027～029、PSC-014，新增 F011。指定參考是 [Ontology-Playground](https://github.com/microsoft/Ontology-Playground)，已核對固定提交源碼；瀏覽器環境啟動失敗，本輪未完成參考站視覺體驗或新頁面驗看。源碼能力及適配邊界見[原生集成決定](../architecture/ontology-playground-integration.md)。

採用本地產品設計 Skill 的“先工作任務和空間、再視覺”的方法。用戶此次明確要求原生完整圖譜，實現深度不能沿舊純 HTML 原型的簡化策略處理。正式工程採用已選 React/TS/Vite，在 `frontend/` 落原生組件；現有 04 原型保留為既有旅程參照，本輪不遷移或另造第二個可點擊原型。

| 角色/情境 | 要解決的問題 | 頁面中的實際結果 |
| --- | --- | --- |
| 質控複核者查看過敏記載衝突 | 不易理解問題來自哪段原文、怎樣關聯規則 | 問題→兩條相反來源斷言→固定段落，並列原文，繼續原複核任務 |
| 責任醫生查看整改要求 | 概念關係、來源陳述與已確認問題容易混淆 | 看清當前對象是術語、原文陳述、候選推斷還是專業意見，可返回整改頁 |
| 專業知識維護者核對術語與約束 | 字段字典難體現語義、適用範圍及版本 | 搜索中文術語，檢查定義/同義詞/方向/約束/來源，創建候選並交既有審核流程 |
| 信息科檢查字段映射 | 上游字段、概念和數據版本不易對齊 | 數據綁定定位到已授權結構/映射，不默認看到患者正文 |

名稱沿用已確認病例、文書、疑似問題、規則和語義定義。概念顯示中文業務名，技術鍵/IRI 放詳情；病例遮罩名稱和業務號遵守當前權限。原生 Healthcare 示例只能作工程對照，不能在醫療工作區顯示為已批准本體或客戶資料。

### 導航與共享對象

保留“質控工作臺、規則與依據、評測與准入、權限與審計”的既有職責，在“規則與依據”後增加一級“知識圖譜”。原病例詳情入口不變。知識圖譜內有“本體與術語 / 病例證據 / 規則影響”三個業務視圖；這是同一工作區的範圍切換，共用原生畫布與詳情結構，不是三個互不相干的圖。

| 從哪裡點擊 | 落點及首屏 | 下一步 | 返回恢復 |
| --- | --- | --- | --- |
| 一級“知識圖譜” | 本體與術語；當前可用語義版本，未選擇患者 | 查定義、路徑、綁定、約束或打開候選設計器 | 保留該用戶合法的視圖/主題偏好 |
| 病例問題“查看證據關係” | 病例證據；固定病例/文書/運行版本並選中該問題，展示相關原文斷言 | 點擊證據節點並列看原文；“返回問題複核”回 F006/F007 原落點 | 原病例頁籤、選中問題、工作臺篩選/頁碼和滾動 |
| 規則詳情“查看規則關聯” | 規則影響；選中該規則版本及其引用的本體基線 | 檢查字段/知識條款、已有問題；有權才進入關聯病例 | 規則搜索、選中規則、版本與抽屜狀態 |
| 節點“查看定義/出處” | 當前檢查器對應分組；原文必要時打開並列證據區 | 固定來源位置，缺口明確 | 關閉證據恢復原選中節點、縮放及焦點 |
| “設計本體” | 具維護權者進入原生全屏 Designer，顯著標識候選與基線 | 保存候選、驗證、預覽或提交內部審核 | 返回原本體視圖；有未保存修改時說明保存/放棄後再離開 |
| “查看歷史版本” | 固定歷史語義/文書/規則組合，頂部寫明歷史 | 對照變更清單/選定對象，舊引用仍回舊原文 | 明確“回到當前版本”，不能靜默替換 |

圖譜讀取現有主責事實源。拖動、縮放、搜索、路徑高亮和切換主題隻影響視圖；不改變問題狀態、專業判斷、整改任務或簽字。候選保存不改變生效版本。F007 狀態更新後，圖上同對象更新責任摘要但不繼承新文書的舊證據；必須先切換到匹配的新版本視圖。

### 頁面空間與操作密度

以 1440×1000、1280×800 桌面視口為交付尺寸。默認保留 224px 全局側欄和 64px 頂欄；進入專注圖譜時側欄可縮為 64px。圖譜模塊使用剩餘可用高度，不在長篇介紹、統計卡片下方放一張小圖。

```text
全局導航 │ 知識圖譜 / 本體與術語   當前語義版本·用途   設計本體
         │ 本體與術語  病例證據  規則影響  │ 搜索 / 版本 / 範圍
         ├────────────┬────────────────────────┬─────────────────┤
         │ 對象/路徑   │ 原生交互畫布             │ 選中對象詳情     │
         │ 搜索結果    │ 類型色、箭頭、原生布局     │ 定義與屬性       │
         │ 篩選與圖例  │ 鄰域聚焦、路徑高亮         │ 關係與約束       │
         │ 當前範圍    │ 平移/縮放/適配/重排/導出   │ 證據與來源       │
         │             │                          │ 版本與狀態       │
         └────────────┴────────────────────────┴─────────────────┘
         │ 已加載範圍 / 部分覆蓋 / 佈局模式 / 選中路徑說明
```

- 1440 寬下左對象欄約 220px、右 Inspector 320px；畫布佔中間剩餘空間。1280 寬時左對象欄默認摺疊為可展開抽屜，右欄約 300px，畫布保持主要工作區；允許專注模式擴大畫布，不能同時擠出四個窄欄。
- 高度有限時工具條固定，對象列表、Inspector 和原文各按實際需要局部滾動；畫布中的滾輪明確用於縮放，不能把整頁滾動鎖住到無法離開。僅出現當前工作需要的滾動區。
- 長原文打開“圖譜 / 原文”並列模式：摺疊左欄與一般 Inspector，保留選中對象簡要信息，畫布和原文約 55:45；讓問題與兩段原文可切換對照。關閉原文後恢復佈局，不把原文塞進 200px tooltip。
- Designer 沿用上游實體/關係編輯＋實時圖/RDF 預覽的分欄，表單與預覽共享草稿；頂部固定“保存候選、驗證、提交審核”，不出現無權的“發佈生效”。原生格式導出收在“導出”菜單，三類產物標籤清楚。
- 圖譜對象列表展示中文名、類型、版本/狀態摘要；規則/病例列表沿用原功能搜索排序。大圖保留上游 100 項可見限制與剩餘數，並可檢索/加載到其餘授權項，不能只給“還有很多”而無到達方式。測試尺寸見技術決定，不把合成數量冒充實際患者規模。

### 詳細信息與視覺編碼

| 對象 | 首要信息 | 可展開核查信息 | 合法動作 |
| --- | --- | --- | --- |
| 概念/術語 | 中文名稱、定義、批准/候選/歷史、類型 | 別名、IRI、外部模塊/許可、父子關係、值集、字段映射、語義版本 | 定位鄰域、選為路徑端點、查看來源；有權才基於它建候選 |
| 關係 | 兩端業務名稱、箭頭、關係名、明確/推導/待核實 | 原始謂詞、已知基數及依據、推導記錄、適用範圍 | 高亮兩端、查看關係依據；未知基數顯示未知 |
| 病例斷言 | 來源文書、主體、否定、時間及當前問題 | 原值/規範值、定位精度、提取版本、缺口、同段和跨段衝突 | 查看固定原文、返回複核；不能直接“確認診斷” |
| 問題/規則 | 風險文字、當前責任狀態、規則版本 | 知識條款、規則理由、模型候選、專業意見各層來源 | 查看證據/規則；正式處理仍進原責任頁面 |
| 約束/映射 | 約束類型、適用範圍、檢查狀態 | 具體形狀/值集/字段、衝突/未覆蓋原因及版本 | 查看報告；報告成功不等於病歷專業合格 |

用顏色區分對象族，用線型和明確標籤區分本體關係、來源引用、推導與候選；紅/橙用於需要注意的業務風險，不能讓漂亮配色掩蓋嚴重度。圖上的近距離沒有醫學含義，線條粗細不能偽裝未經校準的置信度。選中高亮與風險編碼分開，主題切換不丟失二者。

整體延續系統字體、#f5f5f7 背景、#1d1d1f 正文、#0071e3 操作色、細邊框和剋制圓角；正文與常用操作 16px，必要業務標籤 14px，圖譜檢查器正文 16px；選中節點居中放大，節點標籤可讀後在詳情中完整閱讀。Apple 風格用於信息層級和操作反饋，不減少複雜業務所需的信息密度。圖譜默認採用白色畫布與淺色面板，和主體保持一致；保留原生 dark/light/aurora/crimson 手動切換。醫療端用獨立主題偏好，不繼承舊上游緩存的深色默認；用戶此後主動選擇的主題在刷新後保留。

“酷炫”具體落實為原生 fCoSE 排布、帶語義的圖標/顏色、清晰方向箭頭、聚焦鄰域、路徑逐步高亮、流暢縮放和按需佈局過渡。平時不持續抖動、旋轉或播放裝飾動畫；減少動態效果偏好下關閉移動過渡。中文長名截斷時可通過選中檢查器讀取全文，不能只靠鼠標懸停。

### 場景、異常與驗看

1. 質控從第二頁病例列表進入過敏衝突問題→查看證據關係→選中入院記錄斷言與出院小結斷言→並列回查各自原文→返回原問題複核。兩條主張不能在圖中被自動合併為患者已確認結論，返回保持原工作位置。
2. 知識維護者搜索“過敏記載”→核對中文定義、字段綁定與規則關係→在原生 Designer 基於已批准版本建候選→新增屬性並撤銷/重做→查看驗證與 RDF 預覽→保存候選並交內部審核。病例運行仍引用原批准基線。
3. 從規則詳情進入關聯圖→查看規則與約束的有向路徑→選擇歷史版本→圖、詳情和來源一起切換；當前病例不因為查看歷史而回退狀態。局部子圖無路徑僅說明當前範圍內未找到。
4. 信息科可看批准術語/授權字段映射，嘗試鄰居展開、詳情、搜索、PNG/JSON 導出時持續執行對象授權；沒有病歷權不在前端緩存正文或隱藏患者統計。授權失效清空受影響視圖，並保留不洩密的恢復入口。
5. 大圖觸發原生 grid，明確顯示規模策略；搜索到第 100 項之後的對象、打開詳情、定位路徑並返回。加載/渲染失敗可以恢復到對象列表和原文，不能把降級列表當原生圖譜交付完成。

正常加載、空結果、部分覆蓋、無權限、歷史版本不可用和導入損失都給出具體狀態。主操作不依靠圖標猜測；鍵盤可用列表選擇對象、打開 Inspector 和離開畫布，快捷鍵與輸入框互不衝突，關閉後焦點恢復。驗看按 F011 的正式用例和產品 PG-006 執行；當前僅完成設計，未運行這些場景。

### 2026-10-14 可讀性調整

用戶反饋正式應用字體偏小、深色圖譜與白色主體不一致。正式前端按上述字號與淺色默認落地；探索欄和檢查器相應加寬，較窄桌面允許摺疊與滾動。只調整展示，數據與責任流程保持原合同。[本輪驗證](../verification/readability-theme.md)記錄兩個桌面尺寸的實際效果。舊 04 靜態原型不隨本次正式應用樣式修改。

### 2026-10-14 工作區佈局與連續操作優化

用戶反饋正式工作臺內容貼到窗口底部、系統整體操作組織不合理。按本地 build-frontend-prototype 的應用產品設計指引改動正式 React 應用，不另建演示副本。設計依據為現有角色/病例/規則/圖譜合同，桌面基線為 1440×900 和 1280×800，增加 1280×720 短窗口檢查。

| Before | After | Why |
| --- | --- | --- |
| 工作臺整頁隨統計/列表/右側說明增長，底部分頁離開視口 | 應用頂欄常駐，內容區四周 24px；工作臺按剩餘高度排布，病例列表獨立滾動且分頁常駐 | 明確工作邊界，保留底部空間與下一步 |

驗看標準：列表滾到最後仍可看見分頁與至少 24px 窗口底部留白；主文檔無額外縱橫滾動；長管理頁在內部滾到底仍有空間；原生圖譜和 Designer 的底欄/退出可達；搜索、非第一頁進入/返回、原文彈窗和圖譜返回可連續操作。原有淺色/16px 字號與業務權限保留，不縮小字來擠內容。

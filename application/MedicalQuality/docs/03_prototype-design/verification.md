| 路徑 | 操作與觀察到的結果 |
| --- | --- |
| 工作臺定位與返回 | 12 份病例每頁 6 條；搜索無匹配顯示空狀態；按住院號排序後從第 2 頁打開病例，再返回仍顯示第 2 頁和正確範圍 7–12 / 12 |

| 版本與責任 | 醫生在已簽字病例提交新版本後，狀態回到待再次核驗，當前簽字清空；舊簽字仍綁定舊版本，刷新不丟失新版本和操作記錄 |
| 申訴與仲裁 | 醫生提交申訴後專家可以撤銷問題、要求整改或升級爭議；撤銷以“問題不成立”結案；B組病例可由 B組醫生接續，A組醫生不獲同樣權限 |
| 再核驗失敗 | 提交未滿足條件的記錄後再核驗失敗，不提供核驗通過或簽字按鈕；質控可退回責任醫生補充 |
| 缺證據阻斷 | 報告缺失時沒有確認問題或簽字入口；確認關聯報告後重回待複核，原缺口與關聯操作留痕；身份衝突記錄沒有借用補報告按鈕繞過阻斷 |
| 訪問控制表達 | B組醫生不能查看 A組病歷正文；跨科室檢查拒絕訪問；拒絕原因出現在審計中。信息科、管理和支持崗位的病歷正文權限保持獨立 |
| 專家評測 | 建立含 8 類規則的批次；第一/第二複核意見不同進入仲裁，仲裁後原判仍保留、原始一致性不被覆蓋；高風險漏報觸發否決；無法判斷的樣本不能通過高風險門禁 |

| 資料接入與恢復 | 接入 2 份待處理資料後共 14 份病例，再次接入不重複；重置恢復 12 份病例及初始會話狀態 |
| 運行與資源 | 所有實際走查頁面無 JavaScript 錯誤，無域外資源請求；各頁面共用同一會話狀態 |

## 界面與修正

- 在 1440×1000 查看了工作臺、病例詳情、規則、評測與權限頁面；在 1280×800 複查工作臺、病例詳情、規則與權限頁面，無頁面橫向溢出。
- 工作臺以表格支持掃描和定位，病例中原文對照與處理面板同屏；已查看初始工作臺、1280 寬的證據詳情、簽字結果、已撤銷問題與評測門禁截圖。
- 增強了正文及輔助文字的字號和對比度，保留淺色、圓角、剋制藍色強調和系統字體；沒有改變業務內容來適應版式。
- 調整“查看完整文書”為“查看上下文”，與實際展示的相關文書片段一致。
- 修正撤銷問題的階段顯示：只標記複核已完成，其餘未執行階段保持未完成，不將結案畫成已整改、已簽字。已針對該狀態複查。
- 修正“無法判斷”的門禁語義：兩位複核者即便給出相同的無法判斷結果，也不能使高風險門禁通過。以固定瀏覽器樣本狀態驗證了該條件。

變更後僅複查直接受影響的狀態和補充的失敗分支，複用已通過的其他路徑結果。尚未進行客戶驗收；本輪未將移動端或生產全量規則納入驗看。

## 數據與交付邊界

原型覆蓋 14 組需求的主要體驗歸屬，具體對應關係見設計記錄。文書片段和初始狀態為集中維護的合成數據；前端崗位約束、固定核驗條件和簽字記錄只表達原型操作，不是實際身份認證、臨床判斷或生產電子簽名。

沒有讀取、改寫醫療原始數據或調用模型、HIS、遠程服務。正式指南/規則審核、醫學效果、真實專家獨立複核、指標閾值、生產責任接受和上線准入均不由本次驗看證明。

本地預覽服務保留在 5199 端口供用戶繼續操作；原需求看板仍在 5198 端口。臨時瀏覽器、測試腳本、下載結果和截圖僅用於本輪驗看，已完成核對並清理，不進入源碼目錄或 Git。
